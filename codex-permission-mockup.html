3完全访问确认弹窗（当前实现）
当前为一整段警告文字 + 取消/继续，无能力清单分项。
现状：permissions.js 中 confirmPermissionMode：title=完全访问权限，message=完全访问权限会关闭应用层路径限制、危险操作检查和审批，且对所有会话生效，直到你切回“请求批准”。Agent 将以你当前的操作系统用户权限直接执行，并可能读取凭据、修改系统或破坏文件。是否继续？；已改为 openUiModal 统一弹窗
怎么对照看： ① 档位：Codex 下拉 = 图标 + 标题 + 一句大白话 + 禁用原因；MyAgent 当前 = 标题 + 描述，无图标、无下拉标题、无禁用态。改造目标即“只保留审批方式一维、去应用层受限徽章、按 Codex 三句文案重写描述”。
② 审批卡：Codex 选项 = Allow once / Always allow / Allow this conversation / Deny，三种放行粒度对应 本次 / 同类前缀 / 会话；MyAgent 的“始终允许同类操作”等价于 Always allow（规则沉淀），目前没有“本会话允许”这一档。
③ 完全访问：Codex = 三类能力清单（文件 / 终端 / 网络）+ 风险说明 + 确认后常驻警示条；MyAgent = 一段警告文字。可参考 Codex 拆成清单式。
④ 替我审批：Codex 在非沙箱工作区直接置灰该档（Requires default sandboxed permissions…）；MyAgent 目前两档共用应用层边界、无禁用逻辑。
