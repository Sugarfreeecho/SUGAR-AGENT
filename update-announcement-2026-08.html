这一轮新增了什么

核心功能与体验变化

Runtime V2 正式成为默认运行时

新功能性能
会话引擎升级为 Runtime V2：事件日志 + 快照 + 增量投影，刷新、断线、重启后都能从上次状态继续。 新增快照检查点、增量恢复、SHA-256 原子校验、事件版本校验与 V1→V2 批量迁移， 旧会话打开时会自动排队迁移，不需要手动操作。
  • 38 MB 长会话追加写入：6–12.5 ms（实测）
  • 10,000 行 UI 历史批量迁移：约 1.98 s（实测）
  • 旧快照/索引缺失或过期时自动重建一次
RUNTIME_VERSION=2（默认） · V1 仍可回退

持久 Goal：任务不用一直开着页面

新功能
每个会话可设置一个长期目标，服务端会自动续跑，不再依赖浏览器保持打开。 支持暂停 / 恢复 / 追加预算并恢复 / 取消；完成后先由独立的 Judge 裁决，再进入人工结果审核。
  • Token 预算耗尽后必须追加预算才能继续
  • 连续失败 3 次自动暂停，避免无限重试
  • Token 用量、活动时长、续跑次数写入审计事件
GOAL_ENABLED=1（默认开启）· 见下方演示 01

执行仪表盘：看得见每一毫秒

新功能可观测
新增独立执行仪表盘，按阶段展示每次 LLM 请求耗时：发送前准备、API 发送、首 token、 LLM 输出、工具执行、轮内后处理与 Run 收尾；支持累计总值与单请求切换、会话筛选、 Token / 工具 / 网络流量图表，以及 Run 墙钟对账（时间都花在哪）。
  • 心跳、运行状态、文件变更、成本与预算实时合并展示
  • 每 2 秒自动刷新，图表可横向滚动查看历史
  • 主 Agent、子 Agent 与 Agent Team 成员统一观测
入口：主界面 → 执行仪表盘 · 见下方演示 03

模型 Profile：一套配置管到底

新功能配置
模型配置统一收口到 model_profiles.json，首次启动引导创建，支持每会话切换模型、 多模态输入自动探测与回退、能力项编辑（上下文窗口、输出上限、思考模式、reasoning effort 等）， 并新增自适应思考格式，自动适配不同模型厂商的 thinking / reasoning 写法。
  • 旧版 .env 模型配置启动时自动导入一次，不会重复创建
  • 接口拒绝多模态时自动持久化为仅文本模式
  • 子 Agent 默认继承父模型，也可显式指定 Profile
配置入口：设置 → 模型 Profile · 见下方演示 04

安全审批中心：更清晰、更可控

新功能安全
工具审批改为统一中央策略（allow / ask / deny），风险操作折叠成审批卡片， 提供拒绝、允许一次、本任务内、始终允许、以及授权工作区外处理权限等明确选项； 全局权限分为“请求批准 / 替我审批 / 完全访问”三档。
  • 删除默认进回收站（软删除），可恢复
  • 新增可信域名白名单（如华为系站点），其余网络请求仍逐次审批
  • MCP / 插件扩展先经安全门控，MCP 注册需用户确认一次
见下方演示 02（审批卡交互）

会话与消息体验：更稳、更顺手

体验稳定性
Followup 队列改为服务端持久化 + 自动排空；运行中发消息可选择“追加”或“接管”， 断线 / 刷新后队列状态从服务端恢复。SSE 增加重试与自动恢复，实时历史保留 live 输出， 长会话滚动与 Markdown 渲染都有明显改善。
  • Final 结果可一键导出图片（PNG）或 Markdown
  • 新增技能选择器，可一次激活多个 Skill
  • 待处理审批、子 Agent 续接都有顶部横幅提醒
导出入口：消息 → 导出选项

插件与子 Agent：生态更完整

新功能扩展
插件管理页支持从本地目录、压缩包或 Git URL 安装 / 更新插件，自动准备私有依赖并支持热重载。 子 Agent 支持托管 Git worktree 隔离、运行中 steer（追加 / 接管）、 父模型前缀引用（不再深拷贝历史），以及按实际 usage 计算的成本与预算。
  • MCP 工具声明 effect 后可在 worktree 中安全放行
  • 未声明 effect 的 MCP / 插件工具在隔离任务中默认拒绝
  • 插件首次启用或摘要变化后必须人工信任
入口：设置 → 扩展管理

稳定性与平台：不丢会话、不假死

稳定性平台
新增运行心跳看门狗：进程重启后自动把遗留运行标记为孤儿，不再出现“假运行”； 系统睡眠或短暂停顿不会误杀存活任务。托盘启动器失败可自动恢复，Agent 更新器可安全快进更新， 更新冲突时保留现场并把详情写入日志。
  • 模型上下文溢出可自动恢复，截断与压缩语义统一
  • 中断、工具执行、流式重连等热路径全部做有界处理
  • 跨平台 CI 稳定化，Windows 启动依赖自动准备
Windows：RUN.bat / 托盘“更新 Agent”

流式工具调用完整到达后立即执行，不再等整轮结束

⚠ 以下三个功能均为实验阶段，默认关闭。

它们不影响现有会话与子 Agent 行为；关闭时相关 API、工具和网络入口都不会激活。 Agent Team 可在设置中直接开关；飞书机器人与远程控制需要在 app/.env 配置环境变量并重启。 请勿在未理解安全边界的情况下用于生产环境。

多智能体团队（Agent Team）

默认关闭；开启后根 Agent 作为 lead，可创建持久成员、共享任务与邮箱，由调度器按优先级自动派工。
Agent Team（实验功能）— 当前：关闭
未启用：team 工具不可用，现有 subagent 行为不变
还没有共享任务。
启用方式：设置 → Agent Team（实验功能）→ 启用；或写入 AGENT_TEAM_ENABLED=1（即时生效，无需重启）。
成员语义：每个成员对应一个持久子会话，dispatch 唤醒同一会话执行； 成员身份来自会话 metadata，不能通过工具参数冒充。写型工具按团队加锁，降低文件冲突。
调度规则：只给空闲成员认领依赖已完成的 pending 任务，优先级 urgent > high > normal > low；重启后可继续派工。

DEMO 07 · 实验

飞书机器人接入

默认关闭；启用后飞书单聊 / 群聊 @ 机器人即可驱动 MyAgent，支持自动建会话、发送消息、运行中 steer 与审批回复。
/new /session /whoami /stop /approve 123 /reject 123 /help
启用方式：在飞书开放平台创建企业自建应用，然后配置 FEISHU_ENABLED=1、FEISHU_APP_ID、 FEISHU_APP_SECRET，重启后生效。
连接方式：使用官方 SDK 的 WebSocket 长连接，由 SugarAgent 主动发起，不需要公网回调地址。 群聊默认必须 @ 机器人；单聊 / 群聊支持用户与群 allowlist。
能力边界：当前支持文本消息、会话绑定与去重、自动建会话、文字命令批准 / 拒绝审批， 以及最终结果 / 失败 / 中断 / 审批通知回传；暂不支持图片、文件、语音与交互式审批卡片。
