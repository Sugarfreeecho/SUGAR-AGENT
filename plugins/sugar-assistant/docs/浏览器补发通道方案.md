# 浏览器补发通道 · 应用方案

> 目标：把「用本人账号给跨租户联系人发私聊」这件 API 做不到的事，做成插件里一个可控、可关、可审计的兜底通道。

## 1. 问题定性

| 路径 | 结论 |
| --- | --- |
| 官方 `im/v1/messages`（bot / user token） | 跨租户单聊硬拒：230038、230027 |
| 机器人进对方单聊 | 不可能（230002） |
| 桌面客户端 UI 自动化 | 可行但抢焦点、受 DPI 影响，不适合常驻 |
| **浏览器已登录会话 + DOM 操作** | **已实测成功（18:48 送达）**，不抢焦点，复用现有登录态 |

所以新增一条**只负责发送**的浏览器通道，收消息仍走现有 worker。

## 2. 总体结构

```
relay / commands
      │  Delivery
      ▼
FeishuAdapter.send()          ← 现有：lark-cli（官方 API）
      │ 230038 / 230027 且 chat 是 external p2p
      ▼
WebFallbackSender.send_text()  ← 新增：Playwright + 持久化 profile
      │ 成功
      ▼
verify(): lark-cli 只读回查最近消息，确认 message_id 与文本
```

- 收：不变（`feishu_worker` 轮询 / 事件）。
- 发：官方优先，失败且命中白名单错误码才降级。
- 审计：复用 `opstore`，一条 op 记录「通道=web、原因=230038、结果、耗时」。

## 3. 新增文件

| 文件 | 职责 |
| --- | --- |
| `sugar_assistant/web_sender.py` | Playwright 常驻上下文；`open_chat(chat_id|name)`、`send_text()`、`health()` |
| `sugar_assistant/channels/feishu_web.py` | 实现 `ChannelAdapter.send/verify/health`，只做发送 |
| `docs/浏览器补发通道方案.md` | 本文 |

`requirements.txt` 增 `playwright>=1.44`；浏览器用系统 Edge（`channel="msedge"`），不下载 Chromium。

## 4. 关键实现点

### 4.1 登录态
- profile 固定放 `data/browser/feishu-web/`，首次 `headless=False` 扫码，之后可无头。
- 启动自检：打开 `https://<tenant>.feishu.cn/next/messenger/`，URL 落到登录页即判定失效，状态置 `login_required`，不自动重试。

### 4.2 定位会话
- 优先用 `chat_id` 对应的会话直接 URL 打开；拿不到就用搜索框搜联系人名。
- 打开后校验会话头名称与目标 `chat_name` 一致，不一致立即中止（防串台）。

### 4.3 发送
1. 定位输入区（内容可编辑容器），`fill` 文本；
2. 校验输入框内容与待发文本完全相等；
3. 点发送按钮；
4. 等待气泡出现（文本匹配）或超时 8s。

### 4.4 回查（判定成功的唯一标准）
- 调 `lark-cli im +chat-messages-list --as user --chat-id … --page-size 3 --order desc`；
- 命中「发送者=本人 + 文本相等 + 时间≥发送前 30s」才算成功；
- 回查不到 → 标记 `unknown`，不重发（避免重复）。

### 4.5 幂等与限流
- 同一 `(chat_id, 文本 hash)` 60 秒内只发一次；
- 全局串行（一个浏览器上下文），队列深度上限 20；
- 连续失败 3 次 → 通道自动置 `degraded`，控制台告警。

## 5. 配置项（控制台「通道 · 飞书」新增）

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `web_fallback.enabled` | `false` | 总开关 |
| `web_fallback.tenant_host` | 空 | 如 `acneut3zrdux.feishu.cn` |
| `web_fallback.headless` | `true` | 首次登录需 `false` |
| `web_fallback.timeout_ms` | `15000` | 单条超时 |
| `web_fallback.allow_chats` | `[]` | 白名单；空=所有 external p2p |

## 6. 触发条件（严格）

同时满足才降级：
1. `send()` 返回 230038 / 230027；
2. `chats.get` 显示 `external=true` 且 `chat_mode=p2p`；
3. `web_fallback.enabled` 且 chat 在白名单内；
4. 该消息来自用户主动指令或人工回复，不是群聊自动应答。

其余情况一律不降级，避免"静默换通道"。

## 7. 风险与边界

| 风险 | 处置 |
| --- | --- |
| 飞书改版导致选择器失效 | 选择器集中在一个文件；失败即报错，不猜 |
| 非官方用法、条款灰色 | 默认关闭，需用户显式开启并确认 |
| 账号风控 | 串行、限频、只发人工触发消息 |
| 登录过期 | 状态可见，提示重新扫码，不自动重登 |
| 前端状态滞后 | 成功判定只认服务端回查 |

## 8. 落地步骤

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| P0 | `web_sender.py` 原型（复用本机 profile） | 能对王影发一条并回查成功 |
| P1 | 接入 `FeishuAdapter.send` 降级链 + opstore 记录 | 230038 场景自动走 web，其他错误不走 |
| P2 | 控制台配置与健康状态（登录态/最近成功/失败原因） | 配置能存能生效 |
| P3 | 限流、幂等、degraded 告警、日志脱敏 | 连发/失败场景不重复、不雪崩 |

## 9. 明确不做

- 不用浏览器收消息（DOM 轮询不可靠）；
- 不用它替代群聊/机器人对话（CLI 更稳）；
- 不自动重试未知结果；
- 不在未告知的情况下把私聊改发到群里。
