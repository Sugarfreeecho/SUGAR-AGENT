## 1. bot 路径

必须补：
- [ ] 发送图片/文件（`im/v1/images`、`im/v1/files` 上传拿 key，再发 `image`/`file`）
- [ ] 发送表情包（先验证 `msg_type=sticker` 是否受支持，不支持就走图片）
- [ ] 卡片按钮回调的幂等：同一次点击重复投递要去重
- [ ] 外部群/外部用户的可用性边界写进配置校验（现在只在运行时报 230027）

可选提升：
- [ ] 富文本 post 发送
- [ ] 撤回/编辑（`messages patch`）
- [ ] 发送失败分级重试（限频 vs 权限 vs 内容）

## 2. user-cli 路径

必须补：
- [ ] 轮询解析附件：`image`/`file`/`audio`/`media` 下载后落盘交给 agent（现在只取 `text`，附件直接丢）
- [ ] 发送附件（`lark-cli` 支持 `--file/--image`，接进 `send_text` 同级接口）
- [ ] 卡片不再静默降级：要么明确报「user 身份不支持卡片」，要么改成文字并标注
- [ ] 外部单聊失败不再自动退回机器人（现在是静默换通道，违背既定原则）
- [ ] 轮询覆盖率：每轮 2 个会话、60 秒发现一次，需要可配置与可视化（延迟上限写清楚）

可选提升：
- [ ] 表情包发送（若 CLI 支持 `--msg-type sticker`）
- [ ] 已读/未读、撤回
- [ ] 会话发现从关键词探测升级为固定白名单 + 手动添加

## 3. user-web DOM

必须补：
- [ ] 封装成 `web_sender`（打开会话→校验标题→填框→核对→发送→回查）
- [ ] 附件上传（`input[type=file]`，需处理上传进度与超时）
- [ ] 表情包/图片发送（点表情面板，选择器脆弱，需兜底）
- [ ] 失败分类：找不到会话 / 标题不符 / 输入框不可用 / 发送后回查不到
- [ ] 登录态检测与「需重新扫码」状态
- [ ] 幂等：同 `(chat_id, 文本 hash)` 60 秒只发一次
- [ ] 串行队列 + 连续失败 3 次降级告警
- [ ] 明确不承担接收

可选提升：
- [ ] 无头模式（`headless=True`）验证是否可用
- [ ] 多标签隔离，避免和用户手头的标签互相干扰

## 4. user-web API（内部接口）

必须补：
- [ ] 抓包拿到发送请求：路径、方法、必需头（CSRF/设备指纹）、body 结构
- [ ] 在页面上下文用 `fetch` 复现一次发送
- [ ] 建立「接口失败 → 回落 DOM」的双通道
- [ ] 版本探测：接口 404/字段变更时自动标记不可用
- [ ] 合规评估：属非公开接口，需默认关闭并写明风险

当前阻塞：扩展通道不能执行 JS（`execute_javascript` 被拒），必须有一个可控浏览器（独立 profile 扫码，或临时给 Edge 开 `--remote-debugging-port`）才能抓包。

## 5. 跨路径共性缺口

- [ ] 统一「消息内容模型」：文本/图片/文件/表情/卡片统一结构，各通道各自实现渲染
- [ ] 统一发送结果：`sent / unknown / failed(code)`，未知不重试
- [ ] 统一回查：所有通道发送后用只读接口确认，不以 UI 状态为准
- [ ] 控制台展示每条通道的健康度、最近失败原因、登录态
- [ ] 能力矩阵写进配置校验：选中不可用组合时提前报错，而不是运行时报错

## 6. 建议优先级

1. P0：user-cli 附件接收 + 去掉静默换通道
2. P0：web DOM 封装 + 回查 + 幂等（跨租户私聊唯一可用路径）
3. P1：bot 发送附件/表情
4. P1：user-cli 发送附件
5. P2：web API 抓包与双通道
6. P2：统一内容模型与结果模型
