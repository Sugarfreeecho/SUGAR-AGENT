# 插件热重载机制（宿主侧根治）

## 结论

`reload_plugin` 现在能真正重建插件：停旧适配器 → 清模块缓存 → 重新 import → 重挂路由 → 重跑 `start()`。
改插件代码不再需要重启宿主。

## 之前为什么必须重启

1. **启动表按签名去重**
   `start_bundled_host_extensions` 用 `(plugin_id, content_signature)` 判重；只改 Python 文件时签名不变，`start()` 直接被跳过，插件里的 `_reload_plugin_modules()` 也就没机会执行。
2. **路由只追加不替换**
   `app.include_router()` 会叠加路由；最先注册的旧 handler 一直匹配，读的是旧模块的全局变量，表现为“改了没用”。

## 修法

### 宿主 `app/plugins/host.py`

- `forget_bundled_host_extension(plugin_id)`：清 `_MODULES` 与 `sys.modules` 中的对应模块
- `forget_bundled_host_install(plugin_id)`：允许 `install()` 重跑
- `_INSTALLED_ROUTES` + `_drop_installed_routes(app, plugin_id)`：记录每次 install 新增的路由，重装前先摘掉
- `restart_bundled_host_extension(plugin, context, app)`：stop → 清模块 → install → start，完全绕过签名判断

### 宿主 `app/plugin_hot_reload.py`

- 先清插件签名缓存与 `plugin-signatures.json`，避免读到旧签名
- 通用安装后对该插件调用 `restart_bundled_host_extension`

### 插件侧（防御性）

- `install()` 里按 `/api/sugar-assistant` 前缀先清理旧路由，再 `include_router`

## 验证记录（2026-11-19）

| 步骤 | 结果 |
|---|---|
| 不改进文件 reload | uptime 46s → 23s，日志出现新的 `start` |
| 加 `hotreload_probe="probe-1"` 后 reload | `/status` 出现 `probe-1` |
| 删除该字段后 reload | `/status` 中字段消失，uptime 25s |

## 使用约定

- 改插件代码后只需 `reload_plugin`
- 只有改宿主 `app/` 下代码才需要重启
