# 面向用户：设置配置

引导用户打开侧栏“刷B站”控制台或插件详情页，按具体用途配置；不用一次解释所有字段。网页路径 `/plugins/sugar-bili-scroll`。

## 登录和多个账号

在账号区域扫码登录，确认页面的“当前账号UID”是要接收私聊和发布内容的账号。可以保存多个登录态，每次只选择一个运行；切换会先验证登录态。正在值班/回复/切换时需等待空闲。登出会保留已保存账号；删除账号仅移除本地保存的登录态，不能替代在B站撤销设备登录。

任务、白名单、提示词是插件共享配置；切换账号不会复制出一套独立设置。入站队列按接收账号隔离，切换后不会把旧账号的待处理消息发到新账号上。新账号首次监听只建立游标，不补发历史。

## 先配置一个使用场景

### 收私聊并自动回复

1. 开启“入站自动回复”（`inbound_reply`）。
2. “监听哪些渠道”包含`dm`；设定冷却分钟数和每小时上限。
3. 白名单填**发消息人的UID**，一行一个`UID 备注`，例如`25898734 本人`。不填白名单的来信仍可得到普通回复，但不能使用工具。
4. 若允许白名单通过私聊委托发公开评论，开启 `inbound_dm_public_comment`。它不授予对方本机工具权限。
5. 首次建立游标后，从另一账号发送一条新消息测试；先检查当前接收账号，避免扫码登录错号。私聊每条完整回复最多500字，超限本轮不发送，查看入站错误。

### 回复评论和 @

开启入站回复，在渠道中包含`at`或`reply`，并开启独立的 `inbound_public_reply`“回复评论和@”。这个开关覆盖未刷过的视频，不依赖某个值班任务的自动评论。只有能确定视频和评论目标的消息才能回复；缺少目标会跳过并记录原因。同一视频同一楼层复用会话。

### 自动刷视频值班

新建任务并配置关键词、每日额度、谷时窗口、最短间隔、轮次预算和日报级别。每个任务独立计数/会话/日报，所有任务共享全局视频判重。可先在明确授权下手动“跑一轮”验证选片和记账，再启用自动调度。

发送设置：开启自动评论并填写要@的名字、每轮评论额度；私信模式`off/only/both`分别表示不投递私信、仅私信、评论与私信都投递，收件人填UID。评论是否实际发送取决于所选模式和相关开关。不开启发送时仍能分析和生成日报。

值班自动收藏使用全局 `fav_folder_id`，0表示不自动收藏。显式收藏工具未提供fid时也用这个设置；未设置时可以先查询收藏夹并传入fid。收藏夹必须属于当前登录账号。

## 其他配置

- 转写：开启`transcribe`。`asr_engine=host`复用语音输入服务和ffmpeg；`local`使用可选Whisper模型，按机器性能选模型。设置`asr_max_minutes`避免耗时过长；0为不限制。先取字幕，确实需要再转写。
- 图片评论：值班用`image_comment`，入站用`inbound_image_comment`；默认关闭。图片来自本地表情库，每轮最多1张。
- 系统提示词：控制台分别编辑值班、私聊、评论回复的完整系统提示词，保存持久生效，可恢复默认。它替换插件会话的基础提示词；宿主权限校验仍有效。文档中的`bili_*`短名在插件提示词渲染时映射到MCP名称。
- 模型：`duty_model_profile`可填写可用模型档案ID，留空采用会话或全局默认。
- “人设来源目录/workspace”目前没有接入完整提示词生成，不能承诺填一个AGENTS.md目录就生效；应使用三类完整提示词编辑器。

Agent若通过接口修改设置，使用 `PATCH /api/plugins/sugar-bili-scroll/settings`，正文 `{"values":{"字段":值}}`，并携带同源Origin。任务增改接口为 `/api/sugar-bili-scroll/tasks`及其`/{task_id}`，提示词使用`PUT /api/sugar-bili-scroll/system-prompts`。先读取现有值，只更新用户授权的字段，不覆盖其他配置。
