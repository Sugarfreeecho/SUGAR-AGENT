### 原版行为中需要特别区分的地方

1. 原版已经会发私信，但用途是“主动把选片结果投递给配置 UID”，没有持续私聊机器人会话。
2. 原版已经会回复评论，但限于值班过程中处理自己评论下的楼中楼；Sugar 的 @／回复入站队列和独立会话是扩展。
3. 原版的归档、判重、收藏、可编辑章程、失败保底和日志轮转都已有实现，不应列成 Sugar 全新业务。
4. 原版 README 宣称周末全天谷时，但本地 `index.js` 调度实际按 noon／night 时窗扫描，未见独立周末分支。Sugar 当前同样按配置时窗判断，不能据 README 宣称完整继承了节假日／周末日历。
5. 原版 `perDay=0` 说明为不自动刷、仍可手动跑；Sugar 任务额度为 0 会阻止手动和自动运行。这是现有行为差异。

## 三、迁移中的增强，不能简单算作全新业务

| 改造点 | DSH 基线 | Sugar 当前 |
| --- | --- | --- |
| 执行方式 | JS 插件＋Python MCP＋另起 headless DSH | 原生 `trusted_host`，复用宿主会话运行入口 |
| 视频记账 | 模型写报告／判重表，宿主解析 `### BV` 数量 | `bili_record_video` 提交事实，宿主控制额度、判重、日报与归档 |
| ASR | 本地 Whisper | 默认宿主语音输入服务＋ffmpeg；保留本地 Whisper，跨会话串行 |
| 工具权限 | 值班 MCP 名单 | 运行范围＋持久授权＋调用时最新设置校验；撤销白名单／开关后后续调用拒绝 |
| 读取能力 | 值班主要开放搜索、字幕、评论、视频详情 | 另显式开放弹幕和收藏夹读取；底层来源不等于新增整个 B站接口体系 |
| 数据迁移 | 原单任务文件 | 旧单任务事实只迁移给能确认归属的任务，不复制到所有任务 |
| 认证错误 | 本地保存凭证、检查与扫码 | 使用认证账号接口验证，持久化 `-101`，失效时暂停启动模型，新凭证不继承旧失败 |

## 四、不应算作已迁移业务的上游内容

- `vendor/bilibili-mcp` 还带有上传视频、发动态／图文、热榜、用户视频、全站抓取等函数；原项目值班名单并未开放它们。Sugar 没有搬入这整套扩展功能。
- 原版路线图提到的 token／花费记账、停止当前轮、零 Python 重写、封面视频列表，不能只凭路线图文字认定为原版已交付 UC。
- 内置 MCP 有私信／消息读取函数，也不等于原插件已建立持续入站处理、独立记忆和可靠发送队列；对应产品行为由 Sugar 新增。

## 五、验证状态与后续缺口

### 已有证据

- 原有运行日志证明 Sugar 值班链路曾真实调用搜索、字幕、评论和公开评论工具；工具成功不等于评论公开可见。
- 独立完整提示词阶段综合回归 **210 通过、2 项 Windows 符号链接权限跳过**。
- 账号切换阶段相关回归 **104 通过**，并经后端重载验证真实页面显示 UID／切换／退出／取消控件，无 JS 错误。
- 这些是不同阶段、不同范围的测试，不能相加成测试总量，也不能代替真实账号端到端验收。
- 私聊、@、回复评论、表情发送等新 UC 仍需要用正确的收信账号完成真实来信、发送回执与公开可见性验收；目前没有完成这组验收的记录。

### 从迁移对照中识别出的待补齐／待决定项

1. **评论自动复核闭环**：是否恢复原版 90 秒自动复核、手动批量复核和追加日报结果。
2. **人设目录设置**：接通 `AGENTS.md` 读取，或明确废弃该配置并引导使用完整提示词；当前不能让用户以为配置已生效。
3. **旧楼中楼策略**：是否保留近 7 天巡检和独立每轮回复额度，或正式以持续入站替代，并说明首次不补历史。
4. **外围管理入口**：综合自检、打开目录、依赖安装和升级等，哪些由 Sugar 宿主统一承担，哪些还需插件补页。
5. **额度 0 的手动运行语义**：确认保留当前统一禁跑，还是兼容原版“只停止自动刷”。

上述迁移缺口仍为审查记录。其后按用户确认补充 0.4.0 多账号登录态功能，未修改这些缺口的设计、自动回复开关或任务设置。
