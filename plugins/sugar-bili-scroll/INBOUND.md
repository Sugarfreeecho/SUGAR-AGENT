# UC2 · 入站互动（0.4.0）

当前实现入口为 `inbound.py` → `store.py` → `workflow.py` → 宿主会话 / B站传输。旧的自建四工具模型循环及提示词已移除；全部复用宿主会话执行入口。

## 已确认的设计

- 私聊每 UID 一条会话；生成期间的新消息通过 append/steer 插入同一轮。不同 UID 保持独立记忆。
- 评论、@、回复评论按“视频 BV + 根评论 ID”复用回复会话；不复用值班会话。公开回复顺序处理。
- 没刷过的视频也回复，单独由“回复评论和 @”控制，不受值班任务的自动评论设置影响。
- 白名单可使用全部已启用的 B站业务能力，包括转写、表情收藏和评论；始终没有本机命令或文件工具。陌生人没有模型工具。
- 白名单可在私聊里要求在指定视频发布公开评论；普通私聊回复仍由宿主发送，模型没有任意 UID 私信发送工具。
- 普通私聊每条最多 500 字符；任一条超长，整轮私聊不投递、记录失败，不拆分截断。已执行的公开评论保持独立回执。

## 拉取、排队和会话

轮询每 90 秒拉取文本私信、@ 和回复评论；入站调度每秒处理已保存队列，模型运行不会阻塞后续轮询。每渠道首次成功只建游标；某渠道初次报错不会导致恢复后回复旧消息。

游标和新事件一起提交，事件 key 唯一。事件中的 `target` 保存视频和楼层，公开回复始终使用这个目标。无法确定视频或楼层时跳过并记录原因，不回退到任意任务。

入站同时最多四个工作任务，同一 UID 只能一个；公开回复共用一个顺序槽位。同一 UID 连发且当前会话接受插入时，消息作为 steer 附加，实际被模型消费后才归入本轮。未消费的插入会被移除并重新排队。启动每轮前取得宿主会话占用，结束后释放。

工具范围通过执行上下文传递，运行 ID 和权限另存数据库。显式空工具列表表示一个工具都没有，搜索 / 描述 / 调用桥接工具也不能找回被移除的能力。每次 B站工具调用再次核对最新任务、白名单、开关和目标；不同会话及不同运行不会互相覆盖权限。

## 普通回复

只接收完整的 `llm_response` 和 `final`，排除思考、工具结果、流片段以及中断条目。相同最终正文不重复投递。

私聊先缓存整轮，全部长度校验成功后，一次事务保存所有待发送正文，再顺序投递。超过 500 字符直接失败，不自动重新生成。断开或限流后从保存正文继续，不重新问模型。

公开回复：白名单模型使用 `bili_reply`，一次最多一条；普通文字不能作为工具失败后的兜底代发。陌生人模型无工具，由宿主发送不超过 150 字的普通最终正文到原楼层。任何白名单公开回复均不能改去其他视频 / 楼层；私聊指定视频的公开评论使用独立授权。

## 状态和恢复

| 页面状态 | 含义和后续动作 |
| --- | --- |
| 等待处理 `pending` | 待运行、冷却中，或已有正文等待发送 |
| 处理中 `processing` | 已占用并处理，正在运行模型或投递 |
| 已发送 `sent` | 具有成功发送回执，或由用户核对确认 |
| 部分完成 `partial` | 已有成功发送，后续本轮出现错误 |
| 失败 `failed` | 明确失败或到达自动重试上限；可在页面重新处理 |
| 待核对 `unknown` | 发送中连接中断或结果不确定，禁止自动重发 |
| 跳过 `skipped` | 无回复内容、目标缺失等；可重新处理 |
| 随前轮处理 `linked` | 本消息已被当前私聊轮消费，等待该轮投递完成 |

模型等可恢复失败最多自动尝试三次。发送前先落意图，调用网络前改为 `sending`，回执写回后才能称为已发送。启动时将遗留 `sending` 改为 `unknown`；处理中的任务依据发送记录恢复，已发送条目不再投递。

“待核对”需在 B站检查：确认已发送则保留成功事实并继续其余待发送条目；确认未发才重新投递同一正文。核对操作不会自动向 B站查询。接口成功不代表公开可见；`bili_verify_comment` 查不到时，只能说“没查到”。

开关关闭时保留排队正文；白名单私聊发公开评论的授权被撤销后，已排队但未发的公开评论也不能继续发送。

## 配置和运行事实

0.3.1：轮询错误和认证状态一起持久化。B站返回 `-101` 时页面提示重新扫码，暂停启动回复模型；认证错误绑定到对应凭证文件版本。新凭证写入后旧错误不再阻断，扫码成功触发下一次尽快检查。登录校验使用认证账号接口，不用可匿名访问的公开用户资料判断登录。

`inbound_reply` 是总开关；`inbound_channels` 选择渠道；`inbound_public_reply` 控制公开来信；`inbound_dm_public_comment` 允许白名单私聊指示公开评论；`inbound_image_comment` 允许入站带图。

`inbound_whitelist` 每行 `UID 备注`。默认同人冷却 1 分钟、全站每小时 6 条，均可设为 0；对启动模型和实际投递分别记账。重复恢复同一发送不会重复扣发送额度。

`runtime.sqlite3` 保存队列、游标、会话绑定、权限、发送正文及回执。旧 JSON 游标和私聊会话映射只作为迁移来源。页面展示最近 100 条记录，提供失败重试和不确定发送核对。

隔离组合测试覆盖真实轮询事件形状、同秒事件、首轮静默、steer、权限撤销、线程复用、发送中断、重启续发及长度边界。尚未通过真实用户消息验收新版；详见 [实施记录](IMPLEMENTATION.md)。

0.3.2：入站事件和回复会话按登录 UID 隔离。切换到另一账号会停止旧账号排队任务并重新静默初始化各渠道，不补回新账号的历史消息。旧回执保留，手动重试也不能以新账号发送旧账号的回复。退出登录后不再调度回复模型，轮询中的旧请求结果丢弃。

0.4.0：可保存多个账号登录态，每次只启用一个；退出当前账号保留登录态，移除才删除，启用前验证凭证。切换验证期间不启动新的入站工作任务；任务、白名单和提示词沿用当前配置。详见 [多账号说明](MULTI_ACCOUNT.md)。

0.4.1：白名单入站会话可使用 `bili_favorite_add` 收藏视频。收藏夹必须属于当前启用账号；未指定时使用配置值。查询收藏夹后、实际写入前再次验证权限；陌生人及已撤销白名单不能调用。已成功的收藏操作不因普通私信超过 500 字而撤销。
