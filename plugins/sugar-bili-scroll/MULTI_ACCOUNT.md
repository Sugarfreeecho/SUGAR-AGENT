# 保存多个登录态，每次启用一个账号（0.4.0）

用户于 2026-10-24 确认：保存多个账号登录态，每次选择一个账号运行。

## 控制台操作

1. 点“添加账号（扫码）”，用希望保存的 B站账号确认。原账号凭证会先保留到账号列表；扫码完成后启用新账号。添加期间当前账号暂停使用。
2. 重复扫码添加其他账号。再次登录同一个 UID 会更新该账号凭证，不产生重复条目。
3. 在“已保存账号”选择 UID，点“使用所选账号”。后端先验证保存的凭证，成功后启用该账号，无需再次扫码。
4. “退出当前账号”停止使用当前账号，保留它的登录态；以后从列表重新启用。
5. “移除所选账号登录态”删除该账号保存的凭证。移除正在使用的账号也会退出，不自动启用其他账号。
6. 添加账号时可以“取消扫码”。旧账号仍保存在列表里，可以重新启用；取消后的在途扫码结果不能写入凭证。

保存凭证不保证永远有效。验证返回未登录时会提示重新扫码；验证失败不会替换当前账号。网络暂时不可用时保留账号，稍后重试。

状态页显示当前 UID；账号列表区分当前账号、已保存账号和已确认失效的账号，只返回账号元信息。

## 运行规则

- 同一时间只启用一个 B站账号，刷视频、评论、收藏和入站监听都使用它。
- 任务、每日额度、白名单、收藏夹 ID 和完整系统提示词沿用当前配置；切换账号时这些设置保留。
- 切换验证期间暂停启动新的值班、入站和手动运行。已有 B站工作任务未结束时，不允许切换、退出或移除。
- 入站私聊和评论会话按接收账号隔离。切换到另一账号后停止旧账号待处理任务、重新静默初始化游标，不补回该账号的历史消息。
- 退出后不运行入站回复模型。没有自动选择备用账号的机制。
- 停用账号的登录态仍保留，但不同时监听或发送。

## 存储与迁移

- `runtime.sqlite3` 的 `accounts` 表保存各 UID 凭证及更新时间、已知失效状态。
- `bili_credential.json` 仍表示当前启用账号，保持 B站业务层及 ASR 的现有读取方式。
- 原有单账号文件在读取账号列表、退出、保存或切换时自动纳入保存列表，不需要重新扫码导入。
- 新账号覆盖当前文件前，先保存旧账号；退出仅清除当前启用文件。
- 先前版本已被覆盖或清除、且没有保留的登录态无法自动恢复，需要各扫码一次。
- 账号列表接口只返回 UID、是否启用、更新时间和状态，不返回 Cookie 或其他凭证字段。

## 接口

| 接口 | 用途 |
| --- | --- |
| `GET /api/sugar-bili-scroll/accounts` | 已保存账号元信息 |
| `POST /api/sugar-bili-scroll/accounts/{uid}/activate` | 验证并启用保存的账号 |
| `DELETE /api/sugar-bili-scroll/accounts/{uid}` | 移除所选账号登录态 |
| `POST /api/sugar-bili-scroll/logout` | 退出当前账号，保留登录态 |
| `POST /api/sugar-bili-scroll/login/start?force=true` | 添加／重新扫码，保留旧账号 |
| `POST /api/sugar-bili-scroll/login/cancel` | 取消扫码／正在验证的切换操作 |

写操作要求同源 Origin；运行冲突返回 409；账号不存在返回 404；保存凭证失效返回 409；验证网络失败返回 502。失败切换保留原启用账号。

## 验证

新增测试覆盖旧账号导入、保留多个账号、同 UID 更新、免扫码切换、退出保留、显式移除、失效／网络／账号不匹配、同源与运行冲突、在途切换取消和新增扫码取消。浏览器覆盖账号列表、启用、移除、退出后重新启用。

这些回归使用临时凭证、数据和认证接口替身，不向 B站发送真实消息。真实账号仍需用户分别扫码添加。
