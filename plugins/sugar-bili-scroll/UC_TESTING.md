2026-10-23 核对：宿主于 15:23（Asia/Shanghai）启动，晚于后端修改；在线接口有新任务统计和入站处理记录。入站总开关关闭，渠道为 `dm,at`，尚未建立游标。设置页面读取响应的缺陷已修复，刷新页面即可获取新页面代码。

## UC2：两种回复

| 操作 | 通过标准 |
| --- | --- |
| 私聊“记住测试口令：蓝鲸42”，收到回复后再问口令 | 两轮使用同一私聊会话，能接前文，普通回复只到原 UID |
| 白名单私聊“只查询 BV…… 的标题和字幕，不发表评论” | 有对应 B站工具调用，没有本机命令 / 文件工具 |
| 从白名单移出该 UID，再发新查询请求 | 本轮没有模型工具，普通私聊仍能回复；记忆中的旧信息不代表本轮查过 |
| 在同视频同根楼层连续 @ / 回复插件账号 | 顺序处理，使用同一评论会话，并回复各自原目标 |
| 换同视频另一根楼层，再换另一视频 | 各自使用不同回复会话 |
| 在未刷过的视频下 @ | 独立开关开启时仍处理，不受值班自动评论开关影响 |
| 关闭“回复评论和 @”，分别发公开来信和私聊 | 公开来信暂不回复，私聊仍处理；重新开启后队列可能继续处理 |
| 当前私聊生成中发第二条，且前轮结束前被轮询捕获 | 插入当前运行；消费后随该轮完成，未消费的重新排队 |

白名单公开回复用 `bili_reply`，失败不拿普通文字兜底代发。陌生人无模型工具，由宿主发普通最终正文到原楼层。处理记录应有对应会话、运行和结果；“已发送”代表成功回执，公开可见还要在 B站查看或复核。

500 字限制针对 AI 输出。确定性的 500 / 501 字、整轮不发送、限流、断开、重启和并发插入用自动回归验收。给 AI 发 501 字来信，不能证明输出限制生效。

“待核对”先查 B站实际消息，再选“确认已发送”或“确认未发，重新处理”；已有正文会继续投递，不重新生成。

## UC3：多任务

新建测试 A / B，关键词用不同主题，每日额度分别 1 / 2；先关闭自动评论、私信投递、自动收藏，仅测选片与日报。

1. 编辑并保存关键词、额度、窗口、间隔和日报级别，再打开确认保留。
2. 启用 A，点 A 所在行“立即跑”。只应更新 A 的会话、计数及日报，B 不随 A 改变。
3. 运行 B，结果只进 B 日报，A 已记录的视频不再由 B 挑中。
4. 额度用完后不能继续跑；关闭日报仍计额度、保留判重和归档；停用后不能运行。
5. 自动调度另测：启用、额度未满、间隔满足、窗口包含当前时间，等待 60 秒检查。精确测 A / B 顺序时可暂时停用其他任务并记下原状态。任务应依次运行，手动运行通过不能代替自动调度验收。

模型没找到值得的视频时，计数为 0 合法，结合记账、日报和错误判断，不要求每轮凑满额度。测试结束恢复临时配置，删除测试任务即可，其他任务应保持。

## 自动回归

0.4.0 多账号步骤：分别扫码添加两个账号，确认列表均保留；选择其中一个点“使用所选账号”，确认 UID 更新且无需扫码；退出后列表仍在，能再次启用；移除非当前账号不影响当前账号；移除当前账号后保持未登录，不自动切备用账号。执行切换前核对收藏夹 ID 和任务配置，因为它们沿用当前全局设置。更多运行语义见 [多账号说明](MULTI_ACCOUNT.md)。
