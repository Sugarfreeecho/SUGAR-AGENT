# 插件会话独立系统提示词（0.3.0）

按照用户确认，插件会话使用自己的完整系统提示词，替换普通会话的基础提示词。

## 能力归属

宿主此前已有全局提示词模板、会话 `system_context` 的持久化与更新 API，原行为是在普通基础提示词后追加会话内容。

本次在这些机制上增加通用的 `append` / `replace` 会话模式，复用原会话、模型执行、压缩和 token 统计链路。其他插件接入宿主会话 API 时可以显式使用替换模式；普通会话保持原默认行为。

B站插件专属的是三份模板配置、`/api/sugar-bili-scroll/system-prompts` 管理接口和当前编辑页面。此次没有给所有插件自动增加模板编辑页，也没有另建一套模型调用服务。

## 页面操作

打开“刷B站”→“插件会话系统提示词”。分别编辑“值班任务”“私聊回复”“评论和 @ 回复”，点击各自保存按钮。每份最多 240 KiB UTF-8 文本。

三份都是完整模板。保存只更新对应一类，不会覆盖另外两类的未保存编辑。留空或点“恢复默认”采用插件默认模板；值班默认来源仍包括用户自己的 `duty.md`，自定义值班模板优先于它。

| 类型 | 可用占位符 |
| --- | --- |
| 值班 | `{{task_home}}`、`{{seen_file}}`；任务名称、关键词、额度另有任务事实和本轮参数 |
| 私聊 | `{{uid}}` |
| 评论 / @ | `{{bvid}}`、`{{rpid}}`、`{{root}}` |

只替换上述双花括号变量；正文中的普通 JSON / 代码大括号不会被格式化。未知双花括号保持原文。

## 真正替换的内容

普通会话继续使用原来的角色原则、工具策略、技能目录及环境段。插件会话以 `system_context_mode=replace` 保存专属提示词，构造模型请求时不加载普通会话的这三类基础模板。

插件请求保留精简环境事实：月份、操作系统、会话 ID、工作目录，以及实际工具目录由宿主校验的说明。工具 schema、模型可见的聊天历史、压缩摘要和本轮消息仍按宿主会话协议提供。

改变提示词不会授予工具权限。白名单、发送目标、图片与评论额度、私聊 500 字整轮校验等仍由执行代码控制。模板中仍应写清角色、判断标准、语气和如何使用已开放业务工具。

## 持久化和生效时间

配置保存在插件数据目录 `system-prompts.json`，按三类分别存储、原子替换；原章程、任务配置和聊天记录保留。

新会话直接使用替换模式；已有插件会话在下次被使用时，更新同一条会话的完整提示词和替换模式，不创建重复会话。运行中的一轮保留启动时的提示词快照，新配置下一轮生效。

会话元数据保存文本和模式，两者共同参与缓存修订。切换模式或修改文本会绕过旧缓存；token 统计与真实请求使用相同组装逻辑。对话压缩不清除系统提示词，子会话 / fork 继承对应模式。

本次涉及宿主 Python 核心代码，首次部署需要重启 Agent 后端。以后只修改这三份模板，下一轮即生效，无需为每次编辑重启。

## 开发接口

- `GET /api/sugar-bili-scroll/system-prompts`：返回替换模式、三份当前模板及是否自定义。
- `PUT /api/sugar-bili-scroll/system-prompts`：同源写入，正文如 `{"prompts":{"dm":"你是专属助手，正在与 {{uid}} 聊天。"}}`。只更新给出的类型，空字符串恢复默认。
- 会话创建接受 `system_context_mode: "replace"`；更新会话系统上下文也接受该字段。普通会话缺省为 `append`，不受插件配置影响。

宿主完整替换模式要求非空文本；不能因清空提示词悄悄退回普通提示词。插件恢复默认会先解析为非空插件默认文本，再更新会话。
