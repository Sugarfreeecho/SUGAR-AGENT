# Agent Team（agent-team）

可选的多会话协作：一个主会话作为 leader，创建持久子会话作为团队成员，向这些成员派任务，结果回写到各自会话。

- 工具：`team`（创建、派发、领取、更新任务、收发消息、归档等动作都在 `action` 参数里）。
- 路由：由宿主 `app/agent_team/api.py` 提供，插件在 `install()` 里挂上并加插件启用校验。
- 徽标与控制台：保留会话团队徽标，完整团队、成员状态与任务列表进入设置控制台。
- 目录：`host.py`（工具注册、路由挂载、启用开关联动）、`web/`（面板渲染）。

属于 `system` 级插件：设置页不显示，随宿主常开。

## 热重载

- 改本目录里的代码或前端 → 设置页「重新发现 / 热重载」即生效，不必重启：`tool_definitions` 换新模块，`install()` 会先摘掉上一轮注册的同名路由再挂。
- 路由实现位于宿主 `app/agent_team/`，改那边必须重启。
- 判定口径见 [插件热重载](../../docs/plugin_hot_reload.md)。

## 团队控制台

入口为原生「设置 → Agent Team 团队」，也可直接打开 `/settings#plugin:agent-team:main`。从聊天打开设置会绑定当前会话，页内可切换其他会话。原独立地址 `/plugins/agent-team?session=<id>` 保留兼容；详情栏页面和自动生成的团队状态页均已移除。

提供团队创建、真实持久成员创建、模型配置/只读模式、后台派发、成员会话/中断/恢复/移除、任务编辑/依赖/结果/释放/筛选、消息收件箱与已读、手动调度及关停归档。完整关停顺序为“请求关停 → 等待或中断工作成员 → 完成关停 → 归档”。

界面按“任务 / 成员 / 消息 / 运行信息”组织；共享任务以待处理、执行中、已结束分栏，成员使用职责卡片。创建、派发和调度入口始终位于团队概览；自动刷新保留当前页签，新增成员或任务后切换到相应页签。支持宿主深浅色主题和窄屏。

独立页外观沿用「刷B站」的紧凑顶栏、黑色主按钮、灰底卡片、小型指标格、彩色状态胶囊与下划线页签；字体、卡片圆角和表单间距保持一致。

公共资源由 `app/plugin_page_assets.py` 显式注册，插件资源要求缓存重新验证；页面与公共模块的版本参数同时更新。浏览器测试加载实际 ASGI 静态路由，覆盖样式生效、会话绑定、页签键盘切换和创建入口位置。

普通消息写入持久邮箱，不自动唤醒成员；需要执行请使用“派发”。操作超时可能已被后端接受，请先刷新核对。任务编辑会拒绝陈旧状态和依赖环。

团队 API 等宿主改动仍需重启；本次原生设置迁移通过目录热刷新和重载主界面生效。实现与 DSH 对照见 [检查报告](../../docs/goal-agent-team-console-audit-2026-10-27.md)。

## 当前组队边界（2026-10-28 核对）

- 支持一个 Lead 与多个持久成员，成员可指定职责、长期指令、模型配置和只读模式；共享任务支持负责人、优先级、依赖、结果与消息协调。
- 不能把多个已有主会话直接编入同一团队。`spawn_member` 创建 subagent，`dispatch` 通过 subagent resume 执行；宿主会校验目标确实是此 Lead 的子会话。底层 `child_session_id` 字段不等于“已有主会话入队”能力。
- 实际管理权限分为 Lead / 成员。创建、派发、移除、关停等动作仅 Lead 可执行；“开发”“测试”“审查”等 role 是职责指令，不是多级权限或副队长机制。
- 若扩展为已有主会话组队，应新增独立的 Team 成员绑定，保留每个主会话的身份、历史、工作区和 Goal，经 `session_control` 派发，并处理运行占用、结果归属和退出语义；不应把这些主会话改写成子会话。

原生分区由 `web/settings.js` 导出 `mountSettings`，直接渲染在设置文档中，使用设置组件和主题，无插件 iframe。与独立页共用 `web/view.js` / `web/app.js`；每次挂载独立保存团队、任务筛选和弹窗状态，离开分区时取消请求并清理监听。
