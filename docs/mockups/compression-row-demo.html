用户目标：简化压缩期间的日志，并实时显示压缩模型返回的思考。 本轮改动：状态、摘要和思考共用一条“压缩”记录；摘要输出后自动收起思考，仍可手动展开。 后续约束：进度只更新最新状态；保留流式与最终摘要；重试在同一记录内分区。
思考
先整理当前上下文，保留用户目标、已完成的改动和后续约束。 相同的进度提示只保留最新状态，减少等待期间的重复日志。 摘要正文和思考使用各自的容器，放在同一条压缩记录内。 最后生成历史摘要；正文开始后收起思考，内容保留供用户查看。
具体是怎么做的
  1. 复用已有的 context-summary 压缩记录，在其内部加入 <details> 思考区。
  2. 思考增量写入思考区，摘要增量写入正文区。状态更新覆盖原状态，三者分别维护内容。
  3. 首段摘要到达时设置 details.open = false；只自动收起一次，之后可手动展开。
  4. 重试在同一记录内新增思考区；中断只清除活动草稿，保留状态与已结束的思考。
