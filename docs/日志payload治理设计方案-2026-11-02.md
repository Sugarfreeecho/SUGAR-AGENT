# 日志 Payload 治理设计方案（模型生成内容不入日志）

- 日期：2026-11-02
- 状态：已落地（P1–P3 + 文档同步）；实现见 `app/log_safety.py`、`app/agent_harness.py::setup_logging`、`app/agent_local_timing.py`、`scripts/prune_agent_logs.py`。删除历史默认走 `report`，需显式 `LOG_PRUNE_MODE=delete`。
- 范围：`app/agent_harness.py`、`app/agent_loop.py`、`app/agent_mcp.py`、`app/agent_openai.py`、`app/agent_subagent.py`、`app/agent_local_timing.py`、`app/stream_event_bridge.py`、`SPEC.md` §16、设置页环境变量说明
- 结论：把日志从「内容留痕」改为「可定位的索引」，默认不写入模型/用户/工具 payload，只写长度、哈希、结构、状态与耗时；正文一律回到会话存储（`sessions/<id>/events.jsonl`）与 `TempOutput/tool-results/` 查。

---

## 1. 结论摘要（TL;DR）

1. **默认关闭 payload**：新增 `LOG_PAYLOAD_MODE=off|digest|full`，默认 `off`。日志中不再出现模型正文、思考、工具参数值、工具结果、用户输入、系统提示词；`digest` 是可选的折中档（只留首行 ≤80 字符），`full` 才恢复旧行为。
2. **元数据替代正文**：统一用 `len / sha / shape / status / iter / call_id` 描述一次模型输出或工具调用，既能排障也能跨日志比对，不泄露内容。
3. **兜底防线**：`setup_logging` 换用 `PayloadSafeFormatter`，超长行与多行消息在格式化阶段强制摘要，防止新增代码再漏。
4. **顺手治噪声**：单文件 88.8 MiB 中 83.8 MiB 来自 43,370 条 `event_delivery` 计时行；改为按 run 聚合，并给日志加轮转与保留，避免 669 MB / 611 个文件的现状继续膨胀。

预期效果：普通编码会话日志体积下降 90% 以上，`grep -E "LLM Reasoning|LLM Response|工具调用:"` 在新日志中 0 命中，排障仍能凭 `session + run + iter + call_id` 定位到原文。

### 2.3 次生问题

- **无轮转、无保留**：`logs/` 611 个文件 669 MB，最早可追溯到 2026-10-05（约一个月前）且从未清理；`setup_logging` 每次运行新建 `FileHandler`，没有大小上限与淘汰机制。
- **噪声淹没错误**：`@local_operation("event_delivery")`（`app/agent_subagent.py:2120`）对每个子 Agent 事件无条件 `INFO` 一条完整 span JSON；`agent_local_timing.LocalOperationTrace.log()` 对所有 kind 一律 `INFO`。
- **脱敏只覆盖密钥**：`ImagePayloadFilter` + `redact_sensitive_tool_text` 只处理图片 payload 与少量敏感路径，**不处理正文**。

### 2.4 为什么不能靠现有开关

有人会想"把 `LOG_TRUNCATE_KEEP_CHARS` 设小就行"，但现有旋钮有四个漏洞：

1. **有下限**：`max(400, LOG_TRUNCATE_KEEP_CHARS)`、`max(800, …)`（`agent_loop.py:9589/9600/9605/9615`）保证至少保留 400–800 字符，设 0 也关不掉。
2. **覆盖面不全**：`工具调用` 行的参数完全不受该开关约束（`str(tool_args)`，实测 63,213 字符）。
3. **写死上限**：MCP 结果固定 12,000 字符（`agent_mcp.py:605`），与任何日志开关无关。
4. **调试开关旁路**：`LLM_FULL_CALL_TRACE=1` 时消息链不截断（`agent_loop.py:9591-9597`）。

更根本的是：**截断≠不记录**。只要还写入前 N 个字符，隐私与体积问题都只被缓解、没有解决，所以需要"默认不写 + 指纹"的新策略，而不是继续调截断参数。

设计不变量：**一条日志能出现的内容，只能是枚举值、路径、ID、数值、长度、哈希、错误类型**。任何"用户/模型/工具产生的自然语言或代码"都不得作为 `record.msg` 的参数。

## 5. 核心抽象：`app/log_safety.py`

新增一个零依赖模块，供 `agent_harness` / `agent_loop` / `agent_mcp` / `agent_openai` 共用。

```python
"""日志 payload 策略：日志只记录可定位的元数据，不记录正文。"""
from __future__ import annotations

import hashlib
import json
import os
from collections.abc import Mapping, Sequence

MODE = os.getenv("LOG_PAYLOAD_MODE", "off").strip().lower()   # off（默认）| digest（首行摘要）| full（正文）
LINE_MAX = max(400, int(os.getenv("LOG_LINE_MAX_CHARS", "2000") or 2000))
PREVIEW_CHARS = max(0, int(os.getenv("LOG_PAYLOAD_PREVIEW_CHARS", "0") or 0))  # full 模式下才生效
DEFAULT_PREVIEW = max(0, int(os.getenv("LOG_TRUNCATE_KEEP_CHARS", "200") or 200))


def _hash(raw: bytes) -> str:
    return hashlib.blake2b(raw, digest_size=6).hexdigest()


def digest(value) -> str:
    """内容指纹：长度 + 12 位哈希。永远不返回正文。"""
    if value is None:
        return "len=0 sha=-"
    text = value if isinstance(value, str) else json.dumps(value, ensure_ascii=False, default=str, sort_keys=True)
    raw = text.encode("utf-8", "replace")
    return f"len={len(text)} sha={_hash(raw)}"


def shape(value, *, depth: int = 2, max_keys: int = 12) -> str:
    """结构指纹：键名 + 类型 + 长度，不序列化值。"""
    if isinstance(value, Mapping):
        items = list(value.items())[:max_keys]
        inner = ", ".join(f"{k}:{_leaf(v, depth - 1)}" for k, v in items)
        more = f", …+{len(value) - len(items)}" if len(value) > len(items) else ""
        return f"{{{inner}{more}}}"
    if isinstance(value, Sequence) and not isinstance(value, (str, bytes)):
        return f"list({len(value)})"
    return _leaf(value, depth)


def _leaf(value, depth: int) -> str:
    if isinstance(value, str):
        return f"str#{len(value)}"
    if isinstance(value, (int, float, bool)) or value is None:
        return f"{type(value).__name__}={value!r}"[:32]
    if depth <= 0:
        return type(value).__name__
    return shape(value, depth=depth)


def preview(text: str) -> str:
    """digest 只返回首行摘要，full 返回正文；off 返回空串。"""
    if not text or MODE == "off":
        return ""
    if MODE == "digest":
        first = text.strip().splitlines()[0] if text.strip() else ""
        return (first[:80] + "…") if len(first) > 80 else first
    limit = PREVIEW_CHARS or DEFAULT_PREVIEW
    return text if len(text) <= limit else text[:limit] + "…"
```

### 5.2 为什么默认是「指纹」而不是「截断」

- 截断只是把内容变短，200 字符仍足以泄露密钥前缀、用户隐私、模型结论。
- 指纹能回答排障真正关心的问题：**是不是同一段内容、长度对不对、结构变没变**（例如 `contents:str#0` 立刻暴露"模型传了空文件"）。
- 需要还原时，用 `call_id` 去 `sessions/<id>/events.jsonl` 精确取原文，二者天然对齐。
- 确实需要"看一眼开头"时，`LOG_PAYLOAD_MODE=digest` 给出首行 80 字符，仍不落整段内容。

## 7. 兜底防线：`PayloadSafeFormatter`

即使未来新增代码又把正文塞进 `logger.info`，处理器层也不能把它写进文件。

```python
# app/log_safety.py（续）
class PayloadSafeFormatter(logging.Formatter):
    """单行上限 + 多行折叠；异常堆栈保留首尾，避免丢失根因。"""

    def format(self, record: logging.LogRecord) -> str:
        text = super().format(record)
        has_traceback = bool(record.exc_info)
        if len(text) <= LINE_MAX and (has_traceback or "\n" not in text):
            return text
        if has_traceback:
            head, tail = text[: LINE_MAX - 400], text[-360:]
            return f"{head}\n…[log truncated total_chars={len(text)} sha={_hash(text.encode('utf-8'))}]…\n{tail}"
        flat = text.replace("\r", "").replace("\n", "\\n")
        extra = f" lines={text.count(chr(10)) + 1}"
        return flat[:LINE_MAX] + f" …[log truncated total_chars={len(text)} sha={_hash(text.encode('utf-8'))}]{extra}"
```

`setup_logging` 中替换 formatter：

```python
from log_safety import PayloadSafeFormatter
file_handler.setFormatter(PayloadSafeFormatter('%(asctime)s - %(name)s - %(levelname)s - %(message)s'))
```

保留 `ImagePayloadFilter`（两层防线互不替代）。

**成本**：`Formatter.format()` 只调用一次，不会像 Filter 那样重复 `getMessage()`；`replace`/切片对大字符串是 O(n)，只在超限时触发。

## 8. 噪声治理

### 8.1 现状

`LocalOperationTrace.log()`（`app/agent_local_timing.py:72-75`）对所有 kind 无条件 `INFO` 一条完整 JSON。子 Agent 的 `deliver_child_events` 被 `@local_operation("event_delivery")` 装饰（`app/agent_subagent.py:2120`），每个子事件一条。实测单文件 43,370 条、83.8 MiB。

### 8.2 设计

新增 `AGENT_LOG_TIMING=summary|detail|off`（默认 `summary`）：

- `summary`：对逐事件触发的 `event_delivery` 只累计计数与耗时，按 run 收口输出一行；`round_entry`、`model_commit` 等每轮/每次提交一条的 kind 仍保留逐条记录（它们承载 span 顺序，排障价值高）；
  ```
  local_operation_summary kind=event_delivery session=… run=… count=43370 total_ms=182340 p95_ms=9 max_ms=214
  ```
- 慢路径仍单独留痕：`elapsed_ms >= AGENT_LOG_TIMING_SLOW_MS`（默认 500）时照旧输出单条。
- `detail`：维持现状，供性能分析。
- `off`：关闭计时行（错误与生命周期不受影响）。

收口时机：`finish()` 末尾与 `execution_metrics` 的 `timer_flush` 各调用一次 `flush_local_operation_summary()`；另设 1000 条阈值防崩溃丢失。

### 8.3 预期

同一 88.8 MiB 样本，`event_delivery` 从 43,370 行降为 1 行，该文件体积预计降到 3 MiB 量级；配合 §6 的 payload 移除，可到 1 MiB 以下。

## 9. 轮转与保留

| 机制 | 设计 |
|---|---|
| 单文件轮转 | `RotatingFileHandler(maxBytes=LOG_MAX_BYTES, backupCount=LOG_BACKUP_COUNT)`，默认 8 MiB × 2 |
| 目录保留 | 进程启动首次 `setup_logging` 时盘点：`mtime` 超过 `LOG_RETENTION_DAYS`（默认 14）或总量超过 `LOG_TOTAL_MAX_MB`（默认 512）的文件进入候选；`LOG_PRUNE_MODE=report`（默认）只记一行 `log_prune_report`，`delete` 才真正删除 |
| 白名单 | 跳过 `agent_terminal.log`、`agent_update.log`、`launcher_console.log`（由托盘/生命周期写入，不归会话日志管） |
| 现存量 | 提供一次性脚本 `scripts/prune_agent_logs.py --dry-run`，先打印将删除的文件与释放空间，再由用户执行；不在启动时静默删除历史 |

## 12. 验收标准与测试
