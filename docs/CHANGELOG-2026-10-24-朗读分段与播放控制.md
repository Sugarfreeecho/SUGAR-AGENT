**朗读分段与播放控制（2026-10-24）**

上一次只解决了"多快出声"，没解决"听起来像不像话"。这次按块类型重做语音计划，并补上暂停、从头和自动朗读。

**为什么原来读起来乱。** 旧实现把整条回答克隆成纯文本，只在 `tr`、`p`、`li` 末尾补换行，`td`/`th` 之间没有任何分隔。于是表格的每个单元格被拼成一句：`用量窗口 状态 已用 换算金额 重置时间`，再和下一行黏在一起，听的人分不清哪是列名、哪是取值。代码块虽然被剔除，但也只留下一句"这里有一段代码"，没有说清有多少行、什么语言。

**按块类型分段。** `web/shared.js` 新增 `buildSpeechPlan(root)`，把渲染后的回答拆成语音单元，每单元一次请求、一次播放：

| 块类型 | 读法 | 停顿 |
|---|---|---|
| 段落 | 原文 | 0.3 s |
| 标题 | 原文 | 0.4 s |
| 列表项 | 「第 N，」+ 原文 | 0.22 s |
| 引用 | 「引用：」+ 原文 | 0.35 s |
| 表格 | 「下面是一张表格，共 N 行，列有：…」+ 逐行「第 N 行：列名，值；…」 | 0.5 / 0.18 s |
| 代码块 | 「这里有一段 js 代码，共 N 行，就不逐行念了，请查看原文。」 | 0.45 s |
| 图片 | 「此处有一张图片：<alt 或图注>」 | 0.45 s |

超过 8 行的表格只读前 8 行并补一句"其余 N 行请查看原文"；行内代码超过 24 字符读作"一段代码"，URL 读作"链接"；表情符号与零宽字符一律剔除，避免读成杂音或吞掉下一个字。

**播放控制。** 播放中工具栏出现「暂停」与「从头」。暂停挂起 `AudioContext` 时钟，已排期的缓冲停在原位置，继续时接着读，不重排也不重发请求；非流式服务商退回 `Audio` 元素时，暂停作用于元素本身。从头会丢弃当前进度重新开始，命中缓存时几乎立即出声。两个控件随播放挂载，停止时移除。

**自动朗读。** 设置里新增「回答完成后自动朗读」，默认关闭。开启后只在本会话内**观测到流式活动**之后才生效，因此打开旧会话不会自说自话；触发前还要求文本稳定 1.2 秒，避免把还在生成的内容读半截。

**实测。** 真实回答（572 字，含 3 行表格）拆出 11 个单元，空隙序列为 `0.4 / 0.5 / 0.18×3 / 0.4 / 0.22×3 / 0.3`，与设计一致；暂停后 `AudioContext` 为 `suspended` 且按钮变「继续」，继续后恢复 `running`；从头后重新排期 11 个单元。自动朗读开关打开时新回答自动开播、关闭时不播。

**关于缓存。** 已有 PCM 缓存，键为 `sha256(provider, base_url, model, voice, speed, instructions, text)`，落在 `WORK_DIR/.config/speech-input/cache/`，上限 256 MB、按最后播放时间淘汰。因此同一段文字重复朗读不会再次请求 TTS。注意键包含文本本身，本次分段规则改变后旧条目不再命中，会随 LRU 自然淘汰，不需要手工清理。

主要文件：`plugins/voice-input/web/shared.js`（语音计划）、`web/chat.js`（分块播放、控制、自动朗读）、`web/voice.css`、`web/settings.js`、`speech_input/configuration.py`（`tts.autoRead`）。审查清单见 `06-能力扩展加载/09-内置插件-语音输入与朗读方案设计-UseCase清单.md`（v2，新增 UC-321~331、UC-341~348、UC-508）。

设置中心那批改动入库后，此前一直失败的 `tests/js/voice_plugin_browser.cjs` 已能通过（启动聚焦、主题焦点、设置直达、浮窗、草稿冲突、Final 朗读、停止与释放）；`tests/js/speech_input_runtime.cjs` 里对权限处理器的断言同步到更严格的实现（UI 权限也要求来自受信主框架）。

**自动朗读的等待从 1.2 秒降到 150 毫秒。** 原先的 1.2 秒是怕读到半截回答，但最终答案卡是运行提交时**一次性** `renderMarkdown` 生成的（`message-rendering.js:5523`），不会边写边长，这段等待纯属延迟。缩短后发现一个新问题：排队时若页面上还有上一条回答，会抢先把旧消息读出来。改为进入流式状态时先快照已存在的卡片（`preRunWraps`），排队只在新卡片里选；同一卡片重复排队不再重置计时器，避免页面持续变动把启动无限推后。
