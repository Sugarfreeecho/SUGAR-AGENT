# ask_user 图片与扫码登录

`ask_user` 的每个问题支持可选 `images`。图片显示在问题正文下方，支持放大查看；加载失败时可以重试。图片作为现有附件存储的引用持久化，恢复会话后仍可显示。原有纯文本问题及回答格式保持兼容。

本地文件先调用 `read_file`，把返回的 `attachment.attachmentId` 传给 `attachment_id`。如果截图或登录工具直接返回真实 Base64 图片，可以改用 `data_url`。每张图必须提供 `alt`，可用 `caption` 写扫码说明。

```json
{
  "questions": [{
    "header": "扫码登录",
    "question": "请用手机扫描下方二维码，然后选择结果。",
    "images": [{
      "attachment_id": "sha256:<从 read_file 结果复制完整 ID>",
      "alt": "登录二维码",
      "caption": "请在手机上确认登录；如果二维码失效，选择下方对应选项。"
    }],
    "options": [
      {"label": "已扫码", "description": "继续检查实际登录状态。"},
      {"label": "二维码失效", "description": "重新生成二维码。"},
      {"label": "取消登录", "description": "停止本次登录流程。"}
    ]
  }]
}
```

`attachment_id` 和 `data_url` 二选一。`data_url` 仅支持真实 PNG/JPEG/WebP/GIF Base64 图片；不接受文件路径、远程 URL、SVG 或 HTML。远程图片应先通过现有下载/读取工具取得图片附件。限制为每题 4 张、每次调用 8 张，每张原始图片 2 MiB、合计 8 MiB；现有附件存储的字节、像素及配额限制也生效。

后端先验证整批图片，再保存问题；问题记录只保存附件引用。浏览器从绑定到会话、问题及图片序号的接口取图，不直接使用模型传入的地址。接口沿用远程访问认证，并使用 `no-store`。图片引用参与现有导出和垃圾回收扫描。

“已扫码”只是用户反馈。Agent 必须用实际登录工具检查登录状态，不能直接宣布登录成功。二维码失效时，由 Agent 重新取码并创建新问题；本次没有新增登录服务、自动刷新二维码或后台登录轮询。问题正文和选项 `preview` 仍为纯文本，Markdown 图片语法不会出图。

验证覆盖图片持久化和恢复、实际 `read_file` 附件复用、非法来源和大小/数量限制、整批失败不产生待回答卡片、绑定图片读取和访问认证，以及真实浏览器中的加载、放大、失败重试、文本转义和草稿保留。
