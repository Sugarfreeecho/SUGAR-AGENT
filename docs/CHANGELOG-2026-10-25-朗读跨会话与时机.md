**朗读不再随会话切换中断；跨迭代连续读；朗读时机可选（2026-10-25）**

三件相关的事：朗读与会话解耦；带工具的运行不再被读断；以及"什么时候开始读"变成可选。

**切换会话不再打断朗读。** 原来 `myagent:session-change` 直接调用 `stopPlayback()`，听到一半切走就没了。现在会话切换只重置本轮的自动朗读标记与定时器，播放继续。原卡片离开视野后，卡片上的"暂停/从头"按钮也跟着走——所以录音条接管成**播放条**：显示「正在朗读」或「已暂停」，带「暂停 / 继续」和「停止朗读」。卡片回到视野时再把控制权交还，不在两处重复显示。

**带工具的运行照常读，不打断。** 一个带工具的运行里，每轮模型输出各自流式成行。之前的实现只盯住第一行，行结束时收尾，下一轮的文本就丢了。现在 `pumpLive` 发现新的流式行时，在**同一个播放会话里换轨**：重置该行的解析进度（`fed`/`text`），但不重启音频、不重置 `active.next`，所以上一轮还没播完的音频会和下一轮的文字无缝接上。

防止重复读的那道闸也收紧了：`liveSpoke` 只在真正有文本入队后才置位，只有 `liveCovered && liveSpoke` 才跳过最终卡片。这样"最终内容只在 `final` 事件里给出、过程中没有流式文本"的运行，卡片仍然会被朗读，不会被当成"本轮已读过"。

**朗读时机可配。** 新增 `tts.autoReadMode`：

- `progressive`（默认）：边生成边读，跨迭代连续；
- `final`：等 ReAct 循环整体结束，只读最终回答。

手动点「朗读」始终读最终卡片，不受这两个模式影响。

插件版本 1.7.0 → 1.8.0。审查清单见 `06-能力扩展加载/09-内置插件-语音输入与朗读方案设计-UseCase清单.md`（v7，新增 UC-371~378、UC-512，并修正 UC-347/UC-370 与新行为冲突的描述）。

实测：朗读中切会话，AudioContext 保持 `running`、音频块计数不重置；播放条出现并在暂停/继续/停止时分别进入 `suspended`、`running`、隐藏。带工具的运行里，注入 tool-call 后播放不中断，下一轮的流式行会被接续朗读，最终卡片不重复。

主要文件：`plugins/voice-input/web/chat.js`（`updatePlaybackDock`、`togglePause`、`pumpLive` 换轨、会话切换处理）、`web/settings.js`、`speech_input/configuration.py`（`tts.autoReadMode`）。
