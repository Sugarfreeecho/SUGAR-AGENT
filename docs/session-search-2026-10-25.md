# 会话列表搜索与高级全文搜索

侧栏搜索保留原来的本地子串筛选，匹配名称、最近提问及工作目录显示名，沿用当前分组和归档筛选，不请求全文搜索接口。清除或 Esc 清空并收起，输入非空时点击外部保留筛选。

搜索框内的「高级搜索」和视图菜单中的同名入口打开与会话管理相同样式的独立窗口，带入侧栏当前关键词。窗口拥有独立查询、筛选、结果和滚动状态，不替换或清空侧栏列表。

高级搜索默认跨未归档和归档会话，按会话聚合；先返回名称/目录/最近提问，再返回未归档正文，最后返回归档正文。每阶段首次最多 20 个会话，命中明细每页 3 条。归档范围不受普通列表的归档隐藏设置影响。

高级搜索停输 250ms 后请求；中文输入法组词时不请求。Ctrl/Cmd+K 聚焦侧栏搜索（高级窗口打开时聚焦窗口输入框）；窗口内 ↑↓选择、Enter 打开、Esc 关闭，清空按钮只清空高级查询。关闭时取消请求、恢复焦点，并保留侧栏的筛选和滚动位置。打开命中会先关闭窗口，再切换会话并定位正文。

搜索不持久化、不调用模型或外部服务。高级窗口中的工具内容开关默认关闭，推理、系统提示和存储元数据始终排除。

## 接口

`POST /sessions/search` 接收 JSON：

```json
{
  "q": "搜索关键词",
  "scope": "all",
  "phase": "all",
  "include_tools": false,
  "workdir_aliases": {},
  "cursor": null,
  "session_id": null
}
```

- `scope`：`all` / `active` / `archived`。
- `phase`：`all` / `metadata` / `active_content` / `archived_content`。
- `workdir_aliases`：浏览器保存的工作区分组 key 到显示名的映射。
- 阶段续页使用 `phase_done.cursor`；命中续页使用 `upsert.hit_cursor`，同时传入该会话的 `session_id` 和正文阶段。游标绑定查询、范围及会话清单版本，过期返回 409，前端提供重新搜索。

响应为 SSE：`progress`、`upsert`、`phase_done`、`error`、`done`。`upsert` 包含会话摘要、命中来源/片段/Unicode 高亮范围、稳定引用和来源版本。进度中的扫描范围不是命中总数；界面只报告已发现的会话数，并提示续页、失败或尚未完成。

`GET /sessions/{id}/search-hit?ref=…&source_version=…&offset=…` 校验来源版本，返回当前 UI 索引、所属用户轮次或压缩归档原文。`offset` 使用命中的 `match_offset`，超长归档也能展示匹配位置附近的内容。Runtime seq 不作为 UI 索引使用；有效历史变化返回 409，已删除会话返回 404。

## 数据与维护

- 全量会话清单来自 SessionManager，排除隐藏草稿与侧栏以外的子代理会话。
- 可重建缓存位于会话根目录 `.session-search.sqlite3`，使用 SQLite WAL；FTS5 trigram 可用时加速长词，短词/不支持扩展时仍按子串规则搜索。查询仅使用参数化 SQL。
- 正文来自当前有效 UI 投影、可见助手响应/工具执行记录及压缩归档。对话副本去重；明确的改写、删除、截断抑制旧归档副本，快照压缩本身不会抑制仍然有效的归档原文。
- 搜索逐会话检查来源签名；发生变化时重建该会话缓存。冷索引边建立边出结果。单个来源不可读不阻断其他会话，但该阶段报告未完整完成。
- 首次搜索后启用单线程后台维护，复用会话状态/终态通知；每 30 秒核对来源签名，补齐其他入口的历史编辑。原始历史文件保持权威，索引损坏时重新建立。
- 普通列表变化时搜索结果提示重新搜索；删除墓碑即时移除对应结果。请求取消与查询版本共同阻止旧响应更新当前界面。

## 验证

`tests/test_session_search.py` 与 `tests/test_session_search_browser.py` 覆盖阶段顺序、归档、中文短词、多关键词 AND、FTS 回退、工具开关、压缩副本、快照压缩、消息编辑、Unicode/超长原文、分页、游标失效、索引损坏、单来源失败、输入法、取消、高亮、键盘、重试，以及侧栏和高级窗口的状态隔离、两个入口、焦点及滚动恢复。

性能脚本：`python scripts/performance/benchmark_session_search.py`。默认生成隔离的 1,000 个 Runtime V2 会话、10 万条消息，执行 15 次热查询并测量每阶段首批 20 个会话；不访问用户历史。实测结果见 `performance/session-search-2026-10-25.json`。该基准记录服务端检索时间，不包含浏览器防抖、网络与渲染。
