# 浏览器侧栏：主界面 Pending 与流式连续性审查

用户现象：主界面自动发出 Pending 后，侧栏没有响应，部分后续消息和执行过程接不上。

本次审查覆盖生成端、会话事件总线、浏览器宿主 WebSocket、MV3 转发、时间线归属、去重和重连恢复。读取了本地既有事件记录的结构与身份字段，不修改用户会话，也没有重启用户正在运行的后端。具体本次卡住的会话 ID 尚未收到，因此以下是独立复现出的缺陷，不能断言其中某一个就是该次现象的唯一原因。

## 已复现的问题及修复

1. **旧运行的迟到终态关掉新运行。** 时间线对任意 `run_finished/run_failed/run_interrupted` 都直接设置全局 `running=false`。现在只结束它所属的过程，不能关闭另一条已运行的新消息。
2. **缺少用户事实时，下一 Pending 执行组被丢弃。** 原占位分支要求旧条目必须有用户消息；续接或分页只保留了过程时，较新的 `turn:<seq>` 仍落入旧已完成条目，接着被终态保护拒绝。现在新执行组可独立创建占位，收到真实用户事实后原位补齐；仅思考到达时也会进入运行状态。
3. **工具数组下标被当作全局持久身份。** `event.index=0` 会在后续运行再次出现，旧去重键可将新过程误判为重复。持久事实只使用明确的 Runtime/UI 身份；源流序号按运行与流命名，普通数组下标不参与全局去重。
4. **事件总线满队列静默丢弃。** 宿主外层发送队列有满队列恢复逻辑，但内层订阅队列先静默丢消息，外层无法发现。侧栏订阅改为检测溢出并关闭连接，由后台重连后恢复正式历史与执行日志。原单轮消费者的默认契约保持不变，大初始快照也能完整注册。
5. **转发／发送协程退出但连接仍看似正常。** 相关任务异常、意外结束现在关闭传输，避免健康心跳掩盖已停止的消息流。路径等工具值可按文本序列化；发送失败也触发恢复。
6. **恢复仅补工具，未补思考和正文。** 恢复接口和侧栏现在接收尚未提交 UI 的 reasoning/response 记录，恢复中间内容及游标。累计快照替换已有内容，不再次拼接；已包含的旧片段不能重复追加。
7. **迟到快照重新填入已完成回答。** 已有正式终稿时，不恢复它已覆盖的最后一段正文；更早、位于工具之前的过程正文仍按自己的阶段恢复。

## 验证方式

- `browser-extension/tests/stream-continuity.test.mjs`：新增反例先在旧实现失败，再验证运行归属、缺失用户、去重、恢复游标及终稿保护。
- `tests/test_browser_stream_integrity.py`：满队列、重新订阅、大初始快照、转发异常、意外结束及工具结果序列化。
- `browser-extension/tests/stream-continuity-smoke.mjs`：真实生成入口与主界面 Pending 消费器，连续三轮同一运行；思考中重连、转发器故障、正文中重连、下一条主界面消息及历史重载。模型输出为确定性替身，不调用真实模型或执行 shell 命令。
- 保留既有侧栏 Pending、子会话隔离、跨会话失败恢复和核心队列测试。
