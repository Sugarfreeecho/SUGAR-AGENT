# 会话收尾、追问回执与失败状态修复

## 现场证据

会话 `a1d45072-96e6-481f-aa8a-29a30a266ab1`（B站插件工具查询），北京时间 2026-10-27。

- 第一张图最终答案已经显示，但输入框仍为运行中。查接口时服务端 `run_active=false`、`stream_active=false`，没有待恢复或等待人工处理的任务。浏览器控制台实际记录 `ReferenceError: tryMarkSessionUnreadComplete is not defined`，出自 `sendMessage` 收尾。
- “能看到我稍后再看的视频吗？”已经执行，追问条仍在。对应队列操作 `93121bee-f8f3-468b-9c86-dc03972f94af` 已消费；事实日志 `user_turn_committed` 包含这个 `operation_id`，没有旧的 `queued_followup` 标记。新控制服务接管队列后使用普通 user 事件，但投影和前端没有贯通这个回执。
- 最新图不是单纯的显示卡住。run `5fc07f78-2a72-4266-95e9-6875c7a05c98` 在 00:25:33.514 提交 `run_failed`，错误为 `deque mutated during iteration`，没有最终答案。前面的 deferred tool 调用被拦截后已重新发现并成功调用，不能把它当成这一轮最终失败的原因。
- 模型接口后来均正常返回有效配置；短暂的绑定查询失败会把已知选择覆盖成错误文案，且缺少直接恢复入口。

原始失败事实只有错误文本，现存日志没有该异常的堆栈，不能断言当时具体命中哪一处 deque。Token 增量缓存有三处未保护的共享 deque 遍历，新增测试均能在另一个线程写入时稳定复现同样的异常。状态通知队列 `SessionStateSignal` 的读写使用同一把锁，未发现同类无锁遍历。

## 修改

1. 在任何渲染、模型刷新等可选工作前释放本轮拥有的本地 reader；关闭 SSE 后区分本地读取任务与服务端活动 run，保留既有断线恢复机制。删除已不存在的收尾函数调用。清理和旧事件均校验 run 身份，不能清掉或标红更新的 run。
2. 普通 user 回执贯通 `operation_id`：事实、UI 投影、正常 SSE、被乐观消息去重的 `skip_ui` 元数据路径都能按操作 ID 移除队列项。不会按相同文字猜测，也不强制重画乐观用户消息。
3. 失败事件在实时面板和历史投影中显示“执行失败”及原因；实时失败不自动折叠。已有会话变化通知携带最多 1000 字符的失败原因。UI 行投影版本从 2 升为 3，旧派生缓存按现有机制重新生成，不修改原始事实。
4. Token 缓存的哈希前缀、文本前缀、Token 前缀遍历改为短锁内快照；计算、前缀比较和分词仍在锁外。精确缓存和清空操作同样保护。保留所有已有缓存。
5. 模型查询临时失败保留已知绑定，提供重试入口；窗口 focus/online 时只对失败状态重试。强制刷新不会继续继承已失败的共享请求。
6. chat / continuation 外层异常路径记录带 session/run 的完整日志堆栈，方便下次追溯具体出错函数。

没有增加发送前探测、定时检查或轮询频率。投影版本升级可能使旧会话首次读取时重建一次派生缓存。

## 归因审计

不能把这些症状当成同一个问题，也不能据此断言最近所有修改都有效或都造成了退化。

- `tryMarkSessionUnreadComplete` 的定义在 `4083cbc`（2026-09-16）被删除，调用方留下。它早于 10 月 25 日的终态保护修复。
- 无锁 Token 前缀缓存由 `d9bb8b91`（2026-09-20）引入。另一个 reasoning 缓存已采用短锁快照，本次补齐遗漏的三个缓存。
- 队列接管的新路径改变了回执形状，旧前端只识别旧标记，是新旧协议衔接缺陷。
- 10 月 25 日修复的“旧摘要覆盖终态”确实有独立回归测试，但没有覆盖完整页面后台发送的 finally 路径；之前的修复不完整，局部测试不足以保证整条链路。

## 验证

- 完整构建后的页面在隔离的无头 Edge 中运行真实 send、SSE、store、队列与 DOM；只替换 HTTP 数据，不调用模型、不修改真实会话。
- 最初五个浏览器场景使用修改前源码均失败；修改后通过。最终覆盖正常/漏终态的后台发送、两种队列回执、模型恢复、渲染异常、实时失败、历史失败、旧失败不污染新 run，共 9 个场景。
- 三种缓存并发测试用修改前源码全部报 `deque mutated during iteration`；修改后全部通过，并验证前缀比较时其他线程仍可获得写锁。
- 最终合并回归共 218 项全部通过，包含上述 9 个浏览器场景。8 个相关 Node 运行时脚本通过。Vite 生产构建通过。
- 本机 500 条消息的热缓存微基准，7 组各 1000 次取中位数：哈希前缀 56.715→57.618 μs，文本前缀 53.545→47.849 μs，Token 热缓存 53.578→50.202 μs。后两项的差异属于测量噪声，不能声称加速；未发现明显回退。这不是端到端吞吐量承诺。
