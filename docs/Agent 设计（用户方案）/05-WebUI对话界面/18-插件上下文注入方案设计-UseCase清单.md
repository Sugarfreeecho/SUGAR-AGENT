# 插件上下文注入 · 功能方案设计（UseCase 清单）

- 版本：2026-10-23 v2，增加会话固定系统上下文。
- 状态：已接入，验证记录见末节。
- 上级：00《WebUI 对话界面》、06《能力扩展加载》；参考 [DSH 分析](../../plugin-context-injection-and-dsh-analysis-2026-10-22.md)，接口细节见 [Plugin API](../../plugin_api_v1.md)。

## 1. 功能定位

插件可以为模型提供当前业务状态，减少重复查询工具。提供器在服务端运行，与右栏是否打开无关。宿主采集、裁剪并记录实际使用的快照；模型消息和聊天中的注入展示从同一条事实生成。现有 Hook 和插件页面接口继续沿用。

## 2. UseCase

### UC-5C1 注册上下文提供器
- **触发**：原生插件声明 `capabilities.context=true`，Python 使用 `@plugin.context`，Node 使用 `plugin.context(spec, handler)`。
- **预期现象**：已启用、当前签名经授权的插件参与主任务模型步骤准备，提供器收到当前会话身份和本插件的状态。
- **规则与边界**：每插件最多 16 个；本版只支持 `step/snapshot` 文本；提供器不选择模型消息角色，不接收其他会话、其他插件的状态或整个宿主内存。旧 Worker 描述没有 context 字段时按空列表兼容。
- **依据**：`myagent_plugin_sdk.py`、`plugins/{runtime,worker,worker_node}.py/cjs`。

### UC-5C2 按会话采集并在步骤前装配
- **触发**：主任务开始下一个 ReAct 步骤。
- **预期现象**：在输入 token 计算前把当前插件资料加入请求；子代理绑定自己的真实 session_id；网络重试复用步骤已有消息。
- **规则与边界**：提供器不因页面可见而自动唤醒空闲模型；标题、摘要、独立评判等后台请求不主动采集。右栏共享显示 surface 不作为业务身份。
- **依据**：`plugin_context.prepare_for_step`、`agent_loop._inject_plugin_context_step`。

### UC-5C3 去重、失效和压缩后恢复
- **触发**：资料变化、采集失败、禁用、签名变化、撤销授权或压缩上下文。
- **预期现象**：内容不变且快照仍被保留时不重复追加；变化时发送取代旧状态的完整快照；失败时标注沿用的旧资料可能过期；贡献全部移除时追加清除说明；快照被压缩移除后可重新注入。
- **规则与边界**：采样时间与 revision 单独变化不触发重复；空结果表示明确撤销，错误不等于空结果；旧签名资料不转移给新签名；停止后的迟到结果不得进入新运行。
- **依据**：`plugin_context.plan_snapshot`、Worker 超时、既有运行写入围栏。

### UC-5C4 来源展示与可回放记录
- **触发**：快照被持久提交，或者刷新、重启后回放。
- **预期现象**：聊天出现“上下文注入 · 插件 · 条目”折叠行；展开可见实际模型文本，过期、截断、省略状态有说明。
- **规则与边界**：正文与来源标题按纯文本显示；不执行插件 HTML。使用一条带 `metadata.plugin_context` 的 `model_user` 事实，同时供模型历史及 UI 投影消费；实时事件不重复持久化。投影缓存版本更新为 projector 10、UI index 8、UI row 2；原有事实 schema 不变。
- **依据**：Runtime projector / UI projection、`event-dispatch.js`、`message-rendering.js`、`app.css`。

### UC-5C5 配额、超时与用户轮次保护
- **触发**：资料过长、插件阻塞、同一次运行多次刷新快照。
- **预期现象**：按提供器和整体预算裁剪，超时回收所属调用，其他插件仍能参与；注入消息不增加真人用户轮次或产生用户气泡。
- **规则与边界**：每次调度最多 64 个、并发 4 个、8 秒调度预算；整体不超过 4096 个估算 token 和配置上下文窗口的 5%。回收进程、持久提交及文件操作沿用已有机制。压缩统计与主对话派生识别插件元数据，摘要中不把资料标成人类新指令。
- **依据**：`plugin_context.py`、`agent_memory.py`、`agent_harness.py`、`history_context.py`。

## 3. 示例与范围

`examples/plugins/context-provider` 可作为本地插件安装，读取当前工作区的 `AGENT_CONTEXT.md`。创建、编辑或删除该文件后，下一个模型步骤采集变化。文件按文本提供，不直接修改主系统提示。

当前实现面向自动文本快照。插件页面手动附加、浏览器正文提取与多模态上下文需要各自的来源准入接口，不属于本次开放的提供器能力。

### 会话固定章程

固定章程通过 `system_context` 保存在该会话 metadata，由宿主在每次主任务请求时装配为独立系统段。创建接口接受此字段，已有会话可通过独立更新接口替换或清空。未设置时沿用现有行为；内容限 256 KiB UTF-8，不截断指令。动态提供器保持 user 资料角色。

- **UC-5C6 持久章程**：用户或可信宿主插件创建专用会话时提供章程；重启及历史压缩后仍装配，模型历史不追加章程副本。B站值班插件已迁移到该入口，旧值班会话在下一轮自动补入。
- **UC-5C7 更新与隔离**：已有会话更新或清空后，下一轮使用新值；缓存按内容失效。子会话继承创建时快照，之后互不影响；fork 中旧章程被替换而非叠加。HTTP 更新与运行启动串行化，忙碌时返回 409。
- **规则与边界**：章程仍占输入 token；固定前缀可能参与提供方缓存，不保证免计费。B站旧历史保持原样，普通 Worker 不通过动态上下文接口获得写系统指令的权限。参考 `session_system_context.py`、`agent_harness.py`、`agent_loop.py`、`agent_tokenizer.py` 与 Plugin API。

## 4. 验证

测试入口为 `tests/test_plugin_context.py` 与 `tests/test_plugin_context_browser.py`，20 项服务端/真实 Worker/HTTP 请求用例和 2 项真实浏览器用例通过，覆盖声明与授权、超时、变化/清除/失败、预算、持久投影、压缩后恢复、用户轮次、真实步骤链路、迟到写入拒绝，以及折叠行与纯文本显示。HTTP 使用受控响应验证 SDK 与 direct 两条发送路径，正文与持久上下文一致；没有调用外部模型服务。

相关回归分别完成 142 项（ReAct、压缩、后台服务和投影边界）与 121 项（执行生命周期、延迟结果、兼容适配、持久化、压缩元数据和 UI/history 投影）；这些数字按各次命令计数，包含定向用例复用。最终日志与计时调整后的真实步骤链路及授权撤销定向复验 2 项通过。
