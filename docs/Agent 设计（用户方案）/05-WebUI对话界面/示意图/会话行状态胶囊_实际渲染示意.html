运行时约束（plugin-ui-slots.js::normalizeProjectedItem）：label 截断至 64 字、description 200 字；variant ∈ {neutral, info, success, warning, danger}；display ∈ {badge, activity}，activity 不显示胶囊而转为行级活动态；每会话最多 16 枚、每屏最多 200 行参与投影。
同一个 agent-goal 的两枚角标是两件事：Goal = 目标进行中；待审核 = Judge 判定完成、等你审核（review_status=pending）。实机实测（2026-10-11，插件样式表已加载）： Goal 浅色 rgb(79,70,229)（由 app.css 的 --info 浅色修正胜出，插件自述规则特异性更低）／紫黑 rgb(212,184,252)； 待审核 浅色 rgb(36,122,67) + 底 rgba(52,168,83,.12)（插件自己的浅色规则 0,5,0 胜出）／紫黑 rgb(166,227,161)。 另注：插件样式表是按需注入的（挂载该插件渲染器时才挂 <link>），量配色前先确认它已在页面上。
插件还能用自己的样式表按 [data-plugin-id] 覆盖角标配色（plugins/<id>/web/session-panel.css，经 /plugin-assets/<id>/session-panel.css?v=<内容 hash> 注入， 特异性 (0,2,0)~(0,4,0)，会压过 app.css 的 --info 规则）。
⚠ 踩坑：浅色主题只定义了 --accent-rgb / --brand-accent-rgb / --green-accent / --red-accent，没有 --accent-1/2/3（见 ⑤ 规格表）； light 档里写 var(--accent-1) 会回退成紫黑主题的浅薰衣草 #cba6f7。session-todo 的浅色档原本就是 color: var(--accent-1) （特异性 0,4,0 压掉了 app.css 的 10-11 修复），实测 computed rgb(203,166,247)；2026-10-11 已改为 #4f46e5，实测 rgb(79,70,229)。

四处需要留意的代码事实：
① 当前有渲染方的行尾标记只有 待办 / 草稿 / 插件角标 / ?! 待处理徽标（生产者分别在 session-management.js、plugin-ui-slots.js、human-interactions.js）；
② 行内「目标」占位胶囊（.session-goal-badge + 五档 data-goal-status）已于 2026-10-11 删除——它顶替了更早的「修改审查」胶囊，但两者都没有生产者（全仓检索只命中 app.css 与构建产物，buildAndBindSessionRow() 从不插入该节点）；删除后行尾的目标状态由插件角标承载。历史样式与实测见 三种goal对照.html ③ 区；
③ 「待办」胶囊与插件「Plan」角标是两套来源：前者是会话元数据里手动「设为待办」的标记（app/agent_harness.py 的 meta["todo"] → sess.todo，行内位置固定在标题旁、非插件角标），后者来自 session-todo 插件状态 /has_plan，经 session.badge 槽位投影为 .plugin-session-badge（插在相对时间之前）。二者可同时出现在同一行。
④ 两枚 agent-goal 角标别混：插件 Goal（active-goal，目标进行中，variant: info——浅色靛蓝 / 紫黑浅薰衣草）与插件 待审核（review-goal，Judge 判定完成等你审核，variant: success——浅色 #247a43 / 紫黑 #a6e3a1）。两枚文案都是 manifest 字面量、不经词典；「目标」占位胶囊（③ 兄弟）已删除，别再照它接线。
