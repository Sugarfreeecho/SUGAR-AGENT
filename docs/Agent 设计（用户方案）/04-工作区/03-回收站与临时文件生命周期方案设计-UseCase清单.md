## 1. 功能定位

三类"可回收物"的统一管理：软删除文件、临时脚本、回合末清理——全部可追溯、不静默。

## 2. UseCase

### UC-4C1 软删除命名规则
- **触发**：多次删除同名/高频删除。
- **预期现象**：`.trash` 内条目带时间戳前缀（`YYYYMMDD_HHMMSS_mmm_原名`），永不覆盖；回执可复制回收路径。
- **依据**：`delete_file` 命名段。

### UC-4C2 受保护路径矩阵
- **触发**：对 `sessions/`、`skills/`、`.trash/` 及其子路径执行 delete_file。
- **预期现象**：拒绝 + 原因说明；无移动发生。
- **依据**：`_delete_path_prohibited_reason`。

### UC-4C3 临时文件 Turn 末回收
- **触发**：`temporary=true` 写入的中间产物。
- **预期现象**：run 结束（或用户中断收尾）时自动移入 `.trash`，并推送"已清理临时文件 N 个（已移入 .trash）"回执；未声明临时属性的一律不动。
- **依据**：`_cleanup_temporary_write_files`、agent_loop L8566。

### UC-4C4 运行期临时脚本
- **触发**：`run_shell` 物化的长脚本等内部临时物。
- **预期现象**：存放在 `.trash` 命名空间下的 `_RUN_SHELL_TEMP_DIR` 且执行后即时清理；不污染用户目录。
- **依据**：`_RUN_SHELL_TEMP_DIR=".trash"`、`_unlink_run_shell_temp`。

### UC-4C5 插件独立回收区
- **触发**：插件安装/更新失败回滚。
- **预期现象**：使用插件目录下独立 `.myagent-trash`（与工作区回收站分离）；不混入用户 `.trash`。
- **依据**：`plugins/installer.py` L219/307。

## 3. 边界

- `.trash` 的内容本身受"禁删保护"（只能由用户在系统层清空）。
- 工作区回收站与系统回收站无关。
