## 1. 功能定位

授权引擎的"两段式"：先把工具调用翻译成结构化**能力请求**（分类），再综合所有信息给出**决策**（授权）。

## 2. UseCase

### UC-7B1 能力请求分类
- **触发**：任意工具调用进入授权流程。
- **预期现象**：产出结构化 CapabilityRequest：effect（读/写/外网）、声明路径、目标域名、资源标识等；工具本身行为不受分类影响。
- **规则与边界**：分类基于参数与内置策略表（policy.py 801 行）；无法分类 → 保守视为需处理（不默认放行）；run_shell 分类同时基于**生效工作目录**判定 `deletion / destructive / workspace_delete`（见 ../04-工作区/01 UC-4A5）。
- **依据**：`classify_tool`、`_declared_paths / _declared_resource`。

### UC-7B2 综合决策
- **触发**：分类完成后。
- **预期现象**：决策综合：模式预设 + 会话规则 + 授权目录 + 出口约束 + 沙箱状态；输出 SecurityDecision（放行/需审批/拒绝 + 理由）。
- **依据**：`authorize_request / authorize_tool`、`SecurityDecision`。

### UC-7B3 强制审批与"总是询问"
- **触发**：工具/资源命中强制审批清单（如敏感操作）或用户设置了"总是询问"。
- **预期现象**：即使模式较宽松也**仍需人工**；理由对用户可见。典型：非删除类高危命令（`process.destructive`），以及按生效工作目录解析后仍越界的删除 = 红框**单次授权**（完全访问下亦生效，不可被会话规则/复核放行）；工作区内删除为**普通审批**（黄色，可被会话记忆/规则覆盖）。
- **依据**：`forced_approval_for / always_ask_for`。

### UC-7B4 决策审计
- **触发**：每次决策。
- **预期现象**：资源与结论写入审计（可回答"当时为何放行"）；审计不拖慢调用。
- **依据**：`_audit_resource`、（store 审计表）。

## 3. 边界

- 引擎"只给结论"，执行由工具循环完成（配合 ../03-工具系统/02）；
- 钩子的 allow/ask/deny 结论在引擎之前合流（../02-ReAct运行时/06）。
