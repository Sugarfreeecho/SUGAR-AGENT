## 3. 跨功能不变式

1. **不打扰原则**：压缩/观测后台进行；仅用户可感知处（进度、告警）才露头。
2. **诚实原则**：压缩兜底降质、告警未实现项、观测缺失数据——全部如实标注，不伪装。
3. **耐久引用原则**：图片等大载荷保存在内容寻址对象库；消息、事件、队列、日志和独立作业只持有引用或脱敏状态。
4. **结果语义原则**：图片“已接收、已准备、已发送、模型已完成”分开表达；纯文本结果不能冒充模型看过图片。
5. **性能口径原则**：性能结论必须基于逐轮互斥区间；父子诊断段不重复累计，各阶段中位数不直接相加，provider、工具与本地框架分别归因。
6. **优化可追溯原则**：每项已完成性能优化必须同时具有进度记录、所属模块 UC、验收结果和缓存/回退边界。
7. **压缩可追溯原则**：活跃上下文允许有损，但被省略的 reasoning、工具调用与结果必须有稳定归档引用；模型应先用 `history_context` 回溯，不得把摘要当作完整事实源。
8. **异步事实边界原则**：用户轮、助手/工具结果、压缩/摘要、子代理所有权转交仍同步提交；UI 增量入队和派生索引省略维护不能代替耐久事实。异步优化同时验收消费、实际投递排空与终态，不能只把等待移动到收尾。
