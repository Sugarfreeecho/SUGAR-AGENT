## 1. 功能定位

性能优化不是单个“加速开关”，而是贯穿 LLM 连接、ReAct 轮间准备、附件序列化、Runtime V2、扩展刷新和文件工具的系统能力。本篇保证每个历史完成项都能从进度清单追溯到用户方案中的所属用例，并规定优化不能破坏正确性、回退、刷新和持久化边界。

## 2. UseCase

### UC-9E1 首 token 冷热路径治理

- **触发**：服务启动后的首条消息、连接池长时间空闲后的首轮，或连续调用同一模型端点。
- **预期现象**：提示构建、tokenizer 和模型连接在后台预热；流响应排空到 EOF 以复用连接；首选候选走低开销直连适配器。
- **规则与边界**：预热失败不阻断真实请求；直连不得绕过候选链、预算、熔断、取消和回退；keepalive 到期后允许正常重建连接。
- **依据**：01/07 UC-1G3~1G5，02/02 UC-2B5。

### UC-9E2 长历史本地热路径保持增量

- **触发**：历史随 ReAct 轮次追加，系统重复执行附件耐久化、思考剥离、消息哈希、文本扁平化和 token 估算。
- **预期现象**：稳定前缀复用已有结果，只处理新增尾部；附件存储配置和路径解析不按消息重复计算。
- **规则与边界**：对象身份缓存必须保存对象引用并用 `is` 比较，不能只缓存裸 `id()`；token 估算保持压缩 gate 所需精度；配置变化有显式失效入口。
- **依据**：09/02 UC-9B26，02/02 UC-2B3。

### UC-9E3 轮间状态读取与回调调度去重

- **触发**：每轮 `before_round`、工作流回调查询和 context summary 持久化。
- **预期现象**：回调注册表短时复用，Todo 活跃状态走同步过的内存态，未变化摘要跳过重复磁盘快照读取。
- **规则与边界**：run 初始化、工具/UI 更新、压缩和缓存未命中仍回到权威状态；优化不得掩盖其他写者或扩展热更新。
- **依据**：02/06 UC-2F5~2F6，08/03 UC-8C5。

### UC-9E4 工具发现与路径导航

- **触发**：搜索大目录、列出多文件目录、工具连续使用路径。
- **预期现象**：grep 达到结果上限即停止，ls 默认不逐文件计数，路径错误给出候选。
- **规则与边界**：隐藏/ignored 文件和行数统计仍可显式开启；路径候选不自动替用户改写。
- **依据**：03/04 UC-3D5~3D7。

### UC-9E5 可归因、可回归、可失效

- **触发**：评估性能改动、修改 SKILL.md，或使用诊断旁路定位 token 分词成本。
- **预期现象**：阶段计时能区分 provider、工具与本地框架；Skills 树变化推进 catalog generation；诊断开关可隔离本地 token 估算。
- **规则与边界**：父子计时不得重复累计，各阶段中位数不得直接相加；诊断旁路只用于测量；任何缓存必须有签名、TTL、版本或显式失效边界。
- **依据**：09/04 UC-9D3/UC-9D7，06/05 UC-6E4，02/02 UC-2B6。

### UC-9E6 辅助工作减量与异步交付

- **触发**：Agent 在工具后、下一轮准备、流式消费或后台 Goal 扫描中重复执行派生维护和无关读取。
- **预期现象**：指标 JSON 写盘移出全局锁；精确 run 子代理通知跳过完整 UI 投影，空 pending 不读 metadata；Steer 空队列缓存和文件轮询节流；seq 索引无新增锚点不维护；三个模型临时增量有序异步交付；Goal 只复制目标子状态。
- **规则与边界**：用户轮、助手/工具结果、压缩/摘要、子代理所有权转交四类事实边界仍同步完成。事实耐久性、跨进程消息/锁、通知 claim 协议、UI 顺序/清理和 Goal 返回值隔离各有独立验收；不能用缓存或异步入队掩盖失败。
- **依据**：下方 §3.1 完整落点；[02/05 · UC-2E5](../02-ReAct运行时/05-写栅栏与RuntimeV2提交方案设计-UseCase清单.md)。

### UC-9E7 性能效果按真实边界验收

- **触发**：重启后复跑任务或判断是否已达到运行速度目标。
- **预期现象**：确认新代码已加载，再比较工具结果→下一请求、worker→消费完成、实际投递/排空、启动和最终完成；保留样本量、中位、P90、最大值、版本与并发条件。
- **规则与边界**：本地空档不归因于上下文长度或服务器响应。专项测试证明正确性，复制步骤微基准证明该局部步骤成本变化；两者都不替代整条 Agent 的实测。提前消费不能仅把等待挪到 flush/收尾；累积阶段与早启动工具可能重叠，不能直接相加。
- **依据**：[04 · UC-9D7、UC-9D9~9D11](04-观测与运行看板方案设计-UseCase清单.md)，下方 §4.2–4.5。

### UC-9E8 文件审查减量但保留完整签名

- **触发**：一个 ReAct 批次连续写入多个文件。
- **预期现象**：声明路径每次立即耐久记录，Git workspace sweep 合并为批次末尾一次；shell/MCP/插件仍逐次检查。异常、重试和重启保留补扫义务与 UI 交付，避免用丢失审查换速度。
- **规则与边界**：继续全清单枚举和 NTFS ChangeTime 检查；签名并行是可选配置，当前实测更慢，默认串行。文件上限默认为 0，不默认收缩审查范围；mtime 快筛、简单目录 mtime inventory 缓存和 watcher 未实施。收益按总 capture + flush 比较，并与生产轮间目标区分。
- **依据**：[06/08 UC-116~119、506、610](../06-能力扩展加载/08-内置插件-改动审查方案设计-UseCase清单.md)、[02/01 UC-2A9](../02-ReAct运行时/01-主循环与轮次结构方案设计-UseCase清单.md)、[04 UC-9D12](04-观测与运行看板方案设计-UseCase清单.md)；下方 §4.6。
