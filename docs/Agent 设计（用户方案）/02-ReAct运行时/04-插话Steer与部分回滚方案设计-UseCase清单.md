## 1. 功能定位

任务运行中用户的"插话"如何被安全吸收，以及吸收点不巧时如何**干净回滚**。

## 2. UseCase

### UC-2D1 插话入队（受理）
- **触发**：运行中用户发送追加指令。
- **预期现象**：指令立即入队（界面给出受理反馈）；在**安全点**被吸收（下一轮开始前 / 等待点）；模型按新指令调整。
- **规则与边界**：插话不打断正在输出的答复本身（除非含停止语义）；队列有序（先到先入）；可撤销（移除未消费的插话）。
- **依据**：`enqueue_session_steer / _pop_session_steers / _consume_steer_messages`。

### UC-2D2 中断与部分回滚
- **触发**：插话要求停止/转向，且此刻正处于工具执行中途。
- **预期现象**：未完成的当前轮被安全收尾或整体回滚；**半截工具调用不残留**（不会出现"工具在跑但结果没回"的脏历史）；随后按新指令重跑。
- **规则与边界**：已提交的完成轮不回滚；回滚范围 = 未闭合工具调用之后的全部。
- **依据**：`_rollback_steer_partial_turn`、`_runtime_v2_delete_unfinished_tool_events_after_marker`、`_SteerRestartRequested`。

### UC-2D3 失败可恢复
- **触发**：插话流程异常（如进程重启）。
- **预期现象**：未处理的插话不丢失（可查询/恢复）；界面上有"插话状态"查询入口。
- **依据**：`get_session_steer / list_session_steers / transition_session_steer`。

### UC-2D4 停止（非插话）
- **触发**：用户按"停止"。
- **预期现象**：当前 run 在安全点终止（工具被收尾、上下文保留）；会话可继续发新消息。
- **依据**：中断链路（`interrupt_session`、abort 语义）。

## 3. 边界

- 插话与"模型主动 ask_user"是两种通道：问答见 ../07-权限审批/08；两者可同时在等待（不同卡片）。
- 多会话各自独立插话队列（互不串扰）。
