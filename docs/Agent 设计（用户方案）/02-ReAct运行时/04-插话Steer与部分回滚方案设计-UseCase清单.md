## 1. 功能定位

任务运行中用户的"插话"如何被安全吸收，以及吸收点不巧时如何**干净回滚**。

## 2. UseCase

### UC-2D1 插话入队（受理）
- **触发**：运行中用户发送追加指令。
- **预期现象**：指令立即入队（界面给出受理反馈）；在**安全点**被吸收（下一轮开始前 / 等待点）；模型按新指令调整。
- **规则与边界**：插话不打断正在输出的答复本身（除非含停止语义）；队列有序（先到先入）；可撤销（移除未消费的插话）。
- **依据**：`enqueue_session_steer / _pop_session_steers / _consume_steer_messages`。

### UC-2D2 中断与部分回滚
- **触发**：插话要求停止/转向，且此刻正处于工具执行中途。
- **预期现象**：未完成的当前轮被安全收尾或整体回滚；**半截工具调用不残留**（不会出现"工具在跑但结果没回"的脏历史）；随后按新指令重跑。
- **规则与边界**：已提交的完成轮不回滚；回滚范围 = 未闭合工具调用之后的全部。
- **依据**：`_rollback_steer_partial_turn`、`_runtime_v2_delete_unfinished_tool_events_after_marker`、`_SteerRestartRequested`。

### UC-2D3 失败可恢复
- **触发**：插话流程异常（如进程重启）。
- **预期现象**：未处理的插话不丢失（可查询/恢复）；界面上有"插话状态"查询入口。
- **依据**：`get_session_steer / list_session_steers / transition_session_steer`。

### UC-2D4 停止（非插话）
- **触发**：用户按"停止"。
- **预期现象**：当前 run 在安全点终止（工具被收尾、上下文保留）；会话可继续发新消息。
- **依据**：中断链路（`interrupt_session`、abort 语义）。

### UC-2D5 空队列缓存与跨进程失效

- **触发**：运行持续查询 Steer 队列，但尚无插话。
- **预期现象**：空列表也作为有效缓存结果保存在 `_STEER_QUEUES` 中，避免把“没有插话”当缓存未命中重复加载；文件 stat 签名变化后重新读取，另一进程写入仍可被发现。
- **规则与边界**：该优化未替换耐久 inbox 的入队、消费和锁事务；进程内缓存不能吞掉跨进程消息。
- **依据**：`agent_loop.py` 的 Steer 队列加载与签名检查；`tests/test_stream_resilience.py`。

### UC-2D6 流式探测节流与立即中断

- **触发**：消费高频模型事件，或模型暂时没有新输出。
- **预期现象**：每次探测优先检查进程内 `_SteerRunControl.is_aborted`；文件检查按 250 ms 节奏执行。原有 250 ms 空闲唤醒使用 `force_probe=True`，没有输出也可发现其他进程写入的消息。
- **规则与边界**：本进程 abort 不受节流间隔限制；跨进程可见性仍取决于轮询及实际调度，不承诺硬实时上限。append 插话仍在完整 ReAct 边界吸收；中断回滚前先排空流式桥接，参见 [02/01 · UC-2A7](01-主循环与轮次结构方案设计-UseCase清单.md)。
- **依据**：`_StreamSteerPoller`；回归覆盖 500 条连续事件仅 1 次磁盘探测、外部文件更新、空闲强制探测与本地立即 abort。探测次数/累计/最大耗时进入 `llm_local_consumer`。
