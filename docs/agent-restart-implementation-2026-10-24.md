# Agent 主动重启：实现与验收记录

日期：2026-10-24。实现范围为 Agent 申请重启、人工确认、监督器有序交接，以及前端状态/断连恢复。保留工作区原有改动；没有重启正在运行的用户实例，没有构建或安装新的 Electron 安装包。

## 使用流程

1. Agent 单独调用 `request_restart`，填写原因、改动/验证摘要，以及重启后要继续的工作。
2. 全局确认卡显示实际运行任务、后台命令和终端数量；来源会话的工具行也显示同一张卡。
3. 用户选择“暂不重启”或“确认重启”，并可取消“重启后继续本次任务”。未回应就一直待确认；完全访问和自动审批不替代人工确认。
4. 确认后，先保存申请工具结果、模型检查点和运行中断终态。外部监督器才能领取该操作。
5. 监督器先登记预期退出，再要求旧后端冻结新执行、取消/协调任务、关闭资源并显式落盘。旧后端在 HTTP ACK 发完后主动通知 uvicorn 退出。
6. 监督器等待旧进程退出；超过退出预算才记录强制停止并对所持有的进程升级处理。随后启动指定的新实例。
7. 前端核对新实例身份，恢复观察流和会话状态；请求者收到持久重启回执，再按用户选择继续。服务就绪与任务最终完成分别表示。

工具示例：

```json
{
  "reason": "后端代码已修改，需要重启才能生效",
  "change_summary": "完成恢复条件调整和相关回归",
  "resume_hint": "检查新行为生效，再继续当前任务"
}
```

后台子代理执行应由主 Agent 申请重启。没有外部监督器的直接 `python app/main.py` 启动会返回 `restart_unavailable`。

## 核心实现

| 文件 | 职责 |
|---|---|
| `app/runtime_lifecycle.py` | SQLite 持久请求、人工决策、实例身份、检查点、准备停机与 HTTP 契约 |
| `app/lifecycle_supervisor.py` | 托盘共享 mailbox、Electron 监督器桥接进程、Unix 服务包装器与严格就绪检查 |
| `app/builtin_host_tools.py` / `app/agent_tools.py` | 注册 `request_restart`；单工具调用与权限边界 |
| `app/agent_loop.py` | 工具结果和终态提交后释放交接；重启中断保留未回答用户轮次 |
| `app/main.py` / `app/webui.py` | 主动 ASGI 退出、启动恢复、冻结写操作、清理资源和生命周期路由 |
| `app/tray_launcher.py` | Windows mailbox、确认入口、严格实例就绪、受控停止和自动重试 |
| `packaging/electron/lifecycle-bridge.js` / `main.js` / `preload.js` | 停机前 ACK、预期退出登记、独立进度与可信页面 IPC |
| `frontend/src/app/modules/runtime-lifecycle.js` | 全局/会话确认卡、草稿保护、等待重连、实例核对及失败后重新申请 |
| `app/platform_install.py` | 新生成的 systemd/launchd 配置使用外部包装器，后端替换时监督器保持存活 |

状态路径：

```text
awaiting_confirmation → authorized → checkpointed → draining → stopping → starting → completed
                       ↘ denied / cancelled / failed
```

手动菜单请求没有模型工具检查点，因此确认后直接进入 `checkpointed`。Agent 请求必须等工具/运行事实都保存；旧进程里的 Future 不承担跨进程交接职责。

操作和实例存于受保护的 `runtime-lifecycle.sqlite3`。监督器通过随机启动凭据和心跳领取操作，模型不提供命令、PID 或可执行文件。状态文件位置和实例身份由监督器传给后端，不受 `.env` 覆盖。Shell、PTY、Hook、Plugin 和 MCP 子进程不继承生命周期凭据。

## HTTP / 桌面契约

| 接口 | 用途 |
|---|---|
| `GET /api/lifecycle/status` | 当前实例、可用能力、近期操作与 UI 决策令牌；不缓存 |
| `GET /api/lifecycle/status?restart_id=...` | 断连后查询同一操作，不能隐式执行重启 |
| `POST /api/lifecycle/restarts` | 用户菜单创建待确认请求；失败后的重新申请仍需新确认 |
| `POST /api/lifecycle/restarts/{id}/decision` | 仅本次允许/拒绝，验证目标实例、请求摘要和同源 UI 令牌 |
| `POST /api/lifecycle/prepare` | 仅外部监督器可调用，保存状态后 ACK，再请求 ASGI 退出 |
| `GET /api/ready` | 必须返回明确协议、`ok=true` 和预期实例 ID；302/401/404 均不算就绪 |

Electron 的 helper 必须先收到主进程 `ack_prepare`，才能请求后端退出。这保证主进程先登记预期退出，避免跨进程消息和 child exit 的先后顺序造成误报。桌面 bridge 对同一 `restart_id` 只派发一次；旧状态不能覆盖前端较新 revision。

## 前端行为

- 待确认：全局卡和来源工具行显示原因、改动、影响与继续选项；拒绝后不会自动重试同一 run 的申请。
- 保存/交接：保留输入草稿，冻结发送与自动续发，历史仍可阅读。
- 断连：保留当前页面，显示“正在等待服务重新连接”和已等待时长，不展示虚构百分比，不立刻刷新成浏览器错误页。
- 新实例：严格核验实例后同步当前会话，恢复正常观察和执行。
- 失败：显示错误阶段，可重试连接、查看桌面日志或重新申请；部分清理后的旧实例保持冻结，新申请仍需人工确认。

Electron 在 Python 不在线时仍能从主进程获得状态。普通浏览器在断连期间只能确认“正在等连接”；停机时强制刷新或新开页面的离线壳不在本轮实现范围内。

## 同时修正的问题

- 不再按未知监听端口强杀进程；旧服务停止未确认时不启动替代进程。
- 托盘自动创建进程失败后仍按有界重试处理；不会因 `proc=None` 丢失恢复目标。
- 主动重启中断不生成普通终稿，避免把未完成任务误判为已回答。
- 子代理遗留协调先检查跨进程 owner，活跃或无法确认的 owner 不直接标孤儿。
- 清理逐项隔离错误，补齐预热、人工恢复 worker 和 MCP 资源；保存失败不触发正常交接。
- 请求被消费后写入一次性模型回执，防恢复后重复申请同一重启。

## 生效与边界

- Windows 源码版首次需要**退出旧托盘，再运行 `RUN.bat`**；只重启旧托盘托管的 Python 不能更新监督器代码。
- Electron 需要重新构建发行包并重新启动完整应用，不能仅重启内置 Python。本轮只更新源码及 Web 前端构建。
- Linux/macOS 需要重新生成服务配置以使用 `lifecycle_supervisor.py serve`。本轮验证配置生成和通用进程包装器，没有在真实 systemd/launchd 上执行安装或重启。
- 后台命令和终端不自动重放；子代理不透明恢复旧 Python 调用栈；未知外部副作用继续遵循执行日志核实规则。
- 版本/依赖事务回滚、全局恢复队列的资源预算属于原审查后续阶段，本轮没有宣称完成。

## 验证

新增测试覆盖持久化、并发确认、确认摘要变化、拒绝、监督器身份、工具/终态检查点、失败后重新确认、启动凭据隔离、主动退出顺序、重启回执与真实浏览器 DOM。

真实进程验收使用独立临时目录、随机端口和临时 FastAPI 后端：用户确认前不替换进程，确认后仍等待工具检查点；收到保存 ACK 后自然退出，启动指定新实例，且不会重复重启。未对用户正在运行的后端做该实验。

- Node 桌面桥接、重启与恢复检查：54 项通过。
- Web 前端生产构建通过，`scripts/check_frontend_dist_sync.py` 确认产物与源码一致；现有大包体积提示仍存在。
- 修改文件的差异空白检查通过；确认卡与断连状态已用真实浏览器截图检查。截图位于 `.analysis/runtime-lifecycle/`，仅用于布局检查。
