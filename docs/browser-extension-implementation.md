## 实现

### 0.6.37：配对浏览器纳入可信定时任务路径（仅后端，扩展包不变）

- 背景：侧栏会话由浏览器配对身份投递，能力清单缺少 `automation.*`，模型调用 `manage_scheduled_task` 一律返回 `Capability is not granted: automation.create`；桌面主界面是直连运行、无受限父身份，因此不受影响。
- `plugins/browser-use/host.py` 的配对能力清单补齐 `read` 与 `automation.list/get/history/create/update/pause/resume/run/delete`，与主界面聊天对齐；`device.revoke`、Webhook 来源、本机设置适配器仍不对配对开放。
- `restore_pairing_grants` 在插件启动时把仍在有效期内的原始配对凭据补齐到当前能力集，已配对浏览器无需重新配对；委托凭据、子凭据、已撤销与过期凭据保持不动。
- 归属边界不变：`require_document` 仍按 `owner` 隔离，配对身份只能读取和管理自己创建的任务；任务策略不得超出其自身能力与范围，仍受当前工作目录边界约束。
- 验收：`tests/test_browser_use.py` 断言配对可通过能力门禁、`device.revoke` 仍为 403；`tests/test_schedule_model_tools.py` 新增配对身份真实创建、列举且其他身份不可见的用例；`tests/test_browser_connection.py` 的恢复与幂等用例保持通过（19 项）。
- 仅后端改动，扩展包仍为 0.6.36；重启后端生效，已配对凭据自动升级。

### 0.6.36：逐段延迟的证据采集

- 用户明确提供 `run_shell` 中调用 `/api/mcp/tools` 的具体停点，并确认侧栏已加载 0.6.35。该工具属于运行 `89e13f2e…` 第 12 轮：23:14:34 写入执行中，23:15:24 完成。不是此前首次读取时仍活跃的 `5e48ff8b…` 运行，不能混用两次运行判断。
- 该轮桥接日志最大排队 6ms、单次主循环 emit 最大 1190ms；这不足以解释用户观察的约半分钟。尚无该次扩展后台/侧栏接收时间，不能断言根因，也不能将自动补载的补现当作实时链路已修复。
- 增加有界的元数据诊断：扩展后台接收、侧栏接收/缓冲/归属过滤、reducer 的应用/去重/忽略、React 提交、历史补载安装、执行快照来源以及自动恢复触发时的前后游标。后台与侧栏按会话、运行、执行及事件序号关联。
- 设置页增加「复制同步诊断」。仅保留白名单身份、状态与时间，不记录正文、命令、附件、Token 或配对信息。此版本用于获得具体链路证据，根因仍待真实停点诊断确认。
- 154 项单测及 8 项运行中恢复／诊断浏览器检查通过；已验证导出含实际恢复触发、历史安装及后台／侧栏接收和提交记录。跨轮连续性完整回归仍未通过：等待下一运行的正式用户事实超过 60 秒，后端当时仍在准备运行，不能计作通过。包与最终 dist 一致；验收记录 `browser-extension/artifacts/0.6.36-acceptance.json` 明确标记根因未确认。

### 0.6.34：中断感知与失败原因

- 旧版只读取 `content/reason`，遗漏 `run_failed.error`；无原因的中断也没有提示。现识别字符串及对象错误、结构化模型错误卡，并为无原因终态提供明确状态。
- 失败、中断及无法确认的结束状态显示在过程折叠区外，字号 11px、紧凑摘要，长详情按需展开；重复终态更新同一提示，模型错误卡的说明与解决方式保留。
- 运行时每 3 秒核对后端活动状态；两次稳定空闲后补读历史并再次核对，恢复漏收的正式终态。若没有终态，标注结果未确认。每次恢复核对会话及运行身份、不可变更新版本，避免迟到请求覆盖新进度或新运行；不会重放发送与工具动作。
- 旧 0.6.33 浏览器构建已复现：收到真实生命周期的失败事件后，界面仍无具体原因。只需重新加载扩展，无需重启后端。

### 0.6.33：图片加载后的历史底部定位

- 打开会话期间，`replayed_recent` 与 `replayed_snapshot` 均不会触发“新生成”的平滑滚动模式。图片异步加载改变高度后继续直接置底，不播放进入动画。

### 0.6.28：审查问题修复

- 切换快照未安装成功时，丢弃目标会话的缓冲，等待恢复原会话订阅。最终回放同时校验会话归属和选择代次，失败的 B 不会再写入 A；成功快照及同会话重载仍补放期间到达的事实。交互卡缓冲也沿用相同边界。
- 用户消息补取独立为按 run 合并的恢复控制器。一个请求未完成时不再重复发出；空历史和临时错误按 300ms 起、最长 8 秒退避重试，无须等待下一条流事件。成功、失效、切换及卸载清理定时器，过时响应不得覆盖新选择。属于同一执行组且已有用户消息的续跑仍跳过。
- 思考计时直接记录到 Runtime V2 的 `execution_recorded` 事实，复用现有日志与恢复检查点，不引入逐 token 的额外文件。开始时间在首个思考增量落盘，正文／工具参数开始或思考结束时冻结；后续完整内容提交使用同一跨度。新进程的局部计时不能覆盖已持久起点，run／迭代／stream 分别隔离，无实测起点的旧记录保持未知。同进程继续优先采用单调时钟测量。
- 移除仅在内存 state 字典中保存跨度的旧路径，真实启动不同 Python 进程完成写盘、边界冻结和历史恢复测试。新增 `npm run test:recovery` 在隔离 Edge 与真实控制服务中验证原审查中的失败场景。
- 批量 UI 提交的计时索引按修改复制，未提交的计划不能污染共享缓存；新增取消提交前的隔离测试。最终通过 111 项前端单测、157 项后端检查，以及 195 项浏览器检查（恢复 8、重启过程 9、菜单／滚动／回放 158、提问审批 11、Pending 9）。并行构建期间首次有一项 2 秒 shell 测试未读到输出，构建结束后独立重跑通过；首次并行启动的审批夹具超时，原夹具重试通过，见 `artifacts/0.6.28-acceptance.json`。

### 0.6.26：Pending 队列、Append 与 Interrupt

- 核对主 UI `dispatchComposerAction` 的行为后，侧栏采用相同顺序：生成中有草稿时第一次 Enter 加入 Pending；空输入第二次 Enter 优先发送刚排入的条目，否则发送第一条。默认 Append；每条待发项的菜单可选择 Interrupt。快速第二次 Enter 会等首次准入回执后继续，不会把同一段文字提交两次。空输入点击主按钮依然停止，Enter 不停止；修饰键和输入法组合不触发提交。

### 0.6.15：配对持久化与断线恢复

- 根因：长期浏览器配对凭据绑定了短期插件租约的 `epoch`。插件停止／重新加载会撤销该运行批次；重新启用后，未到期的用户配对仍因旧批次被拒绝。WebSocket 又将多种临时故障统一归为 4401，拓展据此删除了本机凭据。断线时的 UI 也统一显示配对表单。
- 新配对使用 `browser-pairing` 来源。它仍检查凭据有效期、设备撤销、插件是否启用及会话能力和范围，但不随插件运行批次变化而失效。插件启动恢复来源状态，并只迁移未到期、未撤销、属于已有浏览器记录的原始配对；任务委托和其他插件的租约继续按批次撤销。
- 临时运行时错误使用 1011、插件不可用使用 4403，真正的凭据拒绝使用 4401。拓展遇到 4401 还会通过认证 HTTP 读取复核；网络失败、暂时不可用及误报均保留凭据自动重连。自动断线处理不再删除凭据，只有用户清除本机配对才删除。
