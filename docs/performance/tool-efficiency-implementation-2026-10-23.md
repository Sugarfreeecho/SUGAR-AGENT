# 工具执行效率优化实施与验收（2026-10-23）

## 1. 本批结果

已实现五组工具的优化：`glob`、待办/Goal、`history_context`、`read_file` 和 `job_output`。其中分段读取、索引可用时的历史检索有明确的隔离对照收益；状态工具重点消除事件循环内的同步磁盘等待；glob 尚未证明真实工作区有稳定倍数收益。没有把模型输出、API 响应或人工等待算作本批收益，也没有宣布完整 Agent 轮间已达到 500ms。

生产代码为 6 个已有文件的修改、4 个新模块，另增加 1 个回归文件。变更基于本批开始时的工作区备份，未覆盖已有未提交改动。

| 组别 | 已实施 | 保留的边界 |
| --- | --- | --- |
| glob | leading `**/suffix` 用 scandir 同时做匹配与递归，提前剪除原已排除的 TempOutput | 其他模式回退 pathlib；保留顺序、链接规则、敏感路径过滤和精确省略数，不偷偷提前截断 |
| 待办 / Goal | 同步状态操作进入取消安全的 fact worker；待办在私有缓存预演，提交成功后在原循环发布 | 事实完成仍是继续执行的边界；同会话待办更新按序；失败和取消不留下未收敛写入 |
| 扩展状态 | `set_latest` 在一次事务中取得最新修订并替换，去掉 get 后 CAS 的双事务 | 显式 CAS 冲突、事实追加、来源校验、投影和检查点顺序保留 |
| 历史检索 | 可重建 SQLite 语义索引，冷查询结束后才排队后台构建；事件引用优先稀疏 seq 定位 | 任意源变化须验证旧前缀哈希；候选复核原始行；作用域、匹配、去重和排序保留 |
| 分段读取 | 每 128 个物理行缓存文本 cookie；只展开需要返回的虚拟行 | 1000 字符虚拟行、精确总行数、Unicode/换行处理和既有权限/大小限制保留 |
| job_output | 无输出且消费状态未变时跳过持久化 | 实际游标、结果、通知和缓冲边界变化仍提交；显式 offset 读取与 wait 行为保留 |

主/子代理调用相同工具实现和插件 handler 时共享这些改动；本批没有新增独立的子代理工具路径。Goal 的所有 HTTP 控制入口没有在本批整体迁移。

## 2. 最终源码对照

使用 Python 3.10.11，在隔离 `.analysis` 目录运行，不发送 LLM/API、不在生产会话创建问题或执行写工具。每组采用 before / after / after / before 顺序；不是负载固定实验，也不是 P95。最终基准 10 份生产源码与最终门禁、当前文件哈希一致。

| 场景 | before | after | 说明 |
| --- | --- | --- | --- |
| 4,860,000 字节文本，8 次范围读取 | 5723.802 / 3394.090ms | 438.866 / 461.911ms | 合成文本 180,000 行，每轮包含首次统计和后续尾部分段；完整输出 SHA-256 一致 |
| 34,980,597 字节真实日志前缀，3 次历史查询 | 378.321 / 362.000ms | 81.471 / 75.274ms | 单个冻结会话，不是完整全局会话集合；索引已准备，含命中与无命中查询；完整结果 SHA-256 一致 |
| 20 次扩展状态替换 | 62.220 / 61.888ms | 46.580 / 48.857ms | 空间较小的隔离会话；事务入口从 2 次变 1 次，不外推为真实卡片/整体轮间收益 |

历史索引首次构建 **1038.820ms**，生成缓存 **15,601,664 字节**，单列成本，未藏进“免费预热”。构建使用字节计数及有界较大缓冲，避免 Windows 逐行 tell 的文件位置查询；本批未对这一个小补修做负载固定的单项因果实验。完整查询结束后最多计划 8 个来源，后台只运行 1 个构建线程、在途不超过 8 个来源；缓存可丢弃，线程不阻止进程退出。冷查询仍走原扫描，不等待首次建索引。真实首次查询与后续任务之间的磁盘/CPU竞争仍需自然运行验证。

追加一条事实后，完整验证旧前缀再仅投影新增事实，查询 **93.736ms**、命中 1 条。哈希验证仍需读取整个已索引前缀，不能声称所有源变化都只读后缀。

第一轮非最终源码对照另外保存在 `benchmark-initial.json/log`：范围读取 2810.259–4508.725→375.994–389.705ms，历史三查询 643.210–644.764→133.109–137.264ms，首次索引构建1420.740ms。两批不混算；机器状态变化较大。

收尾补修前的一轮另存 `benchmark-before-final-reconcile.json`：范围读取1668.195–1683.774→228.110–255.557ms，历史三查询252.010–262.418→54.992–74.601ms、首次构建750.930ms。此后共享 event_log 有并发更新，本批索引构建也改用字节计数，因此上表使用重新冻结后的独立一轮，不把多轮挑选的最快值拼在一起。

## 3. glob 的实际结论

先前真实慢例见[候选审查](tool-efficiency-audit-2026-10-23.md)：2026-10-22 23:47，`**/.config/plugins*.json` 在 workspace 查找无匹配，调用包络 12,378ms。

本批早期仅对真实目录遍历做四次只读对照：旧8429.336ms、新3313.333ms、新2904.356ms、旧2905.752ms，结果均为空。最后一组说明热缓存后新旧接近，不能把第一组差异当成代码稳定加速。该组早于最终的异常错误传播补修；最终功能门禁覆盖补修。实现减少目录后缀探测并可剪除 TempOutput，仍可能需要遍历大量目录。精确省略数量的契约意味着仍收集完整匹配集合。

本批不宣称已消除 glob 的秒级等待；没有改成依赖过期索引判定“不存在”，也没有额外排除 sessions、node_modules 等原本可搜索目录。

## 4. 正确性与验证

最终集成门禁：**594 passed、1 skipped，61.89s，退出码0**。覆盖新工具用例、已有工具性能路径、图片、历史、作业、fact commit、Goal/runner、工具注册、Todo、工具结果与 Runtime V2 全套。261 份 app/plugins Python 源码在门禁前后哈希一致；最终基准关键源码与门禁一致。未将各轮重叠用例数累加，也不代表全仓库所有测试通过。

此前590通过/1跳过、45.92s的一轮本身无源码漂移，但之后共享 `event_log.py` 出现并发改动；已复核差异，保留原结果在 `gate-before-final-reconcile.*`，再按当前整合版本完整重跑得到上述594项。最后一轮集合中包含新增的 Runtime 用例，两个总数不相加。

收尾复核又发现另一工作对 `app/runtime_v2/ui_row_store.py` 有门禁后的更新。`final-audit.json` 明确保留该差异；本批10份生产源码仍与594项门禁及最终基准一致，60个本地文档链接无缺失。没有把后来的UI行存储版本宣称为本批门禁已覆盖，也没有覆盖或反复追逐其他工作的修改。

跳过项是 Windows 目录符号链接权限不足。其余源码/测试对来源替换、mtime 恢复改写、UTF-8 坏字节、长行、换行、范围 seek、重复取消、待办并发提交顺序、跨线程回执、修订重放、索引前缀改写、半行与缓存损坏、空轮询及真正消费进行了验证。意外磁盘错误应传播为工具错误，不能伪装成 glob 无匹配。

读缓存使用已打开文件身份、大小、mtime、ctime；Windows 额外通过该句柄查询 NTFS ChangeTime，避免把创建时间误作修改时间。属性查询失败禁用缓存复用。历史索引在来源发生变化时完整校验旧前缀摘要，读写/替换不一致时回退或重建；SQLite 锁忙、损坏、未知身份和未完成末行不阻断原扫描。候选按原始行再次复核关键词，查询达到去重后的结果上限即停止，不先收集所有索引命中。

### 验证过程的原始失败

- 首轮124项门禁前的尝试出现3个 ripgrep mock 测试失败：Windows 的 platform 冷发现调用被测试替换的 Popen 拦截；验证 runner 先做正常平台发现后，原测试未改，124 passed / 1 skipped。日志中的初次错误保留在会话输出，不计为最终门禁。
- 第一次扩大门禁 runner 缺少 `__main__` 守卫，Windows spawn 子进程重复启动 pytest；子运行记录2个 bootstrap 错误。已按本次 runner 的已核对进程父子链停止测试进程及其后代，生产服务不在该链内；父轮中止，不作为完整门禁。保留 `gate-spawn-attempt.*`，补上入口守卫与 freeze_support 后重跑，才得到上述590项正式结果。

## 5. 暂不扩大与生产加载

- **change-review**：本批未改扫描规则或索引保存。候选审查窗口 batch_flush 平均约21ms，虽有282ms尾部，但不足以支持大规模重构；mtime-only 快筛和只按根目录 mtime 缓存 inventory 不安全。继续保留原有批次合并和完整来源检查。
- 全局历史会话发现仍递归枚举；整份归档分页仍先清洗完整归档。大型改写后的索引重建、初次查询、不同机器负载下的尾部响应均未保证500ms。
- 截至 **2026-10-23 01:52:12 +08**，8192 服务为 **PID11568，01:47:53启动**；本批部分文件在该启动时间后仍有补修。不能据此认定所有最终模块统一加载。没有由本批操作重启/停止生产服务；当前任务结束后统一重启一次，再用普通真实任务验收。
