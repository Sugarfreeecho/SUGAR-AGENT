## 4. 流式和结束阶段的口径修正

- `llm_local_consumer` 的 P50/P95/最大为 **872/1806/2484ms**。它是 worker 完成至消费完成，包含桥接、usage 及可能重叠的早启动工具；不能全部当成“工具完成后的空等”。
- `llm_stream_delivery.main_emit_total_ms` 是整段生成期间累计的主循环投递时间，**不是轮间间隔**。例如28轮累计19120ms、单次最大2133ms，部分与模型输出重叠；不能加到1445ms上。
- 结束 `final_pipeline=460ms`，其中 `finish_after_final=360ms`。其日志完成于09:58:27.016；耐久 run_finished 于09:58:28.086，指标终态完成于09:58:28.134，**pipeline 之后还有约1.1秒终态处理**。尚未逐步骤归因，不把460ms当作整个收尾。
- 本次没有持续死锁或无界卡住的证据；存在反复出现的本地长尾。前42个配对样本已有13次超标，最后43个为6次，不能从这个会话得出“越往后必然越慢”的结论。

## 5. 据本次证据追加的改动

`execution_metrics.py` 改为在锁内发布稳定的请求根对象：快照持有私有的 run 头和请求列表；记录更新通过 `_request` 获取可写对象，若已发布，只复制被修改的单条请求。输入字段/phase/运行扩展值在进入内部状态前复制，防止调用者之后修改其对象；对外 snapshot 仍返回独立副本。没有持久化第二份整段请求缓存。

每会话 I/O 锁、后台领取状态、慢旧写不能覆盖新写、终态 flush 等语义保留。刷盘/看板序列化在全局锁外执行；事实 journal、用户/模型/工具提交不走此派生快照机制。

在本次1,139,811字节、172请求的真实指标数据上，每种方法各20次复测：整份 deepcopy 中位数 **65.750ms**、最大77.238ms；发布根中位数 **0.040ms**、首次1.202ms。两种结果逐值相等。这只证明指标捕获阶段收益，不声称会话整体快1644倍。相关并发/隔离与流式回归 **82 passed**；完整 Agent 压测结果见[总报告 §8](agent-interround-2026-10-17.md#8-追加修复与现行验证)。
