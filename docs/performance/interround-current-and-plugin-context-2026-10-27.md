## 2. 本批修改

### 2.1 插件上下文目录读取复用原事件循环

`plugin_context.prepare_for_step` 原先两次 `asyncio.to_thread(load_plugins)` 没传原owner loop。worker内没有running loop，目录TTL到期时 `_schedule_plugin_cache_refresh` 返回False，随后等待扫描锁并同步 `manager.load_enabled`。此前Hook准备已经修过同类调用，但动态上下文入口遗漏了它。

现在初次目录读取与收集后的复核都显式传 `refresh_loop=asyncio.get_running_loop()`，复用既有单次后台刷新、同键/新鲜度/代号校验和扫描锁。缓存冷启动、目录真正失效仍等待权威新目录；没有延长TTL。动态提供器仍按步骤采集，禁用/签名变更仍在收集后复核，停止后的迟到结果仍受写入围栏限制；没有将业务资料改为跨步骤旧缓存。

新增 `plugin_context_prepare` 慢调用计时，包含 catalog / snapshot_read / provider_collect / catalog_revalidate / plan_snapshot，保留同一session/run/iteration，跨worker复制计时上下文；日志不带资料正文。

### 2.2 工具目录剩余未归属区间

另一例1188ms目录重建仍缺内部证据。隔离进程用真实51工具目录剖析：预热tokenizer后，披露装配约66–69ms，3次本地分词CPU约62ms；这不能解释生产1093ms，因此没有把它当成已证实根因，也没有先重构token缓存或放松工具披露/授权。

`build_combined_tool_registry_for_session` 补充注册、命名/授权策略、披露装配三段；请求侧补充运行配置快照准备。它们是原目录总段内互斥区间，复用既有统计入口，未覆盖的差额继续保留，保持既有总耗时算法和实际授权/发现路径。
