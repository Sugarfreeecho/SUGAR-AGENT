### 2.1 值得补修：插件manager反复解析同一路径

95b下一请求iter13总1537.283ms，其中core→提交1122.335ms；PostToolUse1037.230ms，内部`plugin_manager_canonical`963.780ms、线程CPU0ms，实际hook脚本0.069ms。ca452下一iter18的591.584ms中同一canonical子段另占186.716ms。可确认重复`Path.resolve`在这些本地长尾中出现，不能把它全部说成锁等待或脚本慢。

**已实现**：默认manager配置名称使用最多32项LRU。仅已是canonical拼写的路径可命中；每次校验lstat的device/inode/ctime/type与父目录身份。文件创建、替换、父目录替换、环境配置变化会重新解析；别名、reparse、未知身份、缺父目录、访问错误走原实时解析。默认路径发现/迁移检查继续执行，插件启停状态、信任和实际调用权限仍实时检查。缓存只减少名称解析。

隔离局部比较（3条配置路径）：原60次热访问resolve180次，新0次；本机原P50 1.378ms、新0.811ms。对每次resolve注入25ms等待的12次比较原P50 98.916ms、新0.927ms，证明命中能避开该调用，**不是生产收益预测**，不能把964ms全部当作已节省。首次临时目录使用Windows 8.3别名时缓存按设计不命中，原P50 1.418ms、新2.218ms，说明别名路径仍有守卫成本；该失败/限制保留，没有放宽别名规则。修正探针为canonical配置后得到前述可命中结果，见[局部机制结果](../../.analysis/interround-500ms-implementation/20261019-review/manager-mechanism.json)及[首次别名结果](../../.analysis/interround-500ms-implementation/20261019-review/manager-mechanism-alias-first.json)。

### 5.1 已共用的优化

子入口`agent_subagent._execute_subagent_run._run_core`直接`await react_node(state, emit=child_emit)`，没有另一套独立ReAct实现。因此复用：

| 项目 | 子agent覆盖情况 |
|---|---|
| LLM请求池与真实HTTP端点 | 流式、非流式和回退均走共同run_request_worker；池是进程级，主/子共用，不是每个子agent独享 |
| 发送前减量 | 共同静态段、请求整理/增量计数、目录缓存与后台重验；静态段按session/is_subagent区分，不混父子提示和权限 |
| 插件/Hook | 共同加载与manager名称缓存；子代理调用时启停、信任仍实时 |
| 模型工具结果事实合批 | 共同checkpoint_ready_tool_results及_persist_completed_tool_batch，仍保持发API前事实提交 |
| EventLog、快照、增量投影、派生缓存 | 子会话路径经相同底层模块；WebUI预热的快照worker是进程级 |
| 外层重试首次发送修复 | 共同工厂和栈内trace引用可用；计时run身份另有下述入口缺口 |

### 5.2 尚未覆盖的子agent专用路径

1. **UI工具结果批量交付未接通**。主入口通过`_attach_tool_batch_emitter`和StreamEventBridge提供`emit.tool_batch`；`child_emit`没有该接口，共同`_emit_tool_call_sse_batch`会逐项回退。不要把已实现的模型事实合批与未接通的UI交付合批混为一谈。
2. **单条journal/UI组合提交未接通，回调仍有同步I/O**。主入口调用`persist_execution_event(..., commit_ui=True)`，子入口省略参数，采用默认False，journal.to_thread后再同步append_ui_event；15秒一次的心跳metadata也同步执行。前台子任务位于创建方ReAct循环，后台子任务由进程级持久loop托管；当前没有额外使用主入口的StreamEventBridge。同步处理有阻塞该loop其他子任务的可能，本次未量化其真实贡献。
3. **task入口运行身份及结束观测不完整**。state设置`_subagent_run_id`但没有`_runtime_v2_run_id`，共同trace/metrics读取后者；子入口也不经过主入口start_run/finish_run及run_finalize。扫描到的近期子指标存在`run_id=""`，例如effe381c下51c11a13。`execution_metrics._run`按run_id查找，空ID可能让同一子会话多次task运行覆盖相同iter，故没有使用这些原始长尾计算子agent正式达标率。子代理registry及元数据仍有真实run ID，预约/取消所有权与该观测缺口分别处理。

子代理自身还有首次历史装载、预约/任务索引、每15秒心跳、结束历史对齐、输出文件与pending结果等步骤；共享存储模块可受益，但并不等于这些业务步骤被主入口优化删除或全部异步化。

本次既有`test_agent_subagent_runtime_v2.py / test_subagent_live_state.py / test_subagent_optimizations.py`合计**40 passed，17.85秒**，只验证当前生命周期、事件路由和隔离等功能，不证明性能目标或新缺口已修复。若继续子代理优化，应先补齐独立run计时身份，再将UI单条组合提交及已完成工具批量交付接入专用回调，并保留后台loop生命周期和父子取消边界。实现范围已补入用户设计02/10 UC-2J12。
