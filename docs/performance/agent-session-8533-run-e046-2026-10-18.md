## 4. 实跑后补修：前移可确认的一次性线程创建

`SnapshotStore._schedule_checkpoint`原可在会话事务中首次启动后台线程。新增幂等`start_checkpoint_workers()`，WebUI服务启动时先经to_thread建立有限worker，再进入恢复/用户请求；该动作不创建会话或快照文件。首次事实提交可直接使用这些worker，启动失败保留原惰性重试。线程数仍由原配置约束（默认2、范围1–8），运行时调高配置或启动失败后仍可能追加启动。

这消除了正常启动中一次可确认的初始化位置，不证明实跑834ms全部由Thread.start造成。原10ms可配置短等待、同步事实落盘、源身份/锁及授权检查保留。

同时补齐必要计时：

1. `model_commit / model_commit_batch`从state取得session/run/iter，支持同步函数，记录事实提交及原异常路径；不记录消息内容。
2. 事务细分lookup、进程内锁、目录与锁文件准备、open、OS锁；lookup/目录仍是包络，不伪称纯锁。
3. 快照发布细分路径、取消守卫、文件签名、内存发布、due检查、schedule、inline wait。
4. 插件manager细分锁获取、默认路径/迁移检查、canonical解析及构造；检查与读取行为保持原顺序。registry_revision只有session参数时按session和时间关联，不伪造run ID。
