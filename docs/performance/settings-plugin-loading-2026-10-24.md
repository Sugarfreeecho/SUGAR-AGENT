# 设置中心插件页签加载优化

2026-10-24，Asia/Shanghai。修复已部署，后端在 11:47:21 请求重启、11:47:32 恢复在线。连续两次确认没有运行中的任务后重启，未中断任务。前端产物 main-DyPh7ev9.js。

## 原因与证据边界

设置中心启动会调用 `loadPluginSections()`，等待 `/api/extensions` 后才注册插件贡献的导航页签；插件列表分区也读取同一个完整快照。该快照既包含静态清单/UI 声明，又调用运行时 `command_descriptions()`、`snapshot()` 和 `hook_snapshot()`。运行时查询需要注册表锁，首次 describe 还会启动 Worker；插件请求持有该锁时，页签也跟着等待。完整快照缓存过期、失效或重启之后可能再次进入这条路径。

本次当前空闲服务的三次 `/api/extensions` 热请求为 12.7、10.3、11.0 ms；旧页面的完整快照请求 43.7 ms，在导航后 195.6 ms 返回，没有现场复现用户所说的“总是要等很久”。不能把这些热数据当作没有问题的证明，也没有日志证据把用户每一次慢都归因为锁。新增并通过的受控回归确认：同一真实运行时锁被占用时，完整快照保持等待，新的目录接口能独立返回并注册页签。

新进程同一插件集合、使用 cProfile 的单次隔离剖析：

| 指标 | 完整快照 | 轻量目录 |
|---|---:|---:|
| 墙钟耗时 | 563.0 ms | 280.6 ms |
| 插件加载 | 232.2 ms | 230.8 ms |
| 运行时命令查询 | 276.9 ms | 不调用 |
| Hook 快照 | 7.4 ms | 不调用 |
| 插件数 / UI 声明数 | 8 / 26 | 8 / 26 |

隔离耗时减少约 50%，主要消除了这个页面不消费的运行时查询。该数值包含剖析开销，只是这次单样本；不能当作高负载下的 P90 或用户过往长延迟的提速百分比。

## 改动

- `app/agent_extensions.py`：新增 `plugin_catalog_snapshot()`，只构建插件列表、启用状态、已校验的 UI 声明和清单错误/警告。与完整快照共用目录生成逻辑，保持内容和校验规则一致；目录不获取运行时注册表、不启动 Worker、不构建 Hooks。单独采用有界、合并并发请求的目录缓存；启停、安装、卸载、重载等既有操作提升目录代数后失效。将 HTTP 所属循环传入已有插件缓存，使过期目录能安排后台扫描，而不因线程中没有循环退回同步扫描。
- `app/webui.py`：新增 `/api/plugins/catalog`。在线程中构建，记录 `plugin_catalog_timing`，并返回 `Server-Timing` 的 `queue`、`catalog`。可区分线程排队和目录生成；不记录配置密钥或消息正文。
- 设置中心：插件列表、插件子页签发现及悬停预热读取轻量目录。Hooks 和其他完整扩展使用者保留原接口。
- 共享浏览器目录缓存新增只读 `peek`，在重新获取目录之前可先恢复已有页签；仍不持久化插件清单。写操作和跨窗口变更清除旧数据，返回值克隆，不能被表单直接污染。子页面只复用支持新目录接口的父页面缓存，兼容尚未刷新的旧聊天页面。
- `settings.plugin-tabs` 浏览器性能条目记录本次目录获取与导航注册耗时。它测量 DOM 注册完成，不等同于下一帧完成绘制；若已通过 `peek` 先显示旧目录，条目的结束时间仍对应后续刷新完成。

没有修改插件启用/信任的执行判定，也没有把旧显示缓存用于执行授权。

## 真实页面验证

通过 Edge 的真实页面操作验证，API 与前端回归测试结束后才测量。

| 条件 | 导航到插件子页签注册 | 目录网络请求 | 后端目录生成 | 完整扩展请求 |
|---|---:|---:|---:|---:|
| 重启后该接口首次打开 | 1,085.8 ms | 461.5 ms | 393.8 ms | 0 |
| 服务已暖后的新页面 | 81.8 ms | 12.2 ms | 4.9 ms | 0 |

首次页面在导航后 619.7 ms 开始目录获取，466.1 ms 后完成页签注册。已经显示 8 个用户插件列表、ChatGPT 订阅/语音输入与朗读/刷B站值班设置三个子页签。第二个页面切换“常规→插件”后，目录请求总数仍为 1，无新增插件请求，三张列表卡片正常显示，没有加载占位。常规页面自身的模型和权限请求另行发生，不计入插件目录请求。

这是本机这两次页面观测，首次条件与原先空闲热页面不同，不能直接将两者计算为提速或退化百分比。运行时 Worker 卡住时的独立性通过受控后端及浏览器回归覆盖，尚未做真实模型高负载 P90 抽样。主线程或 HTTP 事件循环被其他功能阻塞时，轻量接口仍可能等待调度；新增队列/生成时长方便继续定位。
