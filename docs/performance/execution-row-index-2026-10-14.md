# 执行行查找优化（2026-10-14）

第一项优化已完成：新文字更新直接通过索引找到对应消息行，避免每次扫描全部历史执行记录。

## 改动

- 每个消息区域共享一个执行行索引。恢复、切换渲染上下文时可复用已有索引；区域释放后索引也可回收。
- 新执行行创建后立即登记。历史补页或重新加载后，在下一次查找时重建一次。
- 缓存中的消息行被替换或移除时，重新确认实际 DOM，避免更新旧节点或生成重复记录。
- 保持原先的匹配顺序，嵌套的审批卡片与消息行共用执行 ID 时仍优先匹配消息行。

生产修改位于 [message-rendering.js](../../frontend/src/app/modules/message-rendering.js) 与 [session-scroll-history.js](../../frontend/src/app/modules/session-scroll-history.js)。前端构建已更新为 `/assets/main-Bb82CeCB.js`。

## 实测

使用与[初次分析](long-session-2026-10-14.md)相同的隔离回放：150 条缓存 SSE 更新，固定新增文字，50 轮历史、1001 条执行行、8077 个页面元素。原版与优化后各重复三次，下面为中位数。

| 指标 | 优化前 | 优化后 |
|---|---:|---:|
| 整批处理时间 | 70.0ms | 15.0ms |
| 各次最长 RAF 间隔的中位数 | 82.3ms | 16.9ms |
| 每次超过 50ms 的间隔数 | 1 | 0 |

整批处理耗时降低约 **79%**。优化后短历史、10 轮历史和50轮历史的整批处理中位数分别为 13.9 / 14.2 / 15.0ms，全部缓存回放均通过最终完整文字校验，无页面脚本错误、无长任务。

这是无头 Edge 中对当前构建的受控验证，RAF 是主线程回调指标，不等于屏幕实际 FPS；该改动解决了已复现的查找开销，尚不代表全部现场卡顿都已解决。

数据：[缓存批量回放](execution-row-index-2026-10-14-burst.json)、[持续逐字输出回放](execution-row-index-2026-10-14-continuous.json)。
