## 3. 本批实现

1. **成功追加回执衔接**：对已写入且flush成功的实际事实字节建立有界热尾部；相邻写入前后身份、长度、mtime须连续，末端再核对当前命名文件。journal结合原始SourceWindow核对后回放这些字节，避免重新打开刚提交的文件。最多64个路径、每路径32条/256KiB。未知外部写入、替换、失配或缓存缺失均读实际文件；独立边界验证和恢复检查点完整哈希保留。
2. **快照字节游标**：stamp增加文件身份，从已知完整行边界补尾；可用成功回执直接解码，否则读取真实后缀。版本、源身份、完整EOF、连续seq和through_seq全部通过才应用；旧格式兼容，已知替换/截断完整回放。
3. **定向观测枚举**：周期与启动对账只走会话和子代理容器，不遍历任务文件、checkout或node_modules；不跟随链接/reparse容器。周期、版本/待刷/配置代保护及stale持久化契约保留。
4. **Hook同次目录复用**：dispatch及预热把本次已加载资源传给manager；强制刷新仍重新加载，未增加跨派发TTL。
5. **无写入persist减量**：primary中未变化摘要直接结束；实际摘要写入、模型/工具事实、legacy提交仍重新检查所有权。去掉工具检查点中重复的主对话派生。
6. **已完成只读结果合批**：只合并已经完成的相邻只读结果/并行组已完成集合，不等待凑批；保留独立model_tool事实，一次追加及投影发布。随后仍逐条严格提交execution/UI，全部完成才发送API。单条、控制/写工具沿原路径；成功兄弟结果先建立检查点，再传播取消/steer错误。追加失败不发布成功标记。
7. **严格UI交付合批**：连续四组测试再次暴露8/8重载长历史超标后，继续把同一已完成批次的execution/UI交付放进一次短事务和一次工作线程调用；逐项事实/flush及取消检查保留，全部成功后才公开。批次内追加句柄只复用至解锁前，普通维护不保留句柄。跨loop队列使用私有封套并保持delta/终态屏障；非strict/子代理转发回原路径。
8. **纯文本附件快筛**：工具UI文本不再被当成附件块序列逐字符遍历，真实块数组保持原处理。

持续保留用户轮、助手/工具结果、压缩摘要及子代理所有权四类关键事实边界。未使用跨独立提交常驻读句柄；没有缩短事实的既有持久化契约。
