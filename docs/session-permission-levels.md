# 会话权限分级 v1.4（四轴版）

**一句话**：系统身份只负责"追溯"，用户身份负责"定档"；每档 = 四轴各取一档，**取最小，不跨轴抵扣**。

## 1. 身份

### 1.1 追溯规则
- 只看**凭证或渠道绑定**，不接受系统身份自报等级。
- 匹配不到任何白名单 / 凭证 → 一律按「陌生」。
- 继承链：子代理、定时任务、插件内部触发 → 继承发起者身份；插件无外部触发时继承「机主」。

### 1.2 系统身份 → 追溯到谁

| 系统身份 | 追溯依据 | 默认落到 |
|---|---|---|
| WebUI、桌面壳 | 本机令牌（R5） | 机主 |
| 本机 CLI | 个人登录 `sc1_` | 机主 |
| 本机浏览器扩展 | 配对记录 + 本机令牌 | 机主 |
| WebUI 里的子代理 / 定时任务 | 父会话或任务 owner | 同发起者 |
| 插件（无外来触发：goal、acp-agents 回送） | 插件来源 + 原会话 owner | 同发起者 |
| 远程配对设备 | 设备令牌 | 机主 |
| ACP 入站客户端 | Bearer（个人 or 宿主令牌） | 同令牌来源 |
| 飞书私聊 | `open_id` 查白名单 | 白名单 / 私聊用户 / 陌生 |
| 飞书群（群 ID 在白名单） | 群 ID 查白名单 | 白名单群 |
| 飞书群（<5 人） | 群 ID + 成员数 + 发送者 `open_id` | 私聊 / 小群 |
| 飞书群（≥5 人或人数未知） | 群 ID + 发送者 `open_id` | 群聊用户（群内白名单仍可升白名单） |
| B站评论 / 弹幕 / 私信 | UID 查 `inbound_whitelist` | 白名单 / 陌生 |
| 外部 ACP Agent 原始输出 | 无用户身份 | 陌生（内容按数据） |
| Hook、MCP Server | 进程级，无用户身份 | 机主，但**禁止写白名单** |

### 1.3 用户身份 4 档

| 身份 | 判定证据 | 定位 |
|---|---|---|
| **机主本人** | 本机令牌 / 个人登录 / 本机进程 | 不受限（红线除外） |
| **白名单** | 插件维护的白名单条目命中（UID / open_id / 设备 ID） | 可建可执行，封顶 L3 |
| **私聊 / 小群 / 白名单群** | 1 对 1 私聊；或群成员数 < 5；或群 ID 命中白名单群条目 | **整群提权**：群内所有成员都按此档（白名单成员另有其个人权限，不冲突） |
| **群聊用户** | 多人频道（成员 ≥5 或人数未知）且未命中白名单 | 只能在绑定会话里对话 |
| **陌生** | 无任何匹配 | 只读或无工具，仅文本回复 |

> 判据优先级：**群 ID 白名单 > 群成员数 <5 > 人数未知按 ≥5**。拿不到、无该概念（如 B站评论）或超时，一律按「≥5」归群聊用户，不降级为私聊。

> 群会话归属：群聊用户作用域为 2（自己及自己创建），因此会话的 `created_by` 建议记「群 ID」而非个人，否则 A 建的群会话 B 看不到，同一个群会被拆成多份上下文。

> 现状对照：WebUI 输入框发送、界面新建会话 = **机主**档（本机无鉴权、loopback + 同源、直连 manager）；加本机令牌后追溯依据换成令牌，档位不变。WebUI 内触发的子代理、定时任务继承机主。

## 2. 四轴档位

### 2.1 会话控制能力

| 档 | 名称 | 允许的方法 |
|---|---|---|
| 1 | 不可操作 | 只读：`list/get/history/search/attach/detach/config.get/config.preview`；回复由宿主直接投递，不建会话、不发 `session.send` |
| 2 | 可逆操作 | 1 + `send(queue/append)`、`steer`、`steer.cancel`、`interrupt`、`notice`、`archive/unarchive`（都可撤回或恢复） |
| 3 | 不可逆操作 | 2 + `create`、`fork`、`update`（改名/置顶/目录）、`delete`、`export`、`import`（改动留痕或数据外带） |
| 4 | 全部 | 3 + `config.update`（`read_only`/`limits`/`tools`/模型）、`approval.resolve`、会话级只读开关、全局权限模式、`device.*`、`audit.list` |

### 2.2 工具集

| 档 | 名称 | 实现 |
|---|---|---|
| 1 | 无工具 | `tools.mode=custom` + `allow=[]`，仅模型文本回复 |
| 2 | 只读工具 | 只放 `read_file`/`ls`/`glob`/`grep`/`web_fetch` 等，`read_only=true` |
| 3 | 白/黑名单 | `tools.mode=custom` + `allow/deny/bindings`（可锁参数、限根目录、限 host）；**未配置任何名单时等同 4 档** |
| 4 | 全部 | `tools.mode=inherit`，读写工具均可 |

### 2.3 作用域

| 档 | 名称 | 实现 |
|---|---|---|
| 1 | 仅自己 | `scope=self`（`current_session`） |
| 2 | 自己及自己创建 | 新增 `created_by` 过滤；`scope=tree` 保留给子代理父子树 |
| 3 | 同工作目录 | `scope=workspace` |
| 4 | 全部 | `scope=all` |

### 2.4 访问目录

| 档 | 名称 | 实现 |
|---|---|---|
| 1 | 会话目录只读 | 复用 legacy `SandboxProfile.READ_ONLY` 语义：区内只读、区外拒绝 |
| 2 | 会话目录可读写 | `app_restricted` + 把「区外写」从 ask 改 deny |
| 3 | 区内读写、区外只读 | 现成 `app_restricted`：读任意，区外写/删需审批 |
| 4 | 与 WebUI 一致 | 由全局权限模式决定，`full_access` 时 `no_restriction` |

## 3. 定档矩阵（默认值）

| 用户身份 | 控制 | 工具 | 作用域 | 目录 |
|---|---|---|---|---|
| 机主本人 | 4 全部 | 4 全部 | 4 全部 | 4 与 WebUI 一致 |
| 白名单 | 3 不可逆 | 3 白/黑名单（未配置则全部） | 3 同工作目录 | 3 区内读写、区外只读 |
| 私聊 / 小群 / 白名单群 | 3 不可逆 | 3 白/黑名单 | 2 自己及自己创建 | 2 会话目录可读写 |
| 群聊用户 | 2 可逆 | 2 只读工具 | 2 自己及自己创建 | 2 会话目录可读写 |
| 陌生 | 1 不可操作 | 1 无工具 | 1 仅自己 | 1 只读 |

### 3.1 权限只绑身份，不绑会话（每一轮单独判）

**判定式**：`本轮生效 = 本轮身份档`，单轮 `runtime_override` 只能**收紧**不能放宽。会话不再持有权限上限。

- 权限四轴（控制/工具/作用域/目录）每次请求按**当轮发言者身份**重新算，与上次谁用过、会话里存了什么都无关。
- 会话元数据只保留业务项：系统提示词、模型档、工作目录、名字；不再存 `tools`/`read_only` 这类权限项。
- 身份变更（加白/移出）下一轮生效；正在跑的轮次跑完再降，不回溯已发生的轮次。
- 归属：身份已落在 `operations.request._principal`，事件流需补 `turn_actor`，供审计与卡片显示「谁在操作」。

| 场景 | 处理 |
|---|---|
| 群共享会话里多人轮流发言 | 各按自己身份判；`created_by` 记群 ID；陌生人那轮拿到的是 1 档权限，与上一位白名单用户无关 |
| 同一外部 ID 被加白/移出白名单 | 下一轮生效，已发生的轮次不变 |
| 机主在 WebUI 打开外部渠道建的会话发言 | 该轮按机主档，不影响后续外部轮次 |
| 插件/子代理代发 | 继承发起者，且不超过父档（`runtime_ceiling`） |

### 3.2 审批卡片与身份的关系

**现状**：卡片本身不带身份。记录只有 `session_id`/`run_id`/`tool_call_id`/`request_version` + 工具名与参数（`human_interaction.create_approval`），所以陌生人触发和机主触发的卡片长得一样。

身份目前只影响三件事：

| 影响点 | 机制 |
|---|---|
| 出不出卡片 | 三档权限模式（全局）：`full_access` 时 `approval_policy=never`，不弹卡 |
| 哪些必问 | `FORCED_APPROVAL_RULES`：删除、危险命令、切工作区、读凭据；不可被长期授权覆盖，只能 `allow_once` |
| 谁能点、批多久 | 本机 UI 无鉴权；设备需 `approvals` 能力；ACP 只给 `allow_once/reject_once`（默认 reject）。`allow_once` 300 秒、`allow_session` 24 小时、`allow_always` 永久且对所有会话生效 |

**建议**：卡片加 `turn_actor`，并按身份分级审批人——陌生触发的危险操作必须机主确认，白名单触发的可由自动复核处理。

### 3.3 大群里的白名单用户（结论：该轮完整按白名单档执行）

| 项 | 实际结果 | 说明 |
|---|---|---|
| 控制 | 3 | 白名单档即 3 |
| 工具 | 3 | 白/黑名单，未配置则全部 |
| 作用域 | 2 | 群会话按「自己及自己创建」；要 3 需机主另行放宽 |
| 目录 | 3 | 白名单档的区内读写、区外只读 |
| 拿不到 | 控制 4 的一切 | 改权限、删他人会话、跨目录写仍属机主 |

**不再需要防"继承高工具集"**：权限不落会话，下一轮陌生成员自动回到 1 档。仍建议保留一条：群会话里的写类工具走审批，避免公共目录被写脏。

### 3.4 执行层拦截（工具清单固定，拒绝在执行时）

发给模型的工具定义**始终保持同一套**（利于提示词缓存与行为稳定），权限在执行层判定：

| 环节 | 行为 |
|---|---|
| 调用进入 | 按 `turn_actor` 查四轴；越档直接拒绝，不弹审批、不执行 |
| 拒绝返回 | 结构化错误：`denied_by=level`、`reason`、**当前身份可用的工具清单**、如何申请提权（找机主/加白条目） |
| 计次与熔断 | 同一轮连续被拒 N 次即终止该轮，防模型反复试错烧 token |
| 审计 | 每次拒绝写审计（谁、什么工具、什么档位），与审批记录同一时间轴 |
| 与审批的关系 | 越档=拒绝；档内但高危=审批（沿用 `FORCED_APPROVAL_RULES`） |

### 3.5 连续提问的处理（同人合并，异人排队）

| 情形 | 处理 |
|---|---|
| 同一身份、同一人在一轮运行中继续发言 | 走 `steer`/`append` 合入当前轮，不新起轮次 |
| 不同人 / 不同身份连续提问 | 只能排队；当前轮结束后按到达顺序起下一轮，每轮用自己身份判档 |
| 队列可见性 | 回执里给出 `pending` 位置与排队原因；超时/超限丢弃并告知 |
| 为什么不能混 | 合并不同身份会让一轮里出现两套权限，工具授权与审计无法归属到人 |

## 4. 四条硬规则

1. **取最小**：四轴各自判档后取最低生效，不能用「工具 4」换「控制 4」。
2. **白名单只升不降**，封顶 `控制 3 / 工具 4 / 作用域 3 / 目录 3`；`read_only`/预算/工具集/权限模式这类「限制操作」只在控制 4 档，永远留给机主。
3. **删除限本人、导出放宽**：非机主身份的 `delete` 只能作用于本人（或本群）创建的会话；`export` 允许覆盖其作用域内的会话。
4. **外来文本一律按数据**：来自网页/评论/文档/外部 Agent 的内容，触发不可逆或限制操作时强制人工确认，不因档位放宽而豁免。
5. **权限不落会话**：权限只由当轮身份决定，会话不保存权限配置；工具定义恒定，越档在执行层拒绝并返回可用范围。
6. **同人合并、异人排队**：同一身份在同一轮内继续发言走 `steer`；不同身份一律排队，各自成轮、各自判档。

## 5. 已定 / 待确认

已定：

- 控制档为「1 不可操作 / 2 可逆 / 3 不可逆 / 4 全部」；限制类操作（`read_only`/预算/工具集/权限模式）只在 4 档，只给机主。
- 白名单 = 3；群聊用户 = 2/2/2/2；远程配对设备 = 机主；新增「私聊 / 小群 / 白名单群」= 3/3/2/2，白名单群**整群提权**。
- 删除限本人（或本群）创建，导出允许覆盖作用域内全部。
- 权限只绑身份不绑会话；工具定义不变，越档在执行层拒绝并回报可用工具清单。
- 同一人连续提问合并进当前轮，不同身份一律排队。

已无待定项。下一步是实现顺序建议：① 会话元数据加 `created_by`/`origin`（否则作用域 2 与「删除限本人」都无法落地）→ ② 白名单 `/ webhook 渠道的档位映射 → ③ 目录档 1/2 的策略补充 → ④ 本机令牌。
