# 前端工具执行结果乱码 · 诊断报告

- 日期：2026-10-07
- 会话：`06345307-d8e7-49ac-aa81-6c6f7726a2ca`（本会话）
- 环境：Windows + PowerShell 5.1（936 代码页）+ 本仓库 `app/main.py` 运行中

## TL;DR

1. **不是前端渲染问题。** 前端把后端传来的字符串原样写入 DOM（`textContent`），SSE 全程 UTF-8（TextDecoder），没有任何二次解码；实测"界面显示 == 会话存档"逐字符一致。
2. **乱码产生在后端"子进程输出字节 → 文本"的解码环节**（`app/agent_tools.py:1239 _decode_cli_subprocess_bytes`；全仓库唯一的 GBK 解码点在第 1255 行）。两类现象：
   - **A 类｜解码失败占位（`�`，U+FFFD）**：字节确实不构成 UTF-8（二进制 / GBK / 混合流）。一部分属设计性降级；**但当整段流是"混合编码"时，本可正确解出的 GBK 中文也会被整段降级成 `�`**（例：`2026��10��3��`）。
   - **B 类｜GBK 二次乱码（`锟絓` / `閿熸枻鎷穃` / `涓枃` 型）**：本来合法的 UTF-8 文本（例如输出里包含 `�` 字符）被**整套按 GBK 重新解码**，正常文字被替换、标点被吞。**这是可修的 bug。**
3. 影响面（全库 423 个会话）：**108 个会话**的工具类事件出现过 `�`；**44 个**出现过 GBK 误码族字符（锟/閿/鎷/涓/鏂/娴…）。

## 机制（伪码，删节自 app/agent_tools.py:1239-1258）

```python
if platform.system() != "Windows":
    return data.decode("utf-8", errors="replace")
try:
    s = data.decode("utf-8")
    if "\ufffd" not in s:
        return s                     # ① 正常 UTF-8 → 直接返回
except UnicodeDecodeError:
    pass
try:
    return data.decode("gbk")        # ② 整套按 GBK 再解（全有全无）
except UnicodeDecodeError:
    pass
return data.decode("utf-8", errors="replace")   # ③ 兜底：解不出的字节换 �
```

问题点：

- **P1 误判触发**：① 把"输出里本来就带 U+FFFD 字符"当作"UTF-8 解码失败"→ 进入 ②。GBK 有效字节空间很大，整段"碰巧"可解并不罕见；一旦成功，**合法 UTF-8 被整段重排**——这就是 `�→锟絓`、`锟斤拷→閿熸枻鎷穃`、反斜杠被吞的来源。
- **P2 全有全无**：② 对整个缓冲区一次性判断。混合编码（UTF-8+GBK）或命中 GBK"码位空洞"时 ② 失败 → ③ → **真实 GBK 中文段整段变 `�`**。
- **P3 流式切片**：流式路径对"自上次快照以来的新增字节切片"逐段调用同一函数（`app/execution_services/shell.py:69-70`）；切片可能劈开多字节字符，"实时输出"与最终结果可能各自抽签。
- **P4 Windows 土壤**：PowerShell（GBK 控制台）+ 子进程 Python（被强制 UTF-8：`RUN_SHELL_FORCE_UTF8`，`app/agent_tools.py:1219-1232`）+ git/cmd 等原生工具（GBK/原样字节）→ 一条流里混着多种编码。

（对照：老路径 `app/agent_tools.py:2388-2407` 的流式用增量 UTF-8 解码器，做法是对的；DSH 路径流式采用启发式按片解码——本会话已证实 DSH 生效：`probe3b_v2` 的 `锟絓` 直接出现在流式 `output_delta` 里。）

## 建议（按优先级）

1. 修 `_decode_cli_subprocess_bytes`：删除 `"\ufffd" not in s` 触发条件（只依据严格解码异常）；GBK 回退仅当 UTF-8 严格失败时执行；对 GBK 结果加质量校验（如 charset-normalizer 打分/乱码率对比），避免整段误转。
2. 统一输入编码：PowerShell 包装层设 `[Console]::OutputEncoding=[Text.Encoding]::UTF8`、`$OutputEncoding`、必要时 `chcp 65001`；或按流记录编码元数据。
3. 流式改增量解码（如老路径的 `codecs.getincrementaldecoder`），或先存原始字节、在安全边界（行边界）再解码。
4. 可选：UI 对"含无法解码字节"的输出段给提示，而不是静默替换。
