# 桌面端系统打开与窗口激活

页面中的系统打开（文件、文件所在目录、工作目录）由 Electron 主进程统一执行。
前端保留当前会话或草稿工作目录上下文，经 preload IPC 传给主进程；主进程仅接受
当前本地应用顶层页面的请求，并通过当前后端端口的 `open-workspace-dir?probe=1`
复用路径校验。校验失败时不调用系统打开，不回退为后台 Python 打开。

打开目录或默认应用使用 `shell.openPath`，等待其返回并显示错误。定位文件使用
`shell.showItemInFolder`，不拼接 Explorer 命令。浏览器版继续使用后端打开入口。
主进程持有唯一的系统打开入口；后端在 probe 模式只解析路径并返回类型，不唤起应用。

Windows 通知保留协议激活，支持托盘、通知中心及应用退出后的冷启动和会话定位。
原生启动器挂起创建 Electron 子进程，调用 `AllowSetForegroundWindow(child.pid)`
后才恢复执行。Electron 单实例机制继续向已有主进程转交前台权限。主窗口按
恢复最小化、显示隐藏窗口、聚焦的顺序执行，并记录未获得焦点的情况。
前台授权只针对该子进程，不修改系统焦点策略，不模拟键盘，不永久置顶窗口。

验收包括：自定义工作区、文件定位、中文及带空格路径、系统打开失败、后端拒绝路径、
非法 IPC 来源、浏览器兼容、通知会话跳转及启动器静默转交。自动测试中的调用成功
不等于 Windows 前置成功；实际通知点击与 Explorer 前台焦点需要交互式验证。

前端改动须重新构建 `app/templates/dist`。桌面主进程、preload 与原生启动器的改动
需要重新打包并覆盖安装；只更新 Python 后端不能更新已安装的桌面外壳。
