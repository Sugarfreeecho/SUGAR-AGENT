## 已复现问题

1. A、B 快速切换时，A 的服务端预检晚返回，仍会恢复 A 的 DOM，而当前会话已经是 B。
2. 运行中会话切到缓存会话后，旧滚动控制器继续写共享 chatContainer，覆盖保存的位置。
3. 流式逐帧累积使用裁剪后的文本，`A\nB` 可以显示为 `AB`。
4. 内外两个滚动容器引用同一个执行过程时，每帧分别扫描全部行、读取相同高度。
5. 每帧设置 textContent 会替换文本节点，触发额外 childList 变化。

这些数字是可重复的 DOM 操作数量与正确性结果，不是实际浏览器耗时、FPS 或端到端加速比例。
本次修改前没有采集真实浏览器帧时间基线；后续真实会话只能报告实测性能，不能据此虚构前后加速比例。

## 优化后记录

- 会话切换开始即使旧消息请求失效，清理历史回放标记，并重置共享聊天容器与旧执行过程的滚动控制器；异步预检返回后重新校验会话和切换代次。
- reasoning / response 保留完整原始累计文本，展示时才裁剪；普通追加复用 Text 节点。重连快照同步替换原始文本，最终持久化内容在旧缓冲排空之后覆盖，避免旧增量污染正式结果。
- 内外容器共享同一个执行过程时，每个动画帧只读取一次该过程的行高度。
- 执行过程封存时释放内部跟随器；手动解除主区域跟随时也停止另一个嵌套容器；后台会话的 final 不再取消前台聊天容器的动画。
- 动画控制器无活动容器时立即取消待执行 RAF，切换时清理旧手势、回调与布局引用。
- 新增有容量上限的浏览器本地性能记录，不上传消息内容或诊断数据；每 5 秒合并保存一次，在隐藏页面时保存。保留最多 4 次页面记录，每次最多 12 个会话。

## 后续真实会话采集

1. 更新构建后刷新 Agent 网页；保持同一浏览器、窗口尺寸和缩放。
2. 依次执行：冷开一个较长会话、切到另一个会话再切回缓存、运行中切换并返回、输出多行文本并调用工具、手动向上滚动后回到底部。带图片会话单独比较。
3. 正常操作会自动采集，无需打开开发者工具或额外启用。结束后可在该 Agent 网页控制台运行 `window.__MYAGENT_UI_PERF__.download()` 下载 JSON；`snapshot()` 查看，`reset()` 清空。
4. 记录保存于该网页来源的 localStorage 键 `myagent-ui-performance-v1`。浏览器隔离窗口、不同端口或地址不会共享；指标只含会话 ID、耗时和计数，不含对话内容。多窗口同时测试时应分别导出，localStorage 最后一次写入可能覆盖另一窗口保存的报告。
5. 后续分析将区分：`switch.cached/live/loaded`、`history.fetch/hydrate/images/scroll/total/backend`、`stream.flush/frameGap`、`follow.work/frameGap/traceScans`、`layout.overflowBatch` 和 `text.nodeAppends/nodeReplacements`。

`frameGap` 是已有 RAF 回调的可见页面间隔，并非屏幕实际 FPS；`p95UpperMs` 是分桶的 P95 上界；`history.total` 包含滚动等待。各指标含义不同，不应直接混为响应延迟。
若要报告真实会话“加速百分比”，仍需在隔离的基准版本中用相同会话数据、窗口与采集方法做对照，不能用模型生成速度不同的两次运行直接比较。
