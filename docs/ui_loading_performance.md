# 设置与会话加载优化

日期：2026-10-21。

## 多会话生成后加载失效的排查与修复

用户随后报告所有会话无法加载。本次在实际运行实例复现了整页等待 35～60 秒仍没有完整侧栏，以及独立 `/sessions/state` 请求 8～20 秒超时；主脚本、HTML 和普通状态请求也会同时延迟。单次接口恢复到几十毫秒不能作为页面已恢复的证据。

真实浏览器及后端采样发现并处理了以下路径：

- HTTP/1 的同源连接池会被后台会话 SSE 占满。保留最多 3 个会话读取器，优先保留当前会话；释放后台连接只断开观察者，不调用中断接口，不停止服务端生成。返回被释放的会话时重新加载持久历史，保留后台运行标识与追问完成对账。
- 插件会话 UI 只允许一个投影请求在途，合并期间的新会话 ID，最多追加一次合并请求；事件调度约 200 ms 限流，隐藏页面积累变化、恢复可见后补查。数据及宿主未变化时保留徽标/面板 DOM 和焦点，外部重建宿主仍会恢复内容。
- 插件会话 UI 的会话成员校验直接读取内存根索引，不再为了存在性检查对每个会话构建活动时间和历史预览；兼容校验也移入工作线程，避免阻塞事件循环。
- SSE 批量回放共享约 12 ms 的执行片段，多个会话及快速处理分支同样会让出主线程，保持事件顺序。
- 图片附件的原图接近可见区域时才下载，最多并发 2 张。保留尺寸占位、共享下载、取消与 Blob URL 释放；隐藏历史中的图和折叠工具输出不会在加载时一齐抢占连接。
- 页面恢复上次会话与侧栏请求并行；已就绪的正文可以先显示。隐藏历史树重放期间跳过溢出/高度测量，显示后统一布局；国际化处理在整个内容子树都不应翻译时直接跳过。
- 长会话首屏显式使用最多 200 条最近事件的窗口，向前翻页继续使用有界窗口。仅用户主动翻阅后才自动加载更早内容，避免首屏较短时立即补回整段历史；目录定位与显式整轮 API 保留原有语义。未提交且仍属于当前运行的执行记录即使开始于窗口之前也会恢复。
- 会话摘要的“能否继续”改为读取可见历史索引的轮次边界，不再重放全日志并加载所有工具/图片正文；正在运行的会话不再进行这项无意义的继续检查。历史不可读时继续保持队列启动失败关闭。
- 启动权限健康检查可能等待本机助手进程，权限读取与页面配置检查移到工作线程，避免同步占用 ASGI 事件循环。
- GIL 采样确认后台恢复/子会话扫描重复深拷贝完整快照，包括不断增长的消息和执行数组。Web UI 状态读取改用一致性只读快照，再仅深拷贝所需的状态、上下文、扩展和子会话字段；保留独立副本、更新时间及恢复逻辑，不改变事实日志。

其中一次长会话真实打开为 33.3 秒，17.5 秒在历史获取、13.2 秒在历史重放；另一次后端历史读取达 156.8 秒。后续中间方案仍测到 38 秒及 45～60 秒失败，因此没有将连接限制和图片优化的通过误报为端到端恢复。前端 CPU 采样还捕获了历史加载中的重复高度限制和折叠内容测量；后端限 GIL 采样捕获了恢复扫描的完整快照复制。

本地独立 Edge/HTTP 实验（没有启动实际 Agent 生成任务）：3 条 SSE 时探测请求约 26 ms；6 条 SSE 时超过 500 ms 仍被阻塞，取消其中 3 条后约 627 ms 完成。使用实际连接预算代码依次观察 9 个会话，保留 3 条读取器，探测请求约 16 ms。该数据验证连接池机制，不代表真实应用总加载时间。记录：`.analysis/stream-connections.json`。

验证覆盖 100 次扩展事件只产生 2 次合并请求且峰值在途 1；12 个会话保留最多 3 个读取器，不取消未接收的提交；400 个并发流事件保持顺序；屏幕外附件不发请求、原图最多并发 2；隐藏历史重复 200 次不读取布局，显示后恢复测量；继续检查不复制历史正文，元数据仍隔离修改。相关后端与队列/消息回归集 80 项通过；增加有界首屏后历史/消息/投影回归集 109 项通过，附件运行时 9 项通过；此前过程框/性能回归 11 项及新增布局/继续检查 5 项通过，集合有重叠。构建、JavaScript 运行时和产物同步检查通过。

本轮已根据用户明确允许中断任务的回复重启后端。重启后的冷状态及自动恢复阶段仍有长等待；最后普通会话实测首次正文可见约 12.4 秒（完整侧栏当时尚未恢复，不能算完整页面成功），随后刷新显示 93 个侧栏会话，正文与输入框可用约 6.6 秒。记录：`.analysis/recovery-verified-small/results.json`。机器负载变化和重启会影响结果，不以这两次观测计算统一加速倍数，也不保证任意长会话都已达到该耗时。

有界历史生效后的长会话真实测试：首屏确认为 200 条事件，重放分别为 426 / 205 ms，连续刷新一次的完整页面可用约 8.1 秒、93 个侧栏会话。重启后首次进入仍达 55 秒，其中客户端历史获取达 49.7 秒、实际返回的后端构建为 8.0 秒，期间存在首屏预取超时及普通请求排队；该首次结果仍是明显瓶颈，不归类为流畅加载。记录：`.analysis/bounded-heavy-final/results.json`。随后还移除了插件成员校验同步构建大量摘要的路径；该项相关回归 47 项通过。

测量脚本现在以侧栏成功应用完整快照的标记判断就绪，而不是仅检测到任意一条会话行；同时记录请求发出前排队和等待响应头的时间，避免临时恢复的单条会话或 HTML 返回被误算为成功。

最后一次重启后，仍在并行生成的测试又出现两次 60 秒内侧栏未就绪（`.analysis/session-recovery-final/results.json`），因此本轮不能宣称并行高负载问题已彻底解决。重启的自动恢复会重新续跑旧任务；随后按用户明确授权，通过 `/sessions/{id}/interrupt` 正常停止原来的 3 个任务，使用手动停止原因防止再次自动续跑，均返回成功。运行数核实为 0 后，独立接口 `/sessions/state` 返回 93 条会话约 553 ms、HTML 128 ms、主脚本 351 ms。

| 场景 | 完整侧栏出现 | 正文与输入框可用 | 会话数 |
| --- | ---: | ---: | ---: |
| 新浏览器上下文打开长会话 | 1,836 ms | 8,049 ms | 93 |
| 同页刷新 | 1,015 ms | 5,842 ms | 93 |

两次没有页面脚本异常，200 条事件重放约 451 / 313 ms。记录：`.analysis/recovered-final/results.json`。这确认了当前实例已恢复会话加载；该最终数据是在停止生成后取得，不能当作多个会话同时生成时的性能保证。后续仍需处理后台扫描、长历史冷索引及其他运行负载的竞争。

## 高负载下的窗口反馈与按需预加载

后续反馈指出：接口缓存命中后，窗口开关在高负载下仍然卡顿。本轮把“交互后第一帧”和“数据全部就绪”分开处理与测量。

- 共享 `MyAgentUiTasks` 与目录缓存一起加载，不新增后端接口。鼠标停留或键盘聚焦约 140 ms 后，只预热目标入口；移开取消尚未开始的任务。后台预热串行执行，页面隐藏、有待处理输入或空闲预算小于 8 ms 时延后，不在启动时扫描所有菜单。
- 设置可提前加载隐藏 iframe；打开时先显示窗口与准备状态，再挂载或校验内容。已加载的常规、模型、技能、Hooks、插件分区保留 DOM 并后台校验，数据相同不重建。后台失败保留上次内容并提示；编辑、搜索、打开对话框后，迟到响应不覆盖当前操作。显式保存表单、权限、MCP 和插件自定义分区继续沿用各自的重新加载与清理流程。
- 设置 iframe 的就绪标记包含会话/工作区 URL，避免在新上下文中显示旧页面。快速打开再关闭会取消未执行的挂载。关闭仍通过未保存确认，再即时隐藏，偏好同步和通知在后续任务执行。
- 模型、加号窗口和加号页签先更新开关或选中状态，再构建菜单。页签等待期间旧列表不可点击；重复相同 HTML 不替换 DOM，后台刷新合并到下一次绘制后的任务。
- 通用确认对话框先关闭再交付确认结果，避免确认回调的大量工作拖住关闭反馈。历史回放每约 12 ms 或 64 条事件让出主线程；单条特别昂贵的渲染仍可能超过预算。

验证包括预热去重、取消、空闲预算、待处理输入优先、串行预热；设置重开 DOM 复用、后台失败、编辑保护、关闭确认；快速打开/关闭与页签旧内容不可交互；昂贵历史事件在达到条数上限前按耗时让出线程。相关完整回归集 147 项通过，最后一轮设置浏览器回归 68 项、功能与设置契约回归 80 项通过，JavaScript 运行时、构建与产物同步检查通过。集合有重叠，不累计为独立测试总数。

隔离的真实 Edge 浏览器测试额外施加 4 倍 CPU 降速，并在加载/关闭后续处理中人为加入 80 ms 同步工作，确认窗口反馈先于重工作执行。该用例的打开/关闭下一帧分别为 7.5 / 7.9 ms；这是隔离用例，不代表繁忙运行实例的总时长。

运行实例的最终测试在首屏就绪后才对页面施加 4 倍 CPU 降速；本轮有 90 个侧栏会话。测得已加载的模型菜单、MCP 页签、Plugins 页签点击到下一帧分别约 70、85、73 ms，Skill 为 232 ms，设置重开约 100～129 ms。菜单/分区数据就绪仍约 0.5～8.6 秒，不能用第一帧数字代替完整加载。关闭的真实点击帧探针未采集到结果（记录为 null），不以自动化点击总耗时冒充关闭渲染耗时。

本轮也复现了剩余瓶颈：对整页启动施加 4 倍 CPU 降速时，一次测试在 90 秒内未得到可用页面，主脚本请求约 60 秒、状态接口超时；繁忙实例中 Skill 和插件会话投影请求出现过约 10～33 秒等待。最终交互复测的首屏在未施加人工 CPU 降速前也用了 9.8 秒。该结果说明机器及服务端负载仍影响资源和接口完成时间，以上前端改动不能宣称已消除所有高负载卡顿。没有为这些改动中断后端正在运行的任务。

复测命令与数据：

```powershell
.\python\python.exe -X utf8 scripts/measure_ui_refresh.py --rounds 1 --panels --cpu-rate 4 --cpu-after-ready --session <会话ID> --timeout 90 --output .analysis/ui-interaction-final
```

去掉 `--cpu-after-ready` 会从整页导航开始施加降速。实际数据为 `.analysis/ui-interaction-final/results.json`；隔离反馈测试数据为 `.analysis/ui-feedback-load.xml`，最后的设置浏览器回归为 `.analysis/ui-window-browser-tests.xml`。交互探针 `clickNextFrameMs` 是点击处理到下一次 RAF 回调的近似值，并非显示器呈现时间；`ms` 包含自动化点击、等待数据与渲染帧的完整观测时间。不同测试期间机器负载变化较大，不据此计算统一加速倍数。

## 真实页面复测与纠正

上一轮的 4.2 ms 是扩展目录缓存读取微基准，不能代表页面加载或刷新时长。用户反馈后，对运行实例 `127.0.0.1:8192` 使用真实 Chromium 页面重新测量：

| 场景 | 实测结果 |
| --- | --- |
| 首次进入 | DOMContentLoaded 约 2.4 秒；约 49 秒后会话列表仍为空，状态和回退列表请求分别在 12 秒超时 |
| 随后刷新 | HTML 首字节约 13.7 秒；约 59 秒后列表仍为空；模型和扩展请求也出现 30 秒超时 |
| 后端日志 | 一次 `/sessions/state` 构建 249,110 ms，其中 pending counts 为 248,957 ms |
| 历史首屏日志 | 一次历史请求共 172,557 ms，其中排队达 166,232 ms |

使用 `py-spy dump` 对运行实例采样，8 个 `pending-counts` 线程均在 `_resolve_session_path` → `_scan_nested_subagent_path` → `Path.rglob`。目录中有 334 条子会话索引，部分旧根会话目录缺少 metadata，触发反复递归扫描整个目录，包括修复备份和历史产物。另有插件静态资源逐个执行 `load_plugins(force=True)`，引发额外串行扫描。

本轮修复：

- 旧会话路径发现只沿 UUID 会话目录及其 `subagents` 层级查找，先排除备份与产物目录；保持对后来创建的子会话和目录边界的检查。
- 侧栏只统计当前可见会话及其后代，排除已归档树和无关子会话；本机计数范围从 419 条收缩到 167 条。
- 会话状态请求在进入 executor 之前合并，避免每个等待构建锁的浏览器请求独占线程；取消一个客户端不取消其他客户端共享的构建。
- 插件页面和 JS/CSS 请求复用目录缓存，同时重新检查启用状态。执行接口继续使用新目录检查。
- 首次打开和刷新直接定位到最新消息，省去长历史约 2.1 秒的滚动动画等待；交互切换仍保留既有行为。
- 加号按钮仅在 Skill 选中数量变化时替换图标。实测发现原来的缓存命中会反复替换鼠标下的 SVG，再触发 pointerenter 预热，形成每秒数十次菜单重绘，使页签无法稳定点击；修复后没有持续替换。

在同一份真实数据上，修复后的 167 条会话路径解析和计数文件读取独立实测 892.3 ms。随后等待运行任务自然结束、确认 active_run_count=0，通过托盘所属进程完成后端重启，下面是重启和最新前端构建生效后的真实页面数据。

## 分析与改动

| 场景 | 原有开销 | 实现 |
| --- | --- | --- |
| 打开 Agent 设置 | 首次先 GET `/settings` 探活，再由 iframe 请求同一页面；关闭销毁 iframe | 直接打开并保留 iframe；同一会话/工作区重开复用实例，重新加载当前分区数据；上下文变更时重建 |
| 设置与聊天目录 | 模型、Skill、插件目录各自维护请求，跨 iframe 无法复用 | 共用 `resource_cache.js`，同源 iframe 复用父窗口实例，并发 GET 合并；返回独立副本，表单修改不会污染缓存 |
| 模型菜单 | 每次打开强制刷新模型配置；配置与会话绑定串行读取 | 普通打开使用 30 秒缓存，列表与会话绑定并行；会话绑定仍实时读取，保留模型改绑及流结束时的权威刷新 |
| 输入框加号 | 每次打开同时请求 Skill、MCP、扩展三个目录，重复渲染隐藏菜单 | 当前页签按需加载；指针进入/键盘聚焦时预热当前页签；Hooks、Plugins 共用扩展快照；隐藏菜单不做刷新渲染 |
| 扩展后端 | 每次快照重新扫描插件并重建 Hook 管理视图；冷加载存在重复发现 | 复用已加载插件的发现报告；新增展示元数据缓存，合并同代构建；10 秒过期后先返回已有展示数据，再单次后台刷新 |
| Hooks/MCP 设置 | 独立 API 串行等待 | Hooks 的扩展/环境请求，以及 MCP 的工具/搜索配置/配置文件请求并行 |
| MCP 工具列表 | 展示请求等待 `ensure_started()`，受最慢服务器连接影响 | 使用既有后台发现调度，立即返回已知工具/服务器及 `initializing`；发现中约 1.1 秒更新一次，结束后停止；设置页只更新工具列表，保留配置草稿 |
| 会话切换 | 恢复缓存或加载历史前，近期会话最多等待 450 ms 状态预检；加载后再次请求摘要 | 状态校验与内容恢复并行；完整缓存立即恢复；摘要并发请求按会话合并；后台发现新运行时再挂接 SSE，仍等待历史恢复完成 |
| 首次打开会话 | 等待侧栏列表、待处理交互，再请求首屏历史 | 提前预取上次会话的首屏历史，与侧栏并行；选中后消费同一个响应；待处理交互与历史并行恢复 |

## 缓存一致性

- 前端仅缓存五类目录：模型、Skill、扩展、MCP 工具、工具搜索配置。环境变量、插件设置表单和审批状态不放入该目录缓存。
- 成功的设置写入、包导入和聊天菜单启停会使对应目录失效。普通重开复用缓存，显式刷新重新取数。
- 缓存只存在内存中；跨窗口只通过 localStorage 发送无业务内容的失效通知。
- 已失效的进行中响应不会重新成为有效缓存；等待旧请求的消费者改为取得当前代结果。失败不缓存，请求含 30 秒超时并允许重试。
- 后端扩展展示缓存的键包含实例、扩展代次、总开关、插件状态文件及 Hook 配置文件状态。启停、安装和配置写入沿用已有扩展失效机制；新代不复用旧代展示数据。
- 后端缓存用于管理页面展示，不参与工具执行、注册授权或权限裁决。
- 快速切换会话仍使用原有 epoch 与取消机制。未读完成结果、显式重载不使用推测性首屏预取；选中其他会话或取消加载会取消对应预取。
