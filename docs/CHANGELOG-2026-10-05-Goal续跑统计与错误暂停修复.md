# Goal 续跑统计与错误暂停修复

日期：2026-10-05

## 问题与修复

1. 自动续跑查找用户轮次时，仅查询事件日志末尾 2 MiB、最多 4000 条事件。长时间运行后，原始用户消息可能离开该窗口，续跑会回退到新的运行 ID，导致改动审查累计基线与轮次归属断开。现在保留末尾查询的快速路径，在未找到普通用户输入时，通过事件序号索引分批向前查找；追问仍不切换用户轮次。
2. Goal 的运行失败原先执行指数退避，默认连续三次失败才暂停。现在 `failed` / `error` 首次发生即暂停，保存错误并清空重试时间，等待用户恢复。运行中断仍采用原有退避及连续中断阈值；正常到达 ReAct 迭代上限仍允许续跑。
3. ReAct 对部分终止错误生成错误卡片和 final，但原先正常返回状态，导致生命周期误记为完成。现在 API 错误、上下文恢复失败、输出长度续接耗尽、无效工具调用重试耗尽保留终止错误标记，统一结算为 `run_failed`。不会继续消费排队输入或触发 Stop Hook 追加工作；错误卡片和 final 保留供用户查看。可恢复的 API 重试和单次工具失败不使用该终止标记。
4. 调度器回收有明确失败状态的旧续跑时，按失败结算并暂停，而非按普通中断重试。失败优先于残留的 ReAct 上限标记。

## 验证

- 改动前回归测试复现：首次失败仍为 active，以及用户消息超出事件数/字节窗口后改动审查使用新的运行 ID。
- 实际执行三轮 `apply_patch`，分别覆盖超过 4000 条事件和超过 2 MiB 的日志，验证快照 ID、用户轮次、累计增删行数和原始 diff 保持一致。
- 覆盖首次失败暂停、重复结算幂等、暂停状态持久化及手动恢复；后台异常、无事件续跑、重启后的失败运行回收；普通聊天和自动续跑的错误 final、失败生命周期及排队输入保留。
- 同时运行 Goal、调度器、改动审查、流式生命周期、排队续跑、错误原因链、上下文恢复、ReAct 恢复和 Runtime V2 相关测试：250 项通过；相关文件的 `git diff --check` 通过。

后端改动需重启 MyAgent 后生效。既有被拆分的审查快照保留，本次不重写历史快照。
