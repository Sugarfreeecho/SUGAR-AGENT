# 设置中心 · 定时任务

入口为聊天页齿轮 → **定时任务**，或本机 `/settings#schedules`。连接已有会话控制后端，与 `app/agent-session-control.py schedule` 使用相同任务、权限、持久入箱和执行记录。

支持新建、编辑、暂停/启用、立即运行、删除及执行历史。历史可打开具体会话、查看结果和错误、取消排队或运行中的执行。手动运行不推进计划，也不计入计划运行次数。

## 模型工具

模型可直接调用两个内置宿主工具，无需运行 CLI 或读取个人令牌：

| 工具 | 操作 |
| --- | --- |
| `scheduled_tasks` | `list`、`get`、`history`：查询本会话/调用身份创建的任务及执行记录 |
| `manage_scheduled_task` | `create`、`update`、`pause`、`resume`、`run`、`delete` |

例如告诉模型「每天北京时间 9 点整理项目进展，有异常再通知我」，它可提交：

```json
{
  "action": "create",
  "name": "每日项目进展",
  "instructions": "整理项目进展，报告异常和需要我处理的事项。",
  "trigger": {"kind": "daily", "time": "09:00", "time_zone": "Asia/Shanghai"},
  "notification": "important"
}
```

任务直接保存在设置页与 CLI 共用的控制库中。默认目标为当前聊天；`new_chat: true` 在当前工作目录每次创建独立聊天。工具也支持一次性绝对时间、带时区的 `local_at`、延迟、间隔、工作日、每周、每月和 Cron，以及任务模型、System Prompt、工具及预算的 `runtime_override`。返回真实任务 ID、revision、下次执行时间及其时区偏移。创建回执表示保存成功，手动 run 回执表示已接收执行。

修改、暂停、恢复、删除前通过 `scheduled_tasks` 获取 `revision`，以 `expected_revision` 提交；同一次工具调用按宿主调用 ID 去重，跨轮次重试可复用显式 `idempotency_key`。工具只接受时间触发，不接受模型提供的身份、权限或 Webhook 来源。

真人本地聊天拥有当前工作目录内的任务入口；已有宿主签发的受限身份继续受原能力、范围、凭据有效期及来源撤销约束，不自动获得自动化写入权。任务执行保存创建身份的工具/参数约束、只读与预算上限；手动执行还叠加当前调用的上限。只读会话只保留查询工具。定时执行默认没有继续创建定时任务的能力。人工编辑已有任务保留其所有者与创建来源限制，不把它转换成设置页管理员任务。

设置页打开且可见时每 5 秒检查任务列表变化，窗口重新获得焦点时也检查；正在编辑或查看执行记录时不覆盖弹窗。模型可用 `show_user` 的 `kind: "settings", section: "schedules"` 打开此页签。

可配置：

- 名称、任务说明；每天、工作日、每周选日、每月选日、指定时间一次、延迟一次、固定间隔、五字段 Cron。
- 时间和 IANA 时区，默认 Asia/Shanghai。一次性任务由后端按所选时区解析；夏令时缺失时间拒绝，重复时间取较早一次。
- 在此电脑上运行：关闭即暂停未来触发；取消已接收执行需在历史中操作。
- 每次创建新聊天，或指定已有会话；新聊天可配置工作目录。
- 模型档案、推理强度、临时追加/替换 System Prompt。
- 继承或自选工具，空列表禁用全部工具；参数 bindings JSON、只读、运行超时、工具调用预算。会话和宿主授权仍然生效。
- 漏跑补最新一次/跳过、最大计划次数、截止时间。
- 发送任务、写入通知、继续未完成会话或停止会话。继续/停止要求已有会话。

通知使用已启用的宿主通知渠道。**重要更新**在失败、中断、结果不明、派发失败或等待人工确认时提醒；**每次结束**另外通知成功；**关闭**不投递该任务通知。提示只带任务名称与状态，点击可定位会话。通知 outbox 持久保存，等待通知提供者就绪后消费；投递前先认领，进程在外部投递期间崩溃时保留 sending，不盲目重发。通知发送不等于任务执行完成；具体执行以 operation 为准。旧 CLI 任务未设置 notification 时默认关闭该通道。

本机页面通过 `POST /api/settings/session-control` 转接白名单 RPC，不把管理员令牌保存到浏览器。此适配器要求直接 loopback 连接、匹配 Host/Origin、原生设置头，拒绝代理和跨来源写入。远程客户端继续使用鉴权控制 RPC。请求共用全局开关、幂等键、配置校验、配置版本与审计；任务执行计时与调度仍由后端拥有。

编辑冲突会保留表单并显示错误，关闭未保存表单需确认。任务配置静态资源位于 `app/templates/static/settings/sections_schedules.js`，独立于主聊天页的 Vite 构建。宿主 Python 改动需要重启后端加载；刷新设置页后生效。

验证使用隔离存储、真实控制服务与 Runtime 持久事实、可控模型及通知提供者，以及生产设置资源的真实浏览器交互。未操作实际账号或创建真实生产任务。
