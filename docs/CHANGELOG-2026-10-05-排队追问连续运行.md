# 排队追问连续运行

普通排队消息在输入时持久化到服务端，当前回答完整保存后，同一个 run 按队列顺序继续处理下一条；队列清空后才结束运行。每条消息仍有独立用户轮次、最终回答和变更审查基线。

- 排队消息只在回答完成边界领取，不在模型或工具执行中途插入。
- 排序同步到服务端，撤回与领取互斥；重复提交、网络延迟和刷新不会重新创建已处理操作。
- 保留所选 Skill 和附件；刷新后可以从服务端恢复队列。
- 后端、历史投影和前端在下一条消息开始时恢复生成阶段，原 run 和连接保持不变。
- 手动停止、暂停和执行上限不继续领取后续消息；中途停止未开始的消息会释放领取状态。
- 消息赶上 run 已结束时，仍可由普通聊天入口启动下一轮，但沿用原队列操作进行去重。

验证包含同一 run 连续三次回答、恢复续接、排序与撤回、重复领取、停止和暂停边界、Skill/附件持久化，以及前端排队注册和运行阶段恢复。更新后需重启后端并刷新页面。
