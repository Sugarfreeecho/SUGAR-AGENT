# 会话目录授权与 Windows 隔离助手：审查和修复

日期：2026-10-22。审查对象为会话 `92a46998-5b7f-4377-82c4-3fbc7abec726`（“请求批准下自动授权目录”），读取其持久化用户消息和五次最终分析，并与当前源代码逐项对照。

核心判断成立：在助手已启用、健康且使用非完全访问模式时，无网络意图的 Shell 会进入 AppContainer。应用层的会话目录授权不会自动变成 Windows 文件权限。原来只有手动运行构建脚本的 `-InstallAcl -WorkDir` 才补权限；默认启动、新会话和切换目录没有接通。因此，同一目录可以被文件工具访问，却被隔离 Shell 拒绝。

报告中“仓库没有任何 ACL 授权代码”的说法不准确，构建脚本已有此功能。仅根据某一台机器的目录 ACL，也无法推断另一台机器的安装状态。完全访问模式确实绕过助手，但不能证明隔离模式已修复。

## 已实现的修复

- `security/egress_guard.py` 把生效工作根、会话已授权目录、当前工具的一次性目录授权和当前运行已分配的 scratch 目录放进签名票据。Shell 的任意 cwd 或任意 `TEMP` 值不会扩大授权。解释器和非系统 Shell 的运行目录使用只读执行权限。
- Windows helper 在验证票据后按需补目录 ACL，保留其他 ACE、所有者和完整性标签；已有等效权限时复用。目录不可授权时返回具体路径和原因，执行失败不会自动换成未隔离进程。没有增加网络能力。
- Windows 会重写 AppContainer 子进程的 `TEMP`/`TMP`。助手通过签名票据携带 scratch，PowerShell 启动后恢复临时变量，子进程也使用运行专属临时目录。
- Windows PowerShell 5 会因无法规范化祖先目录而退回 `C:\`。启动脚本显式设置工作位置；必要时使用以授权工作目录为根的 `SugarAgentWork:` 文件系统驱动器，避免修改磁盘根、`C:\Users` 等系统目录权限。进程 cwd 仍是真实目录。定位失败会停止命令。
- “本次允许目录”现在仅存活于当前工具调用，包含目录审批和后续操作审批；结束、异常或取消后失效。它不写入会话 metadata，不影响并行工具，复制到后台任务的上下文也会失效。删除、联网等操作继续按策略审批。卡片中“删除自动放行”的错误文案已修正。
- `RUN.bat` 和 Windows 桌面载荷准备过程使用 `-IfNeeded` 检查助手的版本能力和源文件时间，按需重建。更新运行时遇到旧助手会明确提示重建。新助手仍接受旧运行时票据，保留原有执行行为。
- 网络自检要求隔离子进程确实启动并报告 socket 被阻止，避免把“程序根本没启动”误报为网络隔离成功。

## 生效和边界

**重启 SugarAgent 后，常驻后端才会加载本次 Python 修改。** 本次没有重启正在运行的后端。开发启动和后续 Windows 打包会自动更新助手，不需要为普通用户自有工作目录手动运行广泛的 `-InstallAcl`。

本方案沿用原有共享 AppContainer SID，补入的系统 ACL 是持久的。切换工作目录或结束一次性应用授权不会撤销已经补入的系统 ACE；每次工具调用仍由应用策略检查。这是网络助手的文件访问兼容机制，**不提供会话级 OS 文件系统隔离**。需要撤回持久的 OS 访问权时，应在对应目录移除该 SID 的 ACE。scratch 删除时，其 ACL 随目录一起删除。

历史 metadata 中已经保存的目录授权没有足够信息区分“本次”或“会话”来源，继续按既有授权处理；需要用户按实际意图撤回。此后的一次性目录批准不会再落盘。

Windows 的 AppContainer 权限模型及临时目录重定向说明参见 [Microsoft 官方文档](https://learn.microsoft.com/en-us/windows/win32/secauthz/implementing-an-appcontainer)。票据字段、兼容策略及 ACL 生命周期详见 [egress_helper_protocol.md](egress_helper_protocol.md)。
