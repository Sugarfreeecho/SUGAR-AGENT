**朗读文本清洗：括号不读、路径不再念成"一段代码"（2026-10-24）**

两处"听起来不像人话"的问题一起修：括号里的附注被逐字念出来；一串文件路径被读成"一段代码、一段代码"。

**括号默认不读。** 中文 `（）` 与英文 `()` 的内容（附注、日期、参数、文件名）在合成前剔除，最多递归 4 层，嵌套括号也能处理干净。设置里新增「朗读括号里的内容」，勾选后原样保留。剔除后会留下双空格和中文之间的空隙，统一由 `tidy()` 清掉，否则 TTS 会在中间停一下。

**路径、链接、代码分开计数。** 原来所有超长行内代码都变成"一段代码"，一句话里出现五个路径就读五遍。现在先分类再聚合：

| 内容 | 读法 | 例子 |
|---|---|---|
| URL | 一个链接 / N 个链接 | `https://example.test/a` |
| 带路径的文件 | 一个文件 / N 个文件 | `frontend/src/app/modules/sse-handling.js:301` |
| 单个短文件名（≤24 字符、无路径） | 照读 | `chat.js`、`message-rendering.js` |
| 其它长标识符 | 一段代码 / N 处代码 | 长哈希、`oc_sk_…` |

同类之间允许「、，、；和与」分隔，三类互不合并。实测一句里三个路径 + 一个链接 + 一个长哈希，读作「3 个文件，另外参考一个链接，以及一段代码」。

**顺带。** `v1.4.0` 这类版本号不会被误判成文件（正则要求点后是字母开头的后缀）。
