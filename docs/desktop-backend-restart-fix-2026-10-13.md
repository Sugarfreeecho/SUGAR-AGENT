# 桌面版“重启内置服务”报错修复

日期：2026-10-13。

关联会话：`05bb3539-cea1-4eff-ad58-015496a7a6bd`，标题“托盘重启内置服务功能”。读取了本地服务的会话元数据、全部用户消息和最终回答，以及原审查报告和复现脚本。

## 问题与核验

“重启内置服务”重启的是内置 Python Agent 后端。Electron 窗口和托盘继续运行，沿用已选择的端口；后端就绪后重新加载界面。

原会话已经研究并复现异常，但没有应用补丁。本次修改前重新运行其 `repro_restart_dialog.cjs`，9 项缺陷断言均成立；原有 20 项桌面外壳测试也全部通过，说明原测试未覆盖真正的后端重启路径。

根因是 `stopBackend()` 主动终止进程没有登记预期退出，旧进程的 `exit` 回调随后仍走崩溃恢复分支。同时该回调直接修改全局 `backend`、全局日志流和状态文件，事件迟到时可能清空新后端引用、写入新后端日志或覆盖其就绪状态。

原报告的“每次点击必然报错”来自可重复的 Windows 事件模拟，不能据此确认用户已安装实例的所有现场错误；本次没有取得该实例点击时的日志。不过代码缺陷和对应事件顺序均已独立复核。

## 修改

- `packaging/electron/main.js`：用 `WeakSet` 按 child 对象登记主动退出，事件闭包捕获自身 child 与日志流；旧进程只处理自己的状态，无法清空或污染新进程。按对象登记也避免 PID 重用造成误判。
- 日志在 child 的 `close` 事件后结束，确保 stdout/stderr 已排空；同步启动失败也关闭日志，并记录日志流写入错误。
- 托盘、IPC 和崩溃恢复共用重启互斥状态；重启期间禁用重复请求，直到健康检查和页面加载结束。停止失败保留旧进程引用，不启动第二个后端。
- 退出取消待启动定时器；启动及异步等待检查退出状态，防止退出后再次拉起后端。健康检查绑定具体 child，并在 HTTP 回应后重新确认它仍存在。
- 运行中的真实崩溃保留恢复对话框；启动或重启失败由对应流程报告，避免叠加错误框。提前退出、启动异常和真正的 180 秒未就绪分别提示；迟到的旧恢复对话框不能操作已恢复的后端。
- 重启期间通知跳转先排队，就绪后处理；失败时保留仍待处理的通知。页面加载期间后端退出也会报告失败。
- `tests/js/desktop_shell_runtime.cjs`：增加可控 child、日志、定时器和健康检查桩，补充 13 项重启回归测试。
- `packaging/README.md`：补充重启行为及生效方式。

## 验证

- `node --check packaging/electron/main.js`：通过。
- `python/python.exe -m pytest tests/test_desktop_shell.py -k electron_shell_runtime -q`：通过（1 个 Python 入口，其中运行 33 项桌面外壳测试和 5 项通知测试，共 38 项；其余 6 个 Python 用例未选择）。
- 对本次修改执行 `git diff --check`：通过。

覆盖主动重启、旧 `exit/close` 迟到、多个入口连点、重启定时器触发前退出、健康请求途中退出、真实崩溃及恢复、失效的恢复对话框、异步启动失败、同步启动异常、真正的超时、停止失败、通知跳转及界面加载途中退出。

上述验证以真实主进程源码在 VM 沙箱中的受控事件执行为主，没有实际重启运行中的 Agent，也没有把这次测试称为已安装桌面版的点击验收。保留了工作区原有的其他修改。

## 生效

修复位于 Electron 主进程源码，不由刷新网页或重启 Python 服务加载。已安装桌面版需要重新构建安装包并覆盖安装，然后重新启动桌面应用。本次没有构建或安装新版本，原有 1.5.3 安装包不含这次修复。
