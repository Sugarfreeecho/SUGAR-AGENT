# 会话重放与卡顿记录工具

Windows x64 便携版。完整解压后双击 **启动.cmd**（也可用 start.cmd），自动打开本机浏览器。无需安装 Python、Node.js 或 SugarAgent。关闭启动窗口，或点击首页“停止服务”即可退出。

1.0.5 在 1007 对照面板补充 9 项控制，共 **21 项开关**。新增完整前端资源、全部脚本、整套样式，以及会话加载／侧栏刷新、上下文卡片、流式事件／执行渲染、历史滚动、审批／终端交互和媒体展示模块。关闭资源或模块开关会回退到归档中的 1004 实现；完整资源回退使用原 1004 页面、JS、CSS 和审阅插件，同时保留重放适配层。

**比较原来的连续上滑卡顿，请同时保留“自动跟随最新文字”和“平滑跟随动画”。** “对照组合”提供 1007 原版、1004 完整基线、1004 脚本 + 1007 样式、1007 脚本 + 1004 样式、模块回退五种预设，均保留这两项。选择组合后点“应用并重载本段”，再播放。建议先比较原版与完整基线，再交叉脚本／样式，最后逐个模块回退；固定同一轮次、原速、完整历史和窗口大小，多次重复并保存肉眼标记。

整套脚本优先于模块，整模块优先于同范围的细项。例如回退流式模块后，执行分组细项即使勾选，也不会将它重新切成 1007。页面显示实际脚本／样式／页面／插件来源、替换数量及被上级回退覆盖的操作；这些信息与资源校验和一并保存到 JSON，CSV 也注明资源来源。完整基线只覆盖前端资源，仍使用本工具的日志与历史适配层，不复现原后端或 Electron 宿主。

1.0.4 增加了两版共有的 **自动跟随最新文字** 和 **平滑跟随动画**。自动跟随会计算聊天区与执行过程框的底部目标，并在文字换行、插入条目或高度变化时移动滚动条。关闭平滑动画后只在内容更新时直接贴底；关闭自动跟随后停止流式自动滚动、终态贴底与长文本窗口折叠的位置补偿，保留初始历史定位和手动滚动。这两种模式改变了原症状的观察条件；无法判断时应记为“无法判断”，不能据此认定不卡或问题已修复。浏览器仍可能因容器变矮而钳制滚动位置；关闭自动跟随时，平滑动画开关没有作用。

这两项不会关闭 `smoothStream` 总功能，不改变逐字释放、内容渲染或行高动画。面板显示当前滚动模式并校验跟随状态，JSON 另记 `follow_mode` 与 `follow_runtime`（被阻止的调用数、直接贴底次数等）。CSV 记录滚动模式。1.0.3 的“全关”只包含原 10 项，未关闭这两条路径。

1.0.3 增加 **10/07 改动开关**，并修正重放内 change-review 插件地址，使其能被原前端加载规则接受。本机 1.0.5 放在独立的 `SessionReplay-1.0.5` 目录，复制已有会话和记录；旧目录保留。使用新版目录内的启动脚本，首页版本应显示 1.0.5。端口被旧工具占用时会自动选择空闲端口。

在首页选 10/07 → 打开重放 → 展开“1007 对照开关”。**勾选表示启用**，默认全开；取消勾选后点“应用并重载本段”，页面自动重载，保留会话、轮次、速度和测量选项，然后点播放。播放期间开关禁用，先结束并保存再更改。“全部关闭”也会关闭自动跟随和平滑动画，不适合比较原来的连续上滑卡顿；使用“1004 完整基线（保留平滑）”预设。

包含折叠框保留布局、尺寸动画、overflow 写入、执行分组复用、历史补页锚点、审阅实时更新、插件样式等待、侧栏分组与宽度测量、压缩思考、附件卡片预览。开关下方说明实际覆盖范围，并显示当前生效配置、源码适配数量和配置 ID。适配失败会阻止播放，避免以未生效的配置保存对照结果。配置、检查结果、替换操作及实际 JS/CSS/插件 SHA256 保存到 JSON；首页和 CSV 报告也显示配置。

**当前重放未覆盖后端索引、投影锁、检查点和缓存服务；不执行图片上传批处理；直接加载历史，不触发历史分页。** 分页开关虽替换了相应函数，不能用当前重放判断其影响。审阅、压缩和附件开关需要相应事件才会走到这些路径；插件等待影响页面启动；侧栏在重放内只含一条会话。页面按选中片段的历史和事件显示可能涉及这些路径的数量。

1.0.2 修正了本机页面导入被拒绝的问题：支持 `127.0.0.1` 和 `localhost` 两种本机地址；服务重启后，已打开页面会自动更新凭据并重试。升级时先关闭旧启动窗口，再解压新版启动；保留原 `data` 目录即可保留会话和记录。页面底部会显示工具版本。

没有保存文字增量或增量没有有效时间间隔的片段，默认按 120 字/秒模拟逐字输出。重放页可调整“模拟字速”或关闭“缺少增量时逐字模拟”。有完整流式日志的片段仍按日志播放。**模拟部分不是原始 token 到达时序**；JSON 的 `playback` 和 CSV 报告会注明，模拟样本不列入原始节奏对照。日志缺失的信息无法从完整文本恢复。

## 使用

1. 首页选择“会话 ZIP”或“会话文件夹”。目录应包含 `events.jsonl`，有 `metadata.json`、`blobs`、`snapshots` 时一并提供。也可粘贴本机路径，或把目录／ZIP 拖到启动脚本上。包含多个会话的材料会让你选择其中一个。
2. 选择会话、前端版本、任务和播放范围。“执行轮次”包含该 ReAct 轮的文字和工具事件；“流式文本”只播放一段思考／回复；“整次任务”播放该任务全部可显示事件。
3. 点“打开重放”，再点“播放”。默认原速、完整历史，恢复所选范围开始前的历史。播放时面板自动收起，点“展开面板”可调整选项。可暂停／继续、重复播放，或切换轮次和版本。
4. 看到卡顿时点“标记卡顿”，或按 **Alt+M**。可选择停顿、轻微抖动、文字看不清等类型，备注会随记录保存。
5. 播放完成或“结束并保存”会生成独立 JSON。首页汇总所有播放记录；“导出卡顿报告 ZIP”包含 `summary.csv`、`报告.md` 和每次播放的详细 JSON。

记录位于工具目录的 `data/results`，导入副本位于 `data/sessions`。原会话文件只读，不重建原缓存。发给其他人时发送初始发布 ZIP；若要带自己的测试材料，可另附会话 ZIP 和报告 ZIP。**初始发布包不包含个人会话或测试记录**。报告包含会话名称／ID、文本摘要校验和、环境信息、备注与性能时序；不包含完整会话正文，人工备注由使用者填写。

## 对照和记录

内置 2026 年 09/30、10/03、10/04、10/07、10/09 五份备份的前端、样式与 change-review 插件资源。归档文件按原字节保存，校验和见 `versions/manifest.json`。1007 开关关闭时仅生成内存中的诊断变体，原归档文件不变。通过独立启动适配层向前端传入历史和 SSE；只重放，不请求模型、不执行真实工具。

每次保存：浏览器可见时 RAF 帧间隔、平均回调频率、P95／最长间隔、超过阈值次数、浏览器支持的 Long Task／Long Animation Frame、事件接收时序、服务端计划／实际发送时刻、肉眼标记、最终文字一致性校验、版本／日志 SHA256、视口／DPR／字体、播放速度、暂停和后台状态。RAF 回调频率不等于显示器实际 FPS，自动指标不能证明约 1px 位移，应结合肉眼标记和可选滚动位置记录判断。

默认不逐帧读取布局。滚动位置、渲染函数耗时是可选测量，会增加开销。历史隐藏、变速、跳过长空档、暂停、切后台都写入记录。做版本比较时用同一会话和轮次，固定窗口、字体及原速，保持页面在前台，多次重复；这些结果仍是浏览器重放条件下的表现。

日志中的服务端时间戳用于发送节奏，并非原客户端收到数据／显示字符的精确时刻。关闭逐字模拟后，没有流式增量的日志按整条事件播放；缺失时间戳的部分按顺序播放，页面会注明。09/30 和 10/03 通过旧 SSE 协议适配新的执行记录，工具元数据形态与新版本可能不同。缺失的媒体附件／未内置插件不会从原应用取回。长记录保留最近 60,000 个帧／输入／滚动样本，长任务和长动画帧各最多 12,000 条；总体帧统计覆盖整段，截断数量写在 JSON 中。

首页导入目录会读取日志、文本引用和可用历史缓存。若日志持续写入导致两次读取不一致，先复制该目录再导入。单文件限制 512MB，ZIP 总解压大小限制 2GB。服务仅监听 `127.0.0.1`，默认端口 54880；占用时自动选空闲端口，实际地址显示在启动窗口。页面关闭时会尽量保存简化记录；需要完整记录时先用“结束并保存”。

## 源码与重新打包

文字校验遵守该版前端的终态显示投影（包括原有的中间省略），不会把正常省略判作丢字；若前端保留完整执行文本，还会另行校验全文。JSON 的 `text_checks` 区分 `source_text_verified`、`ui_projection_verified` 和校验方式。

`source/server.py`、`source/session_data.py`、`source/playback.py`、`source/experiments.py` 是服务端源码；`web/` 是操作页面、适配层和已生成开关数据；`versions/` 是原前端资源。源码运行方式：在包根目录放置这四个 Python 文件，执行 `python server.py`；Python 3.10+，标准库即可。版本资源仍需保留。

开关数据由 `prepare_experiments.cjs` 从匹配归档的 `cf8024b` / `de2d6d6` 前端源码生成，逐段校验归档内源码及模块唯一匹配。开发时需要本仓库 Git 历史与 frontend/node_modules 的 Rollup，执行 `node tools/session-replay/prepare_experiments.cjs`。便携运行与正常重新打包使用已生成的数据，不需要 Git 或 Node.js。

仓库中的开发源码位于 `tools/session-replay`。使用 Python 3.10+ 环境安装 PyInstaller 后：

```text
python tools/session-replay/build_portable.py
```

输出 `dist/SessionReplay/` 和 `dist/SessionReplay-Windows-x64.zip`。编译必须在 Windows x64 上进行。发布前验证命令：`python -m unittest discover -s tools/session-replay/tests -v`。运行依赖和打包工具许可见 `licenses/`。
